模块 1

计算与 GPU 编程

01

Transformer 单层计算量与显存分析

语言模型先读完提示词，给出第一个回答 token，这一段计算叫预填充（prefill）。随后模型每次接收刚生成的 token，接着预测下一个，这个循环叫解码（decode）。沿着一个位置在 Transformer 层里的计算，可以数清两段各要算多少次、保存多少数据。

↗02

GPU 微架构与 Tensor Core

把两个数组逐项相加，GPU 可以让很多线程同时工作。先找出每个线程负责哪一项，再看它从哪里取数。把这个过程换成矩阵乘，就能看见线程之间有哪些数据值得共用。

↗03

GPU 分块算子、PTX 指令与 DeepGEMM 实现

先在 CUDA C++ 里让四个线程合算一个矩阵块。接着用 Triton、CUTLASS 与 CuTe、cuTile、TileLang、ThunderKittens 分别算同一块，看看每种工具让程序员安排哪部分工作。到指令部分，再回头看已经写过的内核怎样取数、交换和累加。读懂各代 GPU 的搬运和矩阵指令后，最后进入 DeepGEMM，分别追踪 Hopper 和 Blackwell 怎样把同一个结果写回显存。

↗04

GPU 性能剖析与瓶颈诊断

先用 Nsight Compute 对照两个算出相同结果的内核，找到慢的那一版多做了哪些访存。再用 Nsight Systems 跟踪一次 vLLM 请求，看内核省下的时间能否让用户更早收到回答。

↗05

Attention 算子与编译执行

FlashAttention 按块读取 K、V，为每行 query 保留少量统计量。反向传播可以利用这些统计量重新计算概率。

模块 2

跨设备通信

06

集合通信、NCCL 与 RDMA

四张卡各用一批样本算出一个更新方向。下一步要让四张卡拿到同一个合计数。先从两个数怎样相加看起，再把整排数沿链路分片传输，最后跟到另一台机器的接收缓冲区。

模块 3

模型架构与数值方法

07

量化表示、低精度执行与 Muon

低比特表示需要同时保存权重编码和缩放因子。训练部分另算 Muon 矩阵更新所需的计算与通信。

↗08

长上下文模型架构与状态复用

长上下文模型保存的历史各不相同。本课比较 MLA、稀疏注意力和递归状态，并单独分析 DeepSeek-V4.1-Flash 的图文输入、注意力层和专家层。

模块 4

推理系统

09

推理服务指标与 KV 分页

一条请求先把已知的提示读进模型，再用上一个输出接着生成。沿着这两个阶段数输入行、缓存行和用户收到的 token，就能算首词延迟、后续输出间隔，以及系统还能容纳多少请求。

↗10

推理引擎执行与 CUDA Graph

同一请求会参加多个批次。引擎需要维护槽位、KV 页和缓冲区地址，CUDA Graph 重放还要满足捕获时的输入约束。

↗11

分离式推理与 KV 传输

同一条请求可以在一组 GPU 上读完提示，再换到另一组逐词生成。沿着一次交接，先确认谁选出了第一个词、谁接着算第二个词，再计算两组 GPU 之间要搬哪些数据、搬多久。

↗12

推测解码与前缀验证

目标模型一次验证多个草稿位置。能交付多少个 token 取决于连续接受的前缀长度，加速比还取决于生成草稿和验证整批候选的耗时。

↗
模块 5

分布式训练

13

训练显存、激活重计算与卸载

前向结束时仍有空闲显存，第一次 Adam 更新却可能溢出。各阶段同时存活的参数、梯度、激活和临时张量决定了峰值。

↗14

数据并行、状态分片与训练恢复

两张卡各读一半样本，各算出一份梯度。先让它们更新出同一份模型，再看看权重和更新记录中有哪些可以拆开保管。卡数改变后，恢复训练还得把这些分片交给新的持有者。

↗15

多维并行与张量布局

以一层门控 MLP 为例，分别列出张量并行、序列并行和流水线并行下的本地形状、所需通信及边界激活。

↗16

MoE 路由与专家并行

一个 token 可以交给多个专家。专家索引决定发往哪里，路由权重决定如何合并结果，每个专家收到的行数决定矩阵乘的形状。

模块 6

训练平台与性能工程

17

智能体强化学习训练系统

一条训练轨迹包含模型动作、工具返回和奖励。更新策略时需要知道哪些 token 参与损失，以及生成它们的是哪一版策略。

↗18

训练数据管线、检查点与调度

数据管线可能已预取下一批样本，而参数只更新到上一批。检查点需要记录与参数一致的数据位置，集群调度还要为恢复后的作业找到合适节点。

↗
模块 7

综合系统设计

19

长上下文服务与训练平台的系统设计

为百万 token 的 MoE 服务估算每卡 KV 容量、跨机流量和副本数，再用首 token 时延与故障恢复条件检验这些预算。
