Transformer 单层计算量与显存分析

从一个词在 decoder 层里的去向开始。读第 1 课的 Token ID、词嵌入与隐藏状态，跟着 三个 token 的注意力计算 算出一个位置的输出，再沿 Decoder 中的隐藏状态与残差 把注意力与前馈层接成完整的一层。已经能画出这张图，可以直接从下面的成本估算开始。

沿用同一层的配置，读 投影的计算量、因果注意力中的二次项 和 权重与 KV 缓存容量。把提示词长度翻倍时，权重仍是原来那一份，每层留存的 KV 行数翻倍，因果注意力中每个新位置还会增加一整行合法配对。再看 MHA、MQA、GQA 与 MLA，指出换一种头共享方式会改动哪一项。

验算　用 单个 query 的历史读取 检查自己的表。给定历史长度、KV 头数、头宽和精度，应能分别列出一个解码步要读的历史、要追加的 KV，以及所有查询头的打分工作量。

接下来　带着这张表读 GPU 上一次矩阵乘的执行与访存。单层的 FLOPs 已经确定，下一步要弄清同一份权重从显存搬几次。

GPU 上一次矩阵乘的执行与访存

把第一站里的一次线性投影交给 GPU。先读第 2 课的 线程、warp 与线程块 和 寄存器、共享内存、缓存与 HBM，再跟着 矩阵乘的输出分块 找到一个线程块负责的输出区域。沿归约维取下一块输入时，指出哪些元素还能在片上复用。

用 Warp 的合并访存 追踪一组相邻线程的地址，再读 Tensor Core 的矩阵运算。同一张输出表可以有不同的线程分工，输入的地址排列会改变访存事务数。

验算　做 驻留的最紧约束。能从每块使用的寄存器、共享内存和线程数分别算出驻留上限，说明哪一项最先用满。

接下来　到 分块算子的实现与测量，把刚才画的方块换成指针、步长和边界条件。

↑ 返回知识点目录

分块算子的实现与测量

读第 3 课的 形状、步长与地址，按行列坐标手算一个地址，再读 GEMM 的分块寻址与边界。留意最后一块的两类无效位置：输入越界处需要屏蔽，只把有效的输出格写回矩阵。

回到同一行数据，读 融合 softmax 的计算与中间状态，列出融合前后会写回显存的中间结果。需要读矩阵内核源码时，先把乘加对到通用 PTX，再从各代 GPU 的搬运与矩阵指令读到两种 DeepGEMM 的同输入校验。

接着去第 4 课，在 Nsight Compute 内核报告 中核对同一次启动的访存指标，沿 矩阵转置对照 把多余事务追到读写指令。最后用 Nsight Systems 的 vLLM 请求时间线 看设备工作结束后还要等谁，分清内核耗时和用户等待。

验算　在 GEMM 尾块 中画出有效区域。再看 异步工作何时提交、何时完成，说明计时器在哪个事件之后才能读到完整耗时。

接下来　一行 softmax 已经可以融合。到 分块注意力与在线 softmax，处理一行分数无法同时放进片上的情形。

↑ 返回知识点目录

分块注意力与在线 softmax

从第 5 课的 8K 注意力分数矩阵的显存开销 开始。沿 四个 key 的两次在线更新 手算两块输入，每块结束时记下当前最大分数、指数和、按指数加权的值之和。新最大值出现时，旧分子和旧分母都要换到新的指数基准。

把这三个量带回 FlashAttention-1 的两层分块循环，标出从 HBM 取入 K、V 和写回输出的地方。再读 反向传播的概率重算，看前向保存的行统计量怎样用于反向。

验算　做 另一块 KV 到达时怎样合并旧输出，把合并结果与一次性处理全部位置的结果对照。

选择后续方向　想知道训练一层还需保存什么，从 训练步的显存峰值 继续。想知道生成下一个词时怎样少读历史，从 长上下文模型的历史读取 继续。两条路径都用得上刚算过的注意力输出。

↑ 返回知识点目录

长上下文模型的历史读取

从共同基础进入推理路径，先回看第 1 课的 四种注意力的 KV 缓存，再读第 8 课的 MLA 的低秩缓存与权重吸收。跟着一次解码列出要保存的行、下一步重新计算的量，以及各头如何从共享缓存读出不同的值。

把注意力限制到部分历史时，先读第 5 课的 NSA 的三条读取路径 和 扩散 Transformer 中 SLA 的两个计算分支，分别指出各路分母包含的行。回到因果解码，沿 DSA 的逐位置索引、QSA 的块索引、CSA 的压缩记录 读到 HCA 的完整压缩组。另读 KDA 的状态更新，逐步追踪内容怎样写进固定大小的矩阵。

验算　遮住 QSA 与 CSA 的同输入对照表 后两列，自己填入选块号、实际读取的行、softmax 分母和输出。再做 Delta 状态的单步更新，算出写入前后的读数。

接下来　既然能算出一次查询该读哪些记录，就到 请求时延与 KV 分页，看多条请求如何共享有限显存。

↑ 返回知识点目录

请求时延、KV 分页与连续批处理

先沿第 9 课的 预填充与解码算例 填出三轮输入、缓存与输出，再读 流式接口的 TTFT、ITL 与 TPOT，在一条请求上标出到达、第一个 token 和后续 token 的时间。沿 KV 页表与物理页 把逻辑位置映射到页号和页内偏移，随后跟着 连续批处理的逐轮调度、分块 prefill 对 decode 时延的影响 连排两轮。

验算　做 逻辑位置到物理页，说明追加一个 token 是否要分配新页。再用 同时满足两项时延要求的请求比例 核对哪些请求可以计入达标吞吐。

接下来　调度器给出本轮的请求和 token 后，进 推理引擎的一步执行，看它们如何变成实际送往 GPU 的输入。

↑ 返回知识点目录

推理引擎的一步执行与图重放

读第 10 课的 请求槽位与批内顺序 和 变长请求的 token 布局。给每个输入行同时标上请求编号和逻辑位置。再沿 推理框架的图输入缓冲、调度器选图 跟一轮 CUDA Graph 重放，区分可更新的数据、必须稳定的地址和仅用于填充的行。

验算　在 压平批次的索引 中从输出行找回原请求，用 图桶与填充 判断要选哪张图、其中几行真正交付结果。

接下来　要把预填充与解码放在不同设备，先学 跨机 KV 交接。若当前目标是让同一次目标模型前向交付更多 token，可直接学 推测解码的验证与回退；这两站都用到本节的行索引。

跨机 KV 交接与前缀恢复

先读第 11 课的 PD 分离交接，指出谁产生首词、谁把它作为下一步输入。接着回看第 6 课的 RDMA 的内存注册、队列与完成记录、源缓冲释放与远端数据可见性。再读第 11 课的 KV 传输的有效字节数 和 KV 交接协议。按请求写下源页、目的页和完成通知，标出解码端何时能读取、源端何时能复用。

验算　做 源页释放条件 和 远端恢复比本地重算快的条件。比较两条路径时分别计入排队、传输、转换与重算，给出在题设负载下更早就绪的时间。

接下来　继续读 推测解码的验证与回退。已经学过验证与回退，可回到 生成轨迹与策略更新 接训练侧，或直接做 服务容量设计。

↑ 返回知识点目录

推测解码的验证与回退

读第 12 课的 单轮验证的交付 token 数 和 接受概率与拒绝后的纠正分布，手算一次接受和一次拒绝。沿 变长验证的行索引 将草稿位置对应到验证分数，再读 拒绝后的逻辑回退与物理分配，指出哪段 KV 可以在下一轮继续使用。

验算　在 用纠正分布补足被拒后的概率质量 中验算最终分布，再做 输出长度与有效 KV。把最终交付的 token、已经写过的槽位、下轮有效的历史分别标出。

接下来　学习智能体训练，需要前面的 训练状态恢复 和 引擎执行；两者都掌握后，进入 生成轨迹与策略更新。专做服务设计，可补完 跨机 KV 交接 后去 服务容量设计。

训练步的显存峰值与低精度状态

沿训练路径，先读第 1 课的 线性层反向的两次矩阵乘法，写出求权重梯度时还要用到哪份前向输入。再读第 13 课的 每参数 16 字节的适用条件、训练步内的显存曲线，把权重、梯度、优化器状态和激活分别放到时间线上。

在峰值处划出仍然存活的张量。读 激活重计算的边界，判断释放一份激活后要重做哪些计算。若改用低精度，则读第 7 课的 GEMM 归约中的分组缩放 和 量化训练的原值与副本，把缩放因子和仍需保留的高精度副本也计入容量。

验算　做 重算链的保存量，画出保存的边界和反向临时重建的激活。峰值只统计同一时刻存活的那些张量。

接下来　重计算能减少激活，参数和优化器状态仍要找地方存放。到 跨卡归约与状态分片 看多张卡怎样分担它们。

跨卡归约与状态分片

先读第 6 课的 四个 rank 的梯度归约 和 Ring AllReduce 的分片传输，逐轮标出每张卡发什么、收什么、最后持有哪些梯度。带着这张图读第 14 课的 ZeRO 的状态分片，把上一站的状态清单改写成每张卡各自持有的份额。

接着读 前向与反向的参数收集和释放。层开始前要收齐哪份参数、算完能否释放，决定了实际峰值和下一轮通信。想比较矩阵优化器与 Adam 时，再读第 7 课的 Muon 与分片参数，核对独立更新每个局部分片能否还原完整矩阵的更新方向。

验算　完成 三种状态分片 和 参数释放的网络代价，分别给出常驻字节和为再次使用该层而增加的传输。

接下来　到 张量并行、流水线与专家路由。现在进一步拆开一次前向计算本身。

张量并行、流水线与专家路由

读第 15 课的 MLP 的列并行与行并行。沿两次矩阵乘标出各卡输出的形状，找出需要跨卡求和的位置。再读 GPipe 与微批流水线，沿时间轴数清一个微批次从前向到反向占住哪些激活。

换成专家层后，输入会按路由结果重排。读第 16 课的 四个 token 的 Top-2 分派、AllToAll 的计数与载荷交换 和 Combine 与反向路由。给同一个 token 的两个专家副本分别编号，沿发送、专家计算和返回追踪它们，直至加权合并回原位置。

验算　用 专家输出的加权合并 检查路由表。给出每一项的原始 token、专家、路由权重和返回槽位，再算最终输出。

接下来　到 训练数据与故障恢复。一次更新用到的数据、模型分片和训练进度都要能在重启后对上。

训练数据与故障恢复

读第 18 课的 预取游标与训练进度。在数据已预取、优化器刚提交一次更新的位置暂停，分别记下已读取与已提交的数据边界。接着读 检查点的暂存与持久化 和第 14 课的 跨 rank 重分片恢复，判断哪些状态已能从存储重建。

验算　做 按样本和按 token 保存数据游标。改变恢复时的批量，列出第一批应出现的样本或 token，并解释从预取位置恢复会遗漏哪段数据。

接下来　只学过训练路径，转到 长上下文模型的历史读取 补生成侧。已经会逐轮追踪生成请求，可以直接去 生成轨迹与策略更新，把生成与训练接起来。

生成轨迹与策略更新

这里汇合训练和推理两条路径。读第 17 课的 轨迹、动作掩码与逐 token 概率，在模型输出和工具返回之间画出边界，标出参与损失的 token。再读 PPO 概率比的分母、异步训练中的三个策略版本，把生成、打分和更新的版本写到同一条轨迹上。

验算　先做 工具结果的动作掩码，再做 策略滞后和有效吞吐。能从已生成的轨迹中筛出当前允许训练的样本，并据此重新计算有效吞吐。

长上下文服务的容量设计与验收

先用第 19 课的 服务负载与目标 确定请求长度、到达方式和时延约束。按 百万上下文的逐层状态 算每张卡要保留的历史，按 冷请求的跨池 KV 传输 算交接时间，再按 推测解码的准入预算 算一轮能验证多少位置。若同时承担训练，再补 256 卡训练的数据布局 和 在线策略与持续训练的版本边界。

验收　用 一条满长冷请求在每张卡上占多少 KV 复核单卡容量，再按 容量设计与验收条件 写出并发上限、延迟目标及各自的前提。对偏离估算的时间，沿第 4 课的 首 token 的四个时间戳 定位，最后回到 端到端时延复测，用同一负载检验改动。

回查　若先触及显存上限，回到 历史记录 和 物理分页 分清逻辑容量与实际分配。若首词主要等在跨机交接，回到 KV 交接 核对排队和传输。
