GPU 编程、分布式训练与推理系统

课程目标

同样一张 GPU，首词慢可能因为一段长提示词算得久，也可能因为请求一直排不上批次。学习路线的终点是能从记录中区分这两种情况，并估出改动一次调度或算子能省多少时间。

路线按知识依赖排列。前四个阶段学习计算量、显存和 GPU 编程，随后学习通信与训练并行。推理部分以一次生成请求为例，讨论模型状态、调度和服务容量。

总目标
拿到模型配置和请求长度后，分别估算浮点运算量、显存占用和跨卡通信量。再用这些数字判断怎样切分模型，解释用户何时收到首个词、随后多久收到下一个词，以及缩短历史或压缩缓存可以省去多少工作。

计算、访存、通信与调度

计算量、显存访问量和通信量的单位不同。先各自除以相应的吞吐率估时间，再沿依赖关系判断哪些时间会相加、哪些可能重叠。

• 计算量按算子分项统计。先估算矩阵乘的浮点运算次数，再核对 Tensor Core 吞吐；若整体仍慢，查看归一化、激活函数等算子占用的时间。

• 显存既要算容量，也要算流量。列出权重、激活、优化器状态和 KV 缓存的字节数；再注明数据是在片上、显存、主存还是 SSD 之间传输。

• 通信要沿实际链路核算。区分集合通信与点对点传输，记录每个参与方的有效字节、所经链路，以及其中有多少时间能与计算重叠。

• 调度先看谁在等。训练中追踪流水空档和慢进程；推理中追踪队列、批次与缓存命中，再数出每秒有多少请求同时满足质量和延迟要求。

硬件、模型与框架

以一次注意力调用为线索：模型规定哪些位置互相可见，框架决定把哪些请求放在本批，内核决定按什么顺序读取 K 和 V。分析结果出错时，先判断是哪一层改变了可见数据。

• 分块算子有多种实现，包括 CuTeDSL、cuTile、TileLang 和 ThunderKittens。FlashAttention-4 可用来比较矩阵乘、softmax 与数据搬运在 Blackwell 上的分工。

• 从一次集合通信的发起方读起：它可以由主机提交，也可从设备代码触发。再查 GIN、CFT 及对称内存相关接口能访问哪些缓冲区，谁能确认传输完成。

• TorchTitan 用设备网格与 DTensor 描述参数怎样分片。阅读 spmd_types 时，先画保存在各卡上的局部形状，再看算子入口是否需要重新分布张量。

• 百万 token 的状态容量取决于每层保留的信息。稀疏索引改变读取位置，线性注意力维护递归状态，KV 量化改变每条记录的字节数。

• 分离式推理把计算提示词与逐词生成分给不同实例。追踪一页 KV 从源到目的的过程，就能区分 NIXL 的数据传输、Mooncake 的缓存管理和 Dynamo 的请求路由。

• 智能体训练同时涉及采样、工具等待和策略更新。部分轨迹跨越权重切换时，还要记录行为策略的版本。

张量形状与计算量

先分清哪些维度会随请求增长。一层投影的权重在不同请求之间共用，KV 缓存却要为每条请求的每个历史位置另留空间。两者即使都以字节计，也要分别估算。

• 给 Q、K、V 投影、注意力与前馈层标出矩阵形状，再分别计算整段预填充、新增一个词的解码以及包含反向的训练运算量。

• 列出参数、梯度、优化器状态、激活和 KV 缓存的形状及精度。比较 MHA、MQA、GQA 和 MLA 各要保留几份历史记录。

• 用有效浮点运算量除以同一层级的访存字节数得到算术强度，在 Roofline 图上比较计算和带宽上界；再检查小任务是否受启动或等待限制。

• 记录算子每秒浮点运算数、模型与硬件 FLOP 利用率，再分别统计首词延迟、相邻输出间隔、完整请求延迟和达标请求率。

练习

验算时先把序列长度改成 1。此时因果注意力只有一个合法配对，单头的注意力输出应等于该位置的 value。通过这一项再加入第二个位置。

• 写一张可复算的计算表或一段 Python 程序。输入隐藏宽度、前馈宽度、层数、Q 头数、KV 头数、头宽、批量、序列长度及各张量精度，分别输出参数与状态字节、每词 KV 字节、注意力和前馈层的浮点运算量；注明是否含反向、激活和临时工作区。

• 各选一个约 70 亿参数、约 700 亿参数的稠密模型和一个 MoE 模型，附上配置。令有效序列从 8192 增至 1048576，固定批量；对 MoE 另列总专家数与每词选中数。逐项解释哪些量按长度线性增长，哪些在全历史注意力下近似二次增长。

自测

自测时给每个估算值写上单位。若算出的 KV 缓存是“元素数”，还要乘每个元素的字节数，才能与显存上限比较。

□ 给出一个数值例子，分别标出模型参数和请求长度怎样进入 FLOP 与显存公式，并注明训练还是推理、精度、批量及是否分片。

□ 固定模型，对比一个词的低并发解码与一整段提示词的预填充。算出两者的理想算术强度，再说明批量、历史长度或缓存命中发生什么变化时，原瓶颈判断需要重做。

GPU 的执行与访存

• 一个线程块在一个 SM 上执行，块内线程以 warp 为单位发射。沿一次矩阵乘追踪寄存器、共享内存、L2 和 HBM 的读写，再看可驻留的 warp 中有几个已就绪、可以发出下一条指令。

• 画出同机 GPU 经 PCIe 或 NVLink/NVSwitch 的路径，以及跨机 GPU 经网卡走 InfiniBand 或 RoCE 的路径。再标出 CPU 与 GPU 的连接方式，区分经过主存与设备间直接传输。

• 分开估算矩阵乘、指数运算和搬运的时间。以 FlashAttention-4 为例，矩阵引擎的吞吐提高之后，若指数或访存时间仍占主导，加快矩阵乘能节约的总时间就有限。

查硬件手册时，同时记录架构代号、数据类型和指令形状。同为“矩阵乘”，换了操作数类型，能用的指令与公开峰值都可能改变。

AMD GPU、TPU 与 Trainium

比较不同加速器，可以给它们同一题目：一个矩阵块由谁搬进片上存储、谁保存部分和、下一块何时覆盖原槽。这比逐字翻译各家组件名称更容易解释差异。

官方 AMD Instinct MI355X / CDNA4 — 用架构图找到 HBM、矩阵引擎及其低精度输入格式。抄录带宽时注明是单个加速器的指标。

官方 Google TPU7x (Ironwood) — 将每芯片的 HBM 容量与整个互连拓扑分开，追踪一次跨芯片通信在三维环面中的路径。

官方 AWS Trainium2 Architecture — 从 NeuronCore 和片上 SBUF 读起，检查编译器怎样安排搬运，再用 NeuronLink 图解释跨芯片通信。

硬件指标对照
Rubin 的 HBM4 与 NVLink 6 分别影响本地访存和跨卡传输。Ironwood 的 3D torus 影响通信路径，MI355X 的 MXFP4 则改变矩阵输入格式。比较吞吐率时要注明精度和数据所在的位置。

练习与自测

• 使用一份多 GPU 节点的既有拓扑输出，或在可用设备上查看 nvidia-smi topo -m。选定两张 GPU 和一块网卡，画出数据从哪张卡出发，中间经过哪个交换结构，最终到哪个端点。

□ 以一块矩阵被数个线程重复读取为例，标出数据原来在 HBM、搬到共享内存后由谁复用，以及每线程寄存器保留什么。说明块变大后，每个 SM 可同时驻留的块数可能怎样变化。

□ 给张量并行、专家分派和预填充到解码的 KV 交接各选一种拓扑。解释各自传多少数据、由谁等待，以及链路带宽或启动延迟怎样影响放置。

编程练习顺序

归约练习先用全 1 输入核对总数，再只保留末尾一个非零值。后者能暴露漏算尾块的问题，而随机输入的一个近似总和不容易让人看出漏的是哪一项。

• CUDA 练习依次实现向量加法、归约、分块 GEMM 和 softmax。逐步检查相邻线程的访存地址、共享内存复用、warp 内交换以及异步拷贝的完成条件。

• 在 Triton 中重做向量加法、融合 softmax 和矩阵乘。先写出一个程序实例负责哪些元素，再读块指针的步长和自动调优选择的块形状。

• 用 CuTe/CUTLASS 把逻辑矩阵坐标换成实际地址，随后跟踪操作数怎样送入矩阵指令、何时可以复用流水缓冲。

• 用 cuTile、TileLang 和 ThunderKittens 实现分块计算，比较 tile 布局、流水线和同步的写法。

• 从 DeepGEMM 选一条与模型结构有关的实现，例如分组矩阵乘或稀疏索引。跟踪输入布局、编译分派与输出位置，注明阅读的提交。

源码与编程指南

教程用于看完整的调用方式，指令手册用于确认参与线程、地址空间和同步条件。遇到示例只支持特定形状时，沿调用向下找出第一条依赖该条件的指令。

项目 ThunderKittens — 跟踪 tile 从全局存储移入共享内存，再读消费与屏障的先后关系。

项目 DeepGEMM — 选择一种矩阵形状，沿 Python 入口追到实际生成内核，记录输入布局和累加精度。

阶段 9　MoE 与专家并行

MoE 把每个 token 交给少数专家。总参数可以很大，但决定某轮耗时的往往是每个专家真正收到多少行，以及这些行从哪些卡到达。

阶段 14　分离式推理与 KV 传输

阶段 15　推测解码与并行生成

故障诊断与恢复

学习路线术语
AdamW
带解耦权重衰减的自适应优化器。它分别维护梯度的一阶和二阶矩估计，再结合学习率更新参数。
API
供程序调用的接口。函数返回、设备执行结束和远端可见可能发生在不同时间，应按接口的约定判断。
AWQ
用校准激活识别量化敏感的权重通道，再选择缩放以降低权重量化后的输出误差。
BF16
16 位浮点格式，使用 8 位指数和 7 位显式尾数。指数范围接近 FP32，小数有效位更少。
Blackwell
NVIDIA GPU 架构。此处的具体指令和数据格式要结合芯片目标确认，例如 SM100 内核使用的张量内存。
CFT
NCCL 设备侧用于协调通信工作的一类机制。判断缓冲区能否复用时，要区分传输到达与参与线程的同步条件。
CP
上下文并行。把序列位置分给多个设备，各设备处理自己的查询位置，并设法获得它们需要的历史信息。
CTA
Cooperative Thread Array，即一个 CUDA 线程块。块内的线程可共享内存并使用块级屏障同步。
CUDA
NVIDIA 的 GPU 编程平台。主机程序通过运行时或驱动提交内核，GPU 按线程块调度工作。
CUDA Graph
预先记录并实例化一组 GPU 操作及其依赖，再重放整个执行图，可减少主机逐次提交许多小操作的开销。
CuTe
CUTLASS 中用于表达张量形状、步长、线程分工和布局的工具。它可以描述同一逻辑元素由哪个线程访问。
CUTLASS
NVIDIA 的线性代数内核库，提供可组合的分块矩阵乘、数据搬运及结果处理实现。
DDP
PyTorch DistributedDataParallel。各进程持有模型副本，将本地梯度按桶组织并跨进程归约。
decode
推理时利用已有状态生成后续词元的阶段。普通自回归生成中，每条序列每轮通常新增一个位置。
DeviceMesh
记录哪些设备位于哪些网格坐标的数据结构。固定其他坐标、沿指定轴取参与者，即可确定该轴的通信组。
DRAM
动态随机存储器。性能报告里的 DRAM 流量通常指设备与外部显存之间的实际传输量。
DSpark
DeepSeek-V4.1-Flash 的推测解码组件，生成候选后按置信度安排验证；实际交付数同时受验证结果和停止条件限制。
DTensor
把一个逻辑全局张量与各设备的局部张量、设备网格和布局关联起来的分布式张量表示。
E4M3
由 1 位符号、4 位指数和 3 位显式尾数组成的 FP8 格式。具体有限最大值和特殊值还需核对采用的格式变体。
eager
程序运行到张量操作时直接请求执行对应运算的模式。逐个写出的操作可能分别调度，仍须观察实际调用边界。
EAGLE
利用目标模型特征产生后续候选，再交给目标模型验证的一类推测解码方法。
Engram
模型的条件记忆模块，根据输入相关索引取出记录并融合到隐藏状态。活跃读取量和总容量是两个不同指标。
EP
专家并行。不同设备持有不同专家，路由器选完专家后，词元及其结果常常要跨设备传输。
FlashAttention
分块计算注意力的一系列算法与内核。它们用在线归一化保留当前行所需的统计量，避免把完整分数矩阵写入显存。
FlashAttention-4
针对 Blackwell 的一代 FlashAttention，利用张量内存与细分的线程职责，并优化行重缩放和指数计算。
FlexAttention
PyTorch 的可编程注意力接口，用分数修改函数和块掩码描述注意力规则，再由后端生成相应实现。
FLOP
一次浮点算术运算的计数单位。按本节约定，乘法和加法各计一次；除以时间才得到吞吐量 FLOP/s。
FP16
通常指 IEEE 半精度浮点数，使用 5 位指数和 10 位显式尾数。与 BF16 相比，精度与可表示范围的取舍不同。
FP32
32 位浮点格式，具有 8 位指数和 23 位显式尾数。在低精度乘法中常用作累加器或保存统计量。
FP4
一组 4 位浮点表示。很多实现需按一小组数共享尺度，比较容量和误差时必须连同尺度计算。
FP8
一组 8 位浮点格式。使用前应区分 E4M3、E5M2 等编码，并说明缩放因子和累加精度。
FSDP
完全分片数据并行。模型参数等训练状态在组内分片；模块计算前暂时收集所需权重，计算结束后按策略释放。
GDN
Gated DeltaNet，用门控与误差校正更新递归状态。其历史状态容量不必随每个新词元线性增长。
GEMM
通用矩阵乘法。左矩阵的行与右矩阵的列逐项相乘、求和，得到输出的一个元素；训练和推理中的线性层大量使用这种运算。
GiB
二进制容量单位，1 GiB 等于 1,073,741,824 字节；1 GB 按十进制等于十亿字节。
GIN
NCCL 的 GPU 发起网络通信接口。在支持的配置中，设备端代码可发出跨节点通信请求，仍要遵守缓冲和完成协议。
GPTQ
训练后权重量化方法，利用校准输入估计量化误差对层输出的影响，并在逐步量化时补偿误差。
GPU
图形处理器，使用大量线程并行处理数据。需要许多独立运算或数据复用时，它常比逐项在 CPU 上执行更合适。
GQA
分组查询注意力。多组查询头各自共享一组键和值，可以减少解码时需保存和读取的 KV 数据。
GRPO
组相对策略优化，对同一提示采样多个回答，用同组奖励的相对差异构造优势。
HBM
GPU 常用的高带宽显存，用于保存权重、激活和中间结果等数据。芯片与显存之间可持续传输的字节数会限制某些算子。
Hopper
NVIDIA GPU 架构，H100 属于这一代。相关内核可利用 TMA 搬运和 warp 组矩阵乘等特性。
Inductor
PyTorch 的编译后端，接收计算图并选择或生成内核。融合边界、形状与后端配置都会影响最后的执行路径。
InfiniBand
用于节点互联的网络体系，可承载 RDMA 传输。NCCL 集合通信的结果语义与底层选择哪一种网络操作属于不同层次。
INT4
4 位整数。两个码通常可装进一个字节，还要计入分组尺度、零点及必要的对齐空间。
INT8
8 位整数。用于量化时通过尺度及可选零点与实数对应，整数位宽本身并不决定乘积的累加精度。
ITL
同一请求内相邻两个输出 token 到达之间的时长。只有一个输出 token 的请求没有这种间隔。
KDA
Kimi Delta Attention。一种带门控的递推更新，每个头维护状态矩阵，用当前键和值修改状态，再由查询读出。
KV
键和值的合称。一个历史位置通常既提供参与匹配的键，也提供按注意力权重汇总的值。
KV 头
共享一套键和值的注意力头。使用 GQA 时应按 KV 头数估算缓存容量。
KV 缓存
保存历史位置已算出的键和值。解码时只需为新位置生成键和值，再从缓存读取允许关注的历史。
L2
GPU 上多个 SM 共享的二级缓存。L2 命中可免去一次更远的显存访问，因此 L2 流量和 HBM 流量通常不同。
logits
模型为词表中各个候选 token 输出的未归一化分数；经过 softmax 可得到概率。不同词表的同一数字编号不必指向同一 token。
LSA
NCCL 设备通信中的可直接装载与存储的地址访问路径，适用范围取决于对端内存与硬件互连。
MHA
多头注意力。常见实现为每个查询头配一组独立的键和值，再把各头的输出拼接起来。
MiB
二进制容量单位，1 MiB 等于 1,048,576 字节或 1,024 KiB。
MLA
多头潜在注意力。模型把历史内容压到低维潜向量，后续计算按模型规定从该向量获得各头所需的信息。
MoE
混合专家模型。路由器给每个词元挑选少数几个专家，由选中的网络计算，再按路由权重合并结果。
MQA
多查询注意力。在同一层中让多个查询头共用同一组键和值，以减少缓存容量及读取量。
MTP
多词元预测，训练时还预测后续若干位置。用它加速推理时还需要独立的验证、接受及缓存处理流程。
Muon
用于矩阵参数的优化器，对动量矩阵施加近似正交化。维度不适用这种更新的参数通常交给其他优化器。
MXFP8
共享块尺度的 FP8 表示。同一组元素按约定共用尺度，布局和尺度的编码也影响执行支持。
NCCL
NVIDIA 的多 GPU 通信库，负责组织集合通信和点对点传输。它会根据参与设备、消息与拓扑选择可用路径。
Nsight Systems
系统级性能分析工具，用同一条时间轴呈现 CPU、CUDA API、GPU 内核和通信活动，可追踪请求耗时落在哪段依赖上。
NVFP4
NVIDIA 的分组缩放 FP4 表示，使用小组共享尺度。只将元素数乘以四位会低估实际存储量。
NVLink
面向 GPU 等设备的高速互连。实际可达带宽取决于链路数量、拓扑和传输方向。
NVSHMEM
面向 GPU 的并行通信接口，允许参与进程通过对称内存寻址远端数据并发起单边操作。
PCIe
主机与 GPU、网卡等设备之间的互连标准。设备位于哪个根端口或交换机下，会影响传输所经的链路。
PPO
近端策略优化，通过限制新旧策略概率比对目标的贡献，使一次更新不过度偏离采样策略。
prefill
推理时处理已有提示词的阶段。模型可以同时计算多个输入位置，并留下后续生成要读的缓存。
PTQ
训练后量化，在已有浮点权重上用校准或统计方法确定低精度表示，通常不进行完整的模型重训。
QSA
Qwen 对应混合模型中的注意力分支，与递归层穿插使用；估算历史状态时要按实际两类层数分别核算。
query
注意力中发起查询的位置或它的向量。它与各个可见位置的键相乘，得到对应的一行分数。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
RDMA
远程直接内存访问。网卡按已注册的地址和权限读写对端内存，软件还要按照传输协议检查完成和可见条件。
Reindex
复用共享的索引键，在当前层根据自己的查询重选位置。
RoCE
在以太网上承载 RDMA 的一组协议。链路拥塞、丢包控制与网卡配置会影响性能。
rollout
策略与任务环境实际交互生成一条轨迹的过程，既包含模型动作，也可能包含环境返回。
Roofline
用算术强度比较计算峰值和带宽上界的模型。横轴的字节数必须与所选缓存或显存层次的带宽对应。
sector
统计合并访存时使用的地址区间；本例按 32 字节划分。多个线程落在同一段内时只计一次被触及的区间。
SM
流式多处理器。NVIDIA GPU 在 SM 上驻留线程块并调度其中的 warp，寄存器和共享内存会限制可同时驻留的块数。
SM100
Blackwell 数据中心 GPU 使用的一种目标架构。SM100 对应的指令与布局要求不能直接移用于所有 Blackwell 型号。
SmoothQuant
通过按输入通道重新缩放激活与权重，降低激活离群值给低比特量化带来的困难。
softmax
把一行分数先取指数，再各自除以这一行的指数和，得到总和为一的权重。实作时可先减去行最大值以免指数溢出。
Tensor Core
GPU 上执行小块矩阵乘加的专用计算单元，支持的输入格式、累加精度和分块形状随架构变化。
tile
计算时一次处理的一小块数据。划分 tile 可以让线程重复利用已搬进片上的数据，同时限制临时存储量。
TileLang
用分块和流水线描述高性能算子的语言工具。编译器根据目标后端降低成具体线程与内存操作。
TMA
Tensor Memory Accelerator，按照张量描述符搬运多维数据的硬件单元。计算线程通过屏障等机制确认数据可读。
TMEM
Blackwell 的张量内存。部分矩阵指令把累加结果保存在这里，再由指定线程读取或继续计算。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
TPOT
Time Per Output Token，常用于表示首个输出之后平均每个词元的耗时。应注明是否排除首词以及使用了多少个生成间隔。
Transformer
用注意力混合不同位置的信息，再逐位置通过前馈网络。一个解码器通常把多层这样的计算依次连接起来。
Triton
用分块数组表达 GPU 内核的编程语言与编译器。开发者指定每个程序实例处理的块，编译器生成线程层面的实现。
TTFT
Time To First Token，从请求的约定起点到看到第一个输出词元的时长。比较数据时应写明起点在客户端还是服务端。
W8A8
权重与激活都用 8 位表示。累加器和输出仍可能使用更高精度，要另行说明。
warp
NVIDIA GPU 的线程执行组，通常由 32 个线程组成。同组线程执行同一条指令，掩码决定本次哪些线程参与。
Xid
NVIDIA 驱动对设备异常记录的事件标识。应与设备、时间戳、任务日志及其他计数对齐后再判断原因。
ZeRO
通过划分训练状态降低每个数据并行进程的显存占用。三个常见阶段依次把优化器状态、梯度和参数纳入分片。
上下文并行
把同一请求的序列位置切给多个 rank。局部查询仍可能需要访问其他 rank 持有的历史 K、V。
临时工作区
为本轮验证、打分或采样而保留的缓冲，峰值与有效行数、词表宽度和图桶上限均有关。
主权重
优化器使用的高精度参数副本。小幅更新先累积到这份参数，前向另取低精度副本。是否单独保留取决于实现。
互连
设备间传输数据的链路及交换结构。比较系统时要区分片内、单节点内与跨节点的范围。
信号
收发双方约定的完成标记。生产者更新标记前，要把标记与相应代的数据写入建立正确顺序。
全局 KV
随历史保留、可由后续全局注意力访问的 KV 及对应模型口径中的索引状态。滑窗、工作区和分配对齐还需分别核算。
共享内存
同一线程块中的线程可以共同访问的片上存储，用于暂存可复用数据。程序需要安排写入与读取的同步。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
准入
调度器确认有可用资源并允许请求开始执行。准入前的等待属于排队时间。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
分离式推理
将提示处理与逐 token 生成分别放到不同资源池，两端须交接可继续计算的状态。
前缀命中
复用已经计算好的前缀 K/V。新增查询仍要读取掩码允许的前缀位置。
加权输出
各个可见 value 乘以对应的指数权重后累加的向量；采用未归一化累积量时，最后还要除以匹配的分母。
动量
由历次梯度的指数加权和得到的更新方向，同当前梯度可按具体算法再次组合。
参数分片
把一个逻辑参数拆到多个 rank 保存。若一次运算需要整个矩阵，就要显式恢复其布局或跨卡协作。
参数量
不同权重元素的总数；同一参数被多行、多次使用不会因此重复计数。
反缩放
将累计的放大梯度除以相同缩放因子，恢复与原损失对应的梯度。需要按真实范数裁剪时，先完成反缩放。
反量化
把低精度码结合尺度和可选零点，恢复到用于算术的数值。它可单独执行，也可融合到内核中。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
因果编码器
每个位置只能读取当前位置及其之前允许访问的位置，因此增加后缀时，已有前缀的表示可继续复用。
图桶
为某组预定输入容量和形状捕获的图，真实请求可以只占部分槽位。
图重放
重复提交一个已有的设备工作图，同一静态输入地址中的内容可在各轮改变。
在线 softmax
按块读入分数，只保存当前行最大值和按它计算的指数和。遇到更大的分数时先把旧和换到新基准，最后可得到整行一致的归一化结果。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
块指针
描述整块数据的位置和布局的对象。编译器根据块起点、形状和步长生成块内各元素的地址。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
寄存器
线程存放局部值的片上资源。每线程用量过高时可能减少同时驻留的线程块，也可能导致部分值被移到内存。
对称内存
各 PE 按约定共同分配的对应内存对象。远端操作通常以本地对称对象加目标 PE 标识指定目的地。
对称内存
通信组成员按接口契约建立的一组内存对象，结合本地标识和目标 rank 可定位对端对应对象。
屏障
程序中规定的同步点或状态。哪些线程或设备必须到达，取决于屏障的参与范围和约定的完成条件。
已提交训练步
模型和优化器已记录该步更新、样本消费进度也与之匹配的恢复边界。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
常驻
让已启动的工作单元在内核内部反复处理多个任务，而非处理完一块便退出。具体任务领取方式由程序决定。
并行维度
描述一组 rank 沿哪种方式协作的网格轴，例如数据并行、张量并行。不同轴上集合通信的参与者和目的可能不同。
序列并行
在本节的张量并行组合中，沿 token 维切分原本重复保存的部分激活，使残差或归一化可以对本地行执行。
异步拷贝
发起数据搬运后，线程可以先做独立工作。消费者在读取目标缓冲之前仍须按协议确认搬运完成。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
归约轴
矩阵乘中将乘积相加的那一维。不同归约分组的尺度不同时，应先分别恢复各组的部分和。
总线带宽
集合通信测试中由有效载荷与操作时长按操作类型折算的指标，具体换算应以测试工具的定义为准。
恢复点
已完整提交且仍可读取的模型、优化器、数据游标等一致状态，最新文件时间不一定对应最新可恢复步。
投影
此处指注意力与前馈层内的稠密矩阵乘。它按实际输入 token 行数重复执行，同一份权重可被多行共享。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
排空
等待或确认已经提交的设备访问全部结束，使原缓冲能安全复用。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
故障域
一次故障可能共同影响的设备或服务范围，例如同节点或同机架。副本能否用于恢复取决于它是否位于受影响范围之外。
故障域
一次故障可能同时影响的一组资源，例如同一机架的节点。副本和检查点的放置须考虑共享故障。
故障恢复
从可信的一致状态重建执行，训练恢复点和已向客户端承诺的服务输出需分别核对。
时间线
将不同线程、CUDA 流及设备活动按时间展开，可结合事件与请求编号追踪先后依赖。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
有效吞吐
单位时间向请求提交的有效输出 token 数，草稿生成和作废位置不计入分子。
有效行
由一次实际路由产生的输入行。为满足对齐要求而补出的行也占空间，但不对应任何 token。
服务目标
为同一类真实请求约定的延迟、生成质量和可用性门槛，容量预算要按这些条件验收。
校准
预测概率与同类样本中的实际通过频率是否相符，判断时须控制位置及样本是否曾被验证。
梯度同步
把不同数据并行副本算出的对应梯度按约定归约。推迟同步会增加本地需要保留的梯度，具体大小取决于分片时机。
梯度累积
连续处理多个微批次，将其梯度贡献累加到缓冲区，再统一更新参数；样本数不同时还需处理归一化分母。
模型卡
模型发布者给出的配置、使用条件和评测说明。复核模型层数、头数或权重精度时应同时核对相应版本的配置文件。
模型执行器
根据调度结果和缓存位置准备本轮张量、提交模型运算并将输出行映回请求的组件。
步长
某个坐标轴上的下标增加 1 时，物理地址要前进的元素数。换算成字节还须乘元素大小。
残差连接
把子层输入沿一条旁路保留，随后与子层计算出的更新量逐元素相加。
流水线
把搬运、计算等相互依赖的阶段错开执行。不同数据块可以重叠，但消费某个块之前仍要确认它已准备好。
消息大小
一次集合通信中每个进程交给接口的逻辑载荷字节数。实在线路上传输的总字节数还与算法、参与数有关。
消费者
读取共享槽位数据并据此计算的一方。可以开始读，与生产者可以覆盖同一槽，通常由不同完成事件决定。
混合架构
在同一模型中使用不同类型的层。容量应分别累加逐位置历史、固定递归状态和必要的辅助记录。
潜在 KV
将历史位置映射为较低维的中间表示供后续读取；完整缓存容量还取决于所保留的位置分支和布局。
激活
模型处理本次输入时产生的中间张量。它的形状和寿命依赖批量、序列长度以及接下来是否需要反向传播。
激活卸载
前向后把选定激活从显存移到主机等介质，在反向用到前再传回。收益取决于节省的显存和新增传输能否及时完成。
激活参数
MoE 在处理当前 token 时实际走到的参数。估算一次前向时要考虑专家选择，估算所有权重的常驻容量仍要计入未被本 token 选到的专家。
激活重计算
前向少存一部分中间张量，在反向需要时重新做相应运算，以计算量换取较低的显存峰值。
状态容量
继续生成下一 token 所需保留的数据量。与当步临时工作区和模型参数的大小要分别统计。
理想算术强度
以题设规定的最少读写字节为分母得到的算术强度。实际访存可能因缓存、填充和重复加载而不同。
目标模型
推测解码中定义最终生成分布的模型。它一次验证多个候选位置，并在需要时提供纠正词元的分布。
程序实例
执行一块 Triton 程序逻辑的工作单元，通常处理一组元素。一个实例内部怎样分给线程，由编译器按布局和启动参数决定。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
策略版本
生成某段动作所用的权重身份，跨版本的轨迹须能追溯到各段实际行为策略。
算术强度
以指定存储层次为边界，用浮点运算数除以跨过该层次的字节数，单位为 FLOP/B。
算术强度
将有效运算次数除以某一级存储的流量，单位为 FLOP/B。用 DRAM 和 L2 的字节作分母，可得到不同的结果。
累加器
存放矩阵乘等归约运算部分和的位置。输入可以是低位码，部分和可用不同的浮点或整数格式。
线程块
可在同一 SM 上合作并通过共享内存交换数据的一组 CUDA 线程，也称 CTA。
缩放因子
把低精度存储值换算为计算所需数值的系数。按块量化时，必须让每个元素与它所在分组的系数对应。
自动调优
给定输入形状后实际比较若干组内核配置，再为该形状选择合适的配置。首次搜索也有耗时。
草稿模型
推测解码中先提出若干候选词元的模型或预测头。目标模型逐位置验证这些候选，只有符合接受规则的前缀可以直接交给用户。
草稿生成
使用代价较低的分支给出候选序列，随后交给目标模型验证。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
行为策略
实际采出这条轨迹的策略及版本，异步训练时可能与训练端重新计算概率的版本不同。
设备网格
把每个物理 rank 映射到各并行轴坐标的布置，轴的乘积须和实际设备覆盖关系吻合。
词表
记录 token 与整数编号对应关系的表。词嵌入矩阵使用同一套编号查行，每行才是模型参与运算的向量。
载荷
应用需要传送的数据。协议头、编码开销和重传都会占用链路，有效载荷只统计应用数据本身。
达标吞吐
在同一观察窗口内，满足约定服务指标的请求数除以窗口时长。
连续批处理
每一轮重新选择要运行的请求，可补入新请求并移走已结束请求。
递归状态
前一步计算留下的汇总量，读取后与当前输入一起形成下一步的状态。
递归状态
由上一步状态和当前输入更新的有限形状张量；某一递归层的状态规模可固定，混合模型的其他层仍可能随历史增长。
通信组
共同参与一系列集合操作的一组 rank。组内进程必须按兼容的顺序参与，成员失效后通常要重新建立。
速度比
完成相同有效工作量时，原耗时与新耗时之比。若按输出速率计算，则用新速率除以原速率。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
重新分片
在完成需要完整参数的计算后，释放临时收集的完整表示，仅保留该 rank 应持有的分片。
重新分片
按新的设备数或布局重新划分同一全局张量；每个新分片只能从与其坐标相交的旧片段取值。
量化
用有限个离散码近似表示原数值。尺度、零点和分组方式决定恢复后的数值及误差。
门控
用一条分支算出的输入相关系数，逐通道乘到另一条分支上。系数由输入决定，常规稠密实现仍会执行两个投影。
隐藏宽度
每个位置进入下一层时保留的特征通道数，通常记为 D。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
预取
在后续层开始计算前就发起参数传输。预取越早，计算等待参数的时间可能越短，但完整参数与当前层数据同时占用显存的时间也可能越长。
驻留
线程块已获得在 SM 上运行所需的寄存器、共享内存和调度名额。块被接纳后，其线程仍可能等待数据。
