1　张量并行与 MLP 的两次投影

张量并行把同一层的计算分给几张卡。沿用上一课的点积，[2,3] 与 [4,5] 相乘再求和。0 号算 2×4=8，1 号算 3×5=15，最后把两边加起来才得到 23。若任务改成同时求两个不同的输出，每张卡也可以各领一整列权重，直接算完一个输出。切分的方向决定两边最终拿到的是完整输出还是部分和。

如果一层的权重放不进单卡，或者单卡完成矩阵乘法太慢，可以沿输入或输出特征维度拆分权重，让多张卡共同计算这一层。前馈网络（MLP）先把每个 token 的特征展开，逐个做非线性变换，再投回模型宽度。设输入有 D 个特征，中间有 F 个特征，暂不加偏置。各矩阵的形状为 X=[Ntok,D]，W1=[D,F]，W2=[F,D]，中间激活函数逐元素作用。这里 Ntok 合并了 batch 与本 rank 参与计算的 token 位置；书写采用 XW，PyTorch Linear 的 weight 则按 [out,in] 保存。

先看上半幅的 X。第一层 A 沿输出列分成两份，两个设备各自产生中间特征并在本地做 GeLU；第二层 B 沿输入行切分，各设备得到的是同一输出的部分和。绿色 g 在前向归约这些部分和。左端 f 前向传递输入，反向才归约两路输入梯度。下半幅把同样的分工用到不同注意力头上。

2　张量并行的输入梯度归约

上一节两张卡读的是同一个输入。输出发生微小变化时，两条计算路径都能把变化传回这个输入。先看一个数 x：卡 0 算它的两倍，卡 1 算它的三倍，损失取两个结果之和。x 增加 1 时，损失一共增加 5，所以输入梯度要把两卡的 2 和 3 相加。

回到上一节的双输出算例，设损失对两个输出的梯度都是 1。第二层反向时，卡 0 的两行权重分别是 [1, 0]、[0, 1]，每行与 [1, 1] 点乘，得到中间梯度 [1, 1]。卡 1 的两行是 [1, 1]、[2, −1]，同样得到 [2, 1]。四个中间激活都大于零，ReLU 把梯度原样传回。

再沿第一层传回输入。卡 0 的列块是单位矩阵，给两个输入的贡献仍是 [1, 1]。在卡 1，第一个输入连到两列的权重是 1、2，分别乘中间梯度 2、1，加起来得 4；第二个输入对应权重 1、−0.5，得到 1.5。两张卡逐位置相加，输入梯度为 [5, 2.5]。

设 Zi=XW1,i，GZi 是通过激活函数反向传播后，损失对 Zi 的梯度。则 GX=∑i=0p−1GZiW1,i⊤，而每张卡独立计算 GW1,i=X⊤GZi。

行并行 W2 的局部输入 Hi 只需要自己的 dHi=dY·W2,i⊤，所以这一处可以本地完成。常见非 SP 的两层 MLP，在前向末尾归约一次 [T,D]，在反向回到 X 时再归约一次 [T,D]。Attention 的投影组合还会增加对应通信；整层 Transformer 的成本不能只数 MLP 的一次前向。

3　门控 MLP 的特征对齐

普通 MLP 做完第一层投影后，对每个特征做一次激活。SwiGLU 的中间层为每个特征算两个数：一个是待传给下一层的值（up），一个经 SiLU 激活后作为乘数（gate）。同一个位置的两个数相乘，就能随当前输入调节这个特征送往下一层的大小。

例如，两个通道的门值是 0.2、0.9，对应的 up 值是 10、3。按通道配对，通道 0 是 0.2×10=2，通道 1 是 0.9×3=2.7。如果只交换 up 分片，两项就会变成 0.2×3=0.6 和 0.9×10=9；张量仍有两列，但每列读错了伙伴。

SwiGLU 先把同一输入投影到两组中间特征：gate=XWg、up=XWu，然后逐元素计算 SiLU(gate)×up，再由 Wd 投回 D。gate 的第 f 个特征必须与 up 的第 f 个特征配对。把两个物理连续大块随意按总行数均分，可能让某些 rank 只有 gate、另一些只有 up，破坏无需通信的局部乘法。

4　序列并行中的归一化与残差

把四个 token 写成四行，每行保留这个 token 的全部特征。算 RMSNorm 时，一行只需用到这一行的数。残差相加也是同一行的对应位置相加。于是可以让卡 0 管前两行、卡 1 管后两行，省下两卡重复存放同一份激活的空间。这就是 Megatron 配合张量并行使用的序列并行（SP）。

5　注意力的按头分片与词表的按词分片

Attention 中，如果每个 rank 都持有若干完整查询头，并且可以读取这些头对应的 KV head，各 head 的 QK⊤、softmax、PV 可本地计算，再通过输出投影的行并行归约回 hidden。head dimension d 是点积归约维；随意在一个 head 的 d 中间切开，会引入额外点积归约与 softmax 依赖，已经改变了这里讨论的 head-parallel 路径。

GQA 例子：Hq=32、G=8、d=128，TP=4。按 KV group 划分，每 rank 持有 8 个 query head、2 个 KV head，每个 KV head 服务 4 个 query head。TP 增到 16 后，8 个 KV head 无法继续按相同等分方法分成 16 份；实现可能限制配置、复制 KV group 或使用其他布局。是否支持及通信量必须看实际代码，不能只检查 Hq 能否被 TP 整除。

把切分方向换到最后的词表投影，情况就不同了。一个注意力头可以独立决定关注哪些历史位置；几个候选词却要分享同一份总概率。把词表分给两张卡之后，两边仍须就同一个 token 的分母达成一致。

词表输出投影又有不同结构：logits=[T,V] 可以沿 V 分片，但每个 token 的 softmax 分母需要整个词表。只对本地 Vp 做 softmax，会改变概率。一个可行方法是先归约全局最大值，再归约指数和，并找到 target 所属分片的 logit；这样通信的是每 token 的统计量，不必 AllGather 完整 logits。

z0=(1+2)/4=0.75,z1=(3+4)/4=1.75,z=z0+z1=2.5

7　Ring Attention 的键值传递与缓冲复用

上一节解决了一行查询怎样合并多个键块。Ring Attention 进一步安排这些键值块怎样传到需要它们的卡：把卡连成一圈，各自留下查询，每轮从上一个邻居接一块 K、V，向下一个邻居送一块。四张卡各算自己的本地块，再经过三轮交换，都能看到全部四个块。

上半幅中，每台设备留下自己的 Query Block，水平箭头搬的是 Key Value Block。下半幅选定一行 Query 后向右看，先消费本地的 K、V，再消费邻居送来的块，同时向下一台发送已经用过的块。查询块累计各轮的归一化统计量和输出，因此历史能分散存放，最后仍可合并成这行查询的完整注意力。

本地查询有 b 行，本轮收到远端 c 行键值。乘法消去键宽 d，留下 b×c 个位置分数。逐行计算指数权重后，只保留分子和分母与基准，才可把远端缓冲交给下一轮。

Zblock 在这里专指尚未缩放的点积块。软最大归一化使用的分数还要逐项除以 d，再施加因果掩码。即使下一个键值块来自另一台设备，两块的指数基准和概率分母仍需按同一条查询合并。

Zblock=Q·Kblock⊤b×cb×dd×c

例如本地有 2 个查询、远端有 3 个键，每个键有 4 个特征。两行查询各和 3 个键做点积，共得到 6 个分数。每个点积先缩小到原来的一半，因为 4 的平方根是 2。因果掩码再按位置屏蔽相应分数。

本课引用的 PyTorch 版本中， _cp_options.rotate_method 默认是 ALL_GATHER。_AllGatherRotater 一次聚集 KV，后续轮次从 aggregated_buffer 中取对应块；_AllToAllRotater 则通过 permute_tensor 将当前 KV 发给下一 rank。两者可服务同样的逐块 attention 循环，临时容量和通信发起方式却不同。

11　GPipe 与同步 1F1B 的微批排程

GPipe 是 Google 开源的流水线并行训练库。训练很深的模型时，单个加速器有时装不下所有层的权重和反向传播要用的数据。把连续的层分给不同设备，就能共同容纳模型。Google 用 GPipe 将 5.57 亿参数的图像分类模型 AmoebaNet-B 分成四段，在 ImageNet 上训练。原始实现在 TensorFlow 的 Lingvo 仓库中。Google 的训练记录　Lingvo 的流水线实现

假设模型只有四层，甲负责前两层，乙负责后两层。若一大批图片从头到尾一起走，甲算前两层时乙没活干，轮到乙时甲又闲下来。把同一批图片切成 A、B 两小批，甲交出 A 的中间结果后就能开始 B，此时乙正在算 A。这就是微批让多台设备忙起来的原因。

开始训练时，先让这批微批都走完前向，再沿相反方向做反向，收齐梯度才更新这一批的权重。每个阶段因此要保留尚未反向的微批所需的入口激活，反向可按实现从入口重算内部值。

换成同步 1F1B，仍用同样的阶段和微批。预热让流水线先有工作可做；当较早微批的梯度返回，稳态把一次新微批的前向和一次较早微批的反向交替安排，最后收尾清空剩下的反向。如果 A 已经反向完成，A 的激活就可释放，即使后面还有未做完的微批。

设 p 个阶段等速，一次前向或反向各占一个时隙。第一份微批到达末级要 p 个时隙，接下来 m−1 份各隔一个时隙到达，故前向共 p+m−1 个时隙。再用同样方法数反向。一台设备全程忙于 m 次前向和 m 次反向，利用率的分子、分母由此确定。

U=m+m(p+m−1)+(p+m−1),p=4, m=4 ⟹ U=4/7

U=mm+p−1,β=1−U=p−1m+p−1

这个估算取p 个 stage，每个 microbatch 的前向和反向各占一个相同时间槽，通信耗时忽略，单 stage 同时只执行一个计算任务；总长度为 2(m+p−1)，每个 stage 做 2m 份工作。U 为平均计算占用比例，β 为相应空槽比例。若某段计算较慢，或梯度传输迟迟未完成，要按实际耗时拉长相应的格子，等待它的设备也会推迟开工。

p=8、m=8 时 U=815≈53.3%；m=64 时 U=6471≈90.1%。增加 m 可以摊薄气泡，但在固定 global batch 下会减小单 microbatch，可能让 GEMM 变小、启动开销增多。若固定单 microbatch 而增加 m，又会改变训练的有效 batch 和一次更新间隔。

Megatron-LM 把 1F1B 的排程落到每个阶段自己的队列里。以四个阶段、八个微批为例，从 0 开始编号，阶段 0 要先做三份前向，阶段 1 做两份，阶段 2 做一份。末级直接接触损失，第一份前向结束就具备反向的条件。

12　交错流水线的虚拟阶段与设备负载

设八个连续的层段编号为 0 至 7。用四张卡跑这个模型，可以让卡 0 先负责段 0，等微批依次走完卡 1、2、3，再回到卡 0 跑段 4。一个微批两次来到同一张卡，做的是模型里不同位置的计算。每个层段就是一个虚拟流水线阶段。

这一分工下，卡 1 管段 1 和 5，卡 2 管段 2 和 6，卡 3 管段 3 和 7。某些时隙里，段 0 还在等新的输入，段 4 已收到较早微批的激活，卡 0 就可以先做段 4。这种把不同段的就绪工作穿插起来的排程叫交错调度。

虚拟段增加了跨段激活边界，细碎任务可能增加消息和调度开销。每个物理 rank 还需要管理多套参数段、保存队列及对应输入。上一节的 p 统计可同时工作的物理 stage。同一设备上的虚拟段共享算力，轮流占用该设备的执行时隙。

真实 stage 的耗时也常不均衡。词表投影和交叉熵可能拖慢末段，embedding、MoE 路由、不同长度 attention 或不均匀层类型会改变其他段。若四个 stage 的每个 microbatch 总计算时间为 [4,4,7,4] ms，稳态吞吐受最慢的 7 ms 限制；即使没有边界气泡，均匀流水理想下的整体计算占用上限也只有 194×7≈67.9%。这还未计通信。

上例每轮四张卡实际共做 19 个设备毫秒的计算。最慢阶段每 7 毫秒才接得下一份微批，这 7 毫秒里四张卡合计有 28 个设备毫秒可用。19 除以 28 才是上面这个利用率的来历。

切分时应以实测或可信模型中的时间和峰值容量配平，层数只能作为初始近似。重计算可减小某个 stage 的激活占用，却增加其计算时间；把该段变成新瓶颈后，其他设备可能等待更久。一个参数同时影响显存与调度，需要在同一个候选配置里评估。

反向也有两项工作。把损失对输入的梯度算出来，上一段就能开始反向。求本段权重的梯度只需赶在优化器更新前完成。能把两项计算拆开时，可以先传输入梯度，让上一段开工，再把权重梯度计算安排到本卡随后空出的时隙。延后期间还要保留计算权重梯度所需的输入和输出梯度。

13　数据副本与每次更新的全局批量

沿图数一轮更新处理了多少条序列。每个数据副本一次读入一小批，共读 m 次，然后更新一次。若有两份模型副本，各自都读取不同样本，两份读过的序列才能相加。下式中 b 的下标 micro 表示每个副本一次读入的序列数，d 的下标 data 表示这样的副本数。

Bglobal = bmicro m ddata

一次更新的全局批量先按一个副本累计的序列数计算，再乘数据副本数。张量并行的卡负责同一序列的不同特征，上下文并行的卡负责不同位置，流水线的卡负责不同层。这些卡一起完成同一份样本的计算。

例子：64 个设备，PP=4、TP=4、CP=2、DP=2，乘积为 64。每副本 microbatch=1、m=16，则 global batch=32 条序列。若每条均为 32768 个有效 token，一次更新为 1,048,576 token。padding、packing、丢弃标签和变长样本出现时，应直接统计有效 token，不能继续机械乘最大长度。

为了比较两种 PP 调度，应先决定固定哪些条件。固定 global batch 和 DP 度数后，m 增大四倍就要求 bmicro 相应减小四倍；若 bmicro 已经为 1，就没有继续缩小完整序列 batch 的空间。也可以调整 DP 度数或重新定义训练 batch，但这会影响优化行为与其他通信量。

数据读取同样要按角色分工。所有 TP/CP rank 各自随机取一个无关样本，会把一个逻辑模型副本拼成相互不一致的输入。常见方案由指定 rank 读取后广播或分片，也可以让各 rank 从确定的数据位置生成匹配视图。上一课 checkpoint 中的数据游标，应能恢复这种逻辑样本对应关系。

两个数据副本各处理一条序列，一个有 2 个有效标签，另一个有 6 个。若报告的局部平均损失分别为 3、1，则全局 token 平均为 2×3+6×18=1.5。简单平均两个局部均值会给出 2。此例按有效标签等权，每个标签各贡献一份，第一份序列因此占四分之一的权重。

16　同一组 rank 的稠密与专家网格

普通前馈层让所有 token 使用同一套权重。混合专家模型另有几套前馈网络，叫作专家；路由器为每个 token 选择要运行的专家。把不同专家放到不同卡上，叫专家并行（EP）。因此同一台机器在注意力层可能负责一组特征，到了专家层却要按专家编号接收 token。

设 DP_shard=2、CP=2、TP=2，PP=DP_replicate=1。若按最后一条轴的坐标变化最快的顺序给设备编号，rank=4·dp+2·cp+tp，共 8 个 rank。TP group 为 [0,1]、[2,3]、[4,5]、[6,7]；CP group 为 [0,2]、[1,3]、[4,6]、[5,7]；DP_shard group 为 [0,4]、[1,5]、[2,6]、[3,7]。不同 group 可以共享 rank，但承担不同数学动作。

例如全局编号 5 的卡，三个坐标依次是 1、0、1。固定前两个坐标，张量并行伙伴是卡 4；只改上下文坐标，伙伴是卡 7；只改数据分片坐标，伙伴是卡 1。图中所有连线都能这样逐项查回。

总数检查为 dp_replicate×dp_shard×cp×tp×pp，未再乘 ep。sparse_region=dp_shard×cp×tp，要求其能够被 ep 整除。EP 从这个设备池重新划分，剩余大小用于专家区的状态分片。

本例 EP=4 时，专家组为 [0,1,2,3] 与 [4,5,6,7]，剩余 expert shard 度数为 2；EP=8 时，所有 rank 构成一个专家组，剩余 expert shard 度数为 1。两种配置都只有 8 个设备。稠密 attention 的 CP/TP 布局仍按稠密 mesh 解释，进入 routed experts 时需要转换 token 的持有方式与专家目标。

EP 的直接含义是不同 rank 拥有不同专家；还可能对某个专家做 TP 或 FSDP，二者需要额外的形状与 group 规则。路由后各专家收到的 token 数通常不相等，token-to-expert 分发与结果回收需要 AllToAll 或专门通信路径。下一课会追踪 token permutation、capacity、grouped GEMM 和负载不均衡，本课先确定 EP 并不总是一条额外独立乘法轴。

同一模型中稠密参数与专家参数可能具有不同的“数据副本数”和分片方式。计算 optimizer 容量、梯度除法和有效 batch 时应按对象所属的 mesh 解释，不能拿一个全局 DP×EP 因子统一除所有参数。

对照一条 token 的专家记录时，“rank 1”要注明是哪个进程组内的局部编号。例如全局组 [2,6] 内的局部 rank 1 实际是全局 6；用 1 去查全局专家分配会发送到错误设备。可先打印局部到全局的映射表，再逐条核对 router 的全局专家号、分派使用的目标局部 rank 和本地专家号。

设每台机器有八张 GPU。同一台内的卡通过高速互联通信，跨机器的数据要经过网卡。以 64 卡为例，一个流水阶段的一份数据副本用四张卡切特征、两组卡切上下文，正好占满一台机器。这样每层都会发生的张量归约和上下文交换可以留在机内。其余机器用于其他流水阶段和数据副本。

64 设备示例的 rank 可取 (((pp×2+dp)×2+cp)×4+tp)，节点编号为 floor(rank8)。rank 0 的 TP 伙伴为 [0,1,2,3]，CP 伙伴为 [0,4]，DP 伙伴为 [0,8]，PP 伙伴为 [0,16,32,48]。这种枚举能检查 group 是否真的落在预期节点中；仅设置 tp=4 不会自动保证物理局部性。

容量例子单独规定一种存储策略：70B 参数，按上一课显式 16 byte/参数的低精度训练状态记账，层与 TP 均匀切分，CP 上保留副本，仅沿 DP 做全状态分片。64 设备布局的理想每 rank 状态为 70×109×164×4×2=35GB；512 设备布局为 70×109×168×4×8=4.375GB。若 FSDP 还沿其他轴分片，或 optimizer 的 dtype/状态不同，要重新列公式。

先算整份模型，700 亿个参数每个按 16 字节计，共 1,120 GB。64 卡方案把状态分给 4 个流水阶段，每阶段按 4 路张量并行切分，数据并行再按 2 路分片，一共 32 份。另一个上下文伙伴保留相同状态，因此每卡承担 35 GB。512 卡方案同理，共切成 256 份。

这些数字未计 FSDP 参数聚集、激活、通信缓冲、词表/embedding 的不均衡以及 allocator 余量。70B 的层数能否按 PP8 合理切分，head/FFN 能否按 TP4 对齐，CP2 的实际算法是否保留完整 KV，都会影响可行性。容量可行也仅是候选配置的第一关。

跨节点的 FSDP 聚集、PP 激活传递与 EP 路由可能同时争用网卡；每条通信单测有足够带宽，组合后仍可能排队。应画出一层到下一层的依赖，找出无法被计算覆盖的通信，再比较减小 TP、增加 PP、改变 microbatch 或调整 FSDP 组大小的代价。

例如前向、反向各跨机发送一次 64 MiB，若这样的通信在同一路径上重复 32 层，合计发送 4 GiB；若只在一处流水边界发生，一次微批来回合计 128 MiB。比较布局时，同一条链路上每次发送多少、每步重复几次、接收方何时需要数据，都要放到同一条时间线上。

完全分片数据并行。模型参数等训练状态在组内分片；模块计算前暂时收集所需权重，计算结束后按策略释放。
GEMM
通用矩阵乘法。左矩阵的行与右矩阵的列逐项相乘、求和，得到输出的一个元素；训练和推理中的线性层大量使用这种运算。
GiB
二进制容量单位，1 GiB 等于 1,073,741,824 字节；1 GB 按十进制等于十亿字节。
GPU
图形处理器，使用大量线程并行处理数据。需要许多独立运算或数据复用时，它常比逐项在 CPU 上执行更合适。
GQA
分组查询注意力。多组查询头各自共享一组键和值，可以减少解码时需保存和读取的 KV 数据。
HBM
GPU 常用的高带宽显存，用于保存权重、激活和中间结果等数据。芯片与显存之间可持续传输的字节数会限制某些算子。
key
注意力中用来与查询匹配的向量。每个可见位置提供一个键，其分数决定同位置的值参与汇总的权重。
KiB
二进制容量单位，1 KiB 等于 1,024 字节。
KV
键和值的合称。一个历史位置通常既提供参与匹配的键，也提供按注意力权重汇总的值。
LayerNorm
对选定维度减均值并按标准差归一化，通常还带有可学习的缩放与偏置。
logits
归一化之前的分数。例如语言模型为下一个位置的每个候选 token 算一个 logit，经过 softmax 后得到概率。
LSE
LogSumExp，即一行指数和的对数。给定每个位置的原分数和该行的 LSE，就能重建 softmax 权重。
MHA
多头注意力。常见实现为每个查询头配一组独立的键和值，再把各头的输出拼接起来。
MiB
二进制容量单位，1 MiB 等于 1,048,576 字节或 1,024 KiB。
MLP
前馈网络，在每个位置的通道维上施加线性变换和非线性函数。常见解码器先扩展通道再投影回残差宽度。
MoE
混合专家模型。路由器给每个词元挑选少数几个专家，由选中的网络计算，再按路由权重合并结果。
P2P
设备能按受支持的方式直接访问另一设备的内存。它描述访问能力，实际走 NVLink 还是 PCIe 仍取决于拓扑。
Partial
分布式张量的部分结果布局。各参与者持有对同一输出的贡献，必须按指定操作归约才能得到完整值。
PP
流水线并行。把不同层放在不同设备组，让多个微批次依次经过各阶段；某些阶段等不到输入时会空闲。
PV
注意力权重矩阵与值矩阵的乘积。在线计算时可以先用未归一化的权重累加分子，最后按行除以分母。
query
注意力中发起查询的位置或它的向量。它与各个可见位置的键相乘，得到对应的一行分数。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
ReduceScatter
先跨进程归约对应元素，再把归约后的结果按约定分片，每个参与者只留下自己负责的部分。
Replicate
分布式张量的复制布局，表示同一设备网格轴上的参与者各持有相同的逻辑值。
RMSNorm
按一个向量各分量的均方根进行归一化，再施加学习到的尺度。它不需要先减去向量均值。
shape
张量形状，按顺序列出每一维的长度。即使元素总数相同，批次轴与通道轴的互换也会改变算子的含义。
Shard
分布式张量的一种布局标记，表示沿指定张量轴拆分。它需要与设备网格的轴一起解读。
softmax
把一行分数先取指数，再各自除以这一行的指数和，得到总和为一的权重。实作时可先减去行最大值以免指数溢出。
SP
序列并行。将按序列位置独立的计算和激活分给多张卡，以减少各卡重复保存的激活；具体拆分随框架而异。
SPMD
多个参与者运行同一份程序，再依据自身 rank 和布局处理不同的数据分片。
SwiGLU
一种带门控的前馈层。输入经两组投影，一支过 SiLU，再与另一支逐元素相乘，最后投影回输出宽度。
tile
计算时一次处理的一小块数据。划分 tile 可以让线程重复利用已搬进片上的数据，同时限制临时存储量。
token
分词器交给模型的一个单位。它可能是一个字、一个词或词的一部分，进入模型时有自己的整数编号。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
TP4
使用四个参与者的张量并行组。某个头或通道由哪张卡负责，取决于具体布局。
Transformer
用注意力混合不同位置的信息，再逐位置通过前馈网络。一个解码器通常把多层这样的计算依次连接起来。
value
注意力要汇总的内容向量。它与同位置的键配对，并按注意力权重计入输出。
上下文并行
把同一请求的序列位置切给多个 rank。局部查询仍可能需要访问其他 rank 持有的历史 K、V。
交叉熵
给定真实下一 token 的编号后，取模型给该编号分配的概率并计算其负对数；预测概率越小，损失越大。
信号
收发双方约定的完成标记。生产者更新标记前，要把标记与相应代的数据写入建立正确顺序。
元素数
张量各维长度的乘积。将它乘以每个元素的字节数，得到连续有效数据的大小，尚未计入对齐和分配器开销。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
列并行
按权重矩阵的输出特征列切分。各卡对共享输入计算不同输出通道，是否收集全部输出取决于下一算子的布局。
因果掩码
限制一个位置只能访问自身和允许的过去位置，防止预测时读到未来内容。对角线的对齐方式取决于查询与键对应的绝对位置。
因果负载
只数有效查询与键配对时，越靠后的查询通常能看见越多历史位置，因此不同序列区间的工作量可能相差很大。
固定提交
用 Git 提交哈希锁定本课所引用的源码版本，避免行号随主分支变化。
在线 softmax
按块读入分数，只保存当前行最大值和按它计算的指数和。遇到更大的分数时先把旧和换到新基准，最后可得到整行一致的归一化结果。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
工作区
算子在执行过程中为暂存中间数据而申请的区域。模型权重大小不变时，工作区仍可能随输入或算法改变。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
microbatch
把一批训练样本拆成几份后，单次前向或反向计算处理的那一份。多个 microbatch 的梯度可以累积到同一次权重更新。
投影
此处指注意力与前馈层内的稠密矩阵乘。它按实际输入 token 行数重复执行，同一份权重可被多行共享。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
指数基准
为计算稳定性而从当前所有分数中共同减去的数。合并两块时，两块的指数和与加权和都须换算到同一基准。
排空
等待或确认已经提交的设备访问全部结束，使原缓冲能安全复用。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
时间线
将不同线程、CUDA 流及设备活动按时间展开，可结合事件与请求编号追踪先后依赖。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
有效配对
对某个查询位置，掩码允许它读取的一个键位置。统计有效配对可估算算法工作量，实际内核还可能计算被掩掉的块内元素。
未归一化
保留各项加权和，同时单独记录权重之和；除以对应分母后才是可直接输出的加权平均。
查询头
以一组 Q 通道独立计算注意力分布的头。多个查询头即使共用 K、V，也保留各自的打分和概率。
梯度累积
连续处理多个微批次，将其梯度贡献累加到缓冲区，再统一更新参数；样本数不同时还需处理归一化分母。
注意力头
独立计算一套打分、归一化权重和加权输出的通道组。
流水线
把搬运、计算等相互依赖的阶段错开执行。不同数据块可以重叠，但消费某个块之前仍要确认它已准备好。
激活
模型处理本次输入时产生的中间张量。它的形状和寿命依赖批量、序列长度以及接下来是否需要反向传播。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
虚拟流水线阶段
同一物理 rank 上逻辑上分开的模型层段。交错调度可以缩短部分空闲区间，但可能增加通信和调度开销。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
视图
共享底层存储但拥有自身形状、步长和偏移的张量表示。释放其中一个视图时，其他持有者仍可能让整块存储无法回收。
设备网格
把每个物理 rank 映射到各并行轴坐标的布置，轴的乘积须和实际设备覆盖关系吻合。
词表
记录 token 与整数编号对应关系的表。词嵌入矩阵使用同一套编号查行，每行才是模型参与运算的向量。
词表分片
把分类输出的词表轴分给不同 rank，每个 rank 只算一段 token ID 的 logits。计算全局归一化或抽样时仍须协调。
输入梯度
损失相对于共享输入各分量的偏导。多条分支都读同一输入时，各分支的梯度贡献要按元素相加。
输出投影
拼接多个头的输出后再做一次线性变换，使同一位置可以混合来自不同头的特征。
逻辑坐标
由张量的轴和下标标记的位置。坐标本身不能唯一决定物理地址，还须结合布局与起始指针。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
门控
用一条分支算出的输入相关系数，逐通道乘到另一条分支上。系数由输入决定，常规稠密实现仍会执行两个投影。
指数基准
算一块 softmax 时，从各分数中减去的参考值，通常取块内最大分数。合并不同块时，要把已有的分子和分母换到同一基准。
预热
在正式计时前运行若干次，让编译、缓存建立或一次性初始化尽量离开稳态样本。
驻留
线程块已获得在 SM 上运行所需的寄存器、共享内存和调度名额。块被接纳后，其线程仍可能等待数据。
