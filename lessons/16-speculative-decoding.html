1　单轮验证的交付 token 数

设服务正在生成一段长回答，目标模型每次 decode 需要读入大量权重和历史 KV，小 batch 下新增一个 token 的计算未必用满设备。投机解码先让便宜的草稿器提出 k 个候选，再把它们作为已知输入交给目标模型批量计算条件分布。目标模型依然决定最终输出；草稿器决定这次尝试能否把一次昂贵迭代换成更多有效进展。

先固定索引，避免“多了一个token”引起误解。已有长度为 t 的已确定历史x1,…,xt，其中xt是上一轮刚采样的 anchor，目标 KV 只算到xt−1。草稿器给出d1,…,dk。目标本轮输入[xt,d1,…,dk]，共k+1个 query 位置；对应 logits 行分别预测d1、d2、…、dk以及全接受后的下一个 token。

pi(v) = PT(v|x1:t,d1:i-1),    qi(v) = PD(v|x1:t,d1:i-1)

目标模型可以在一次前向中计算这些验证行，因为候选 token 已经给定，causal attention 沿候选历史计算。它没有预先知道最终会接受几行。若d1、d2接受而d3拒绝，p4依赖被拒绝的d3，这一行不能继续接到纠正后的历史。普通逐位置验证只保留连续接受前缀，在第一个拒绝点采样纠正 token，然后结束本轮。

2　接受概率与拒绝后的纠正分布

草稿分布对某个词给出的概率可能高于目标分布。验证阶段只能保留目标分布允许的那部分概率质量；一旦拒绝，剩余概率要转给目标分布中仍有缺口的词。拒绝后再直接从完整目标分布抽样，会把已经通过接受分支交付的概率重复计入。

先看一个位置，以下概率都以相同的已确认前缀为条件。目标分布为 p，实际抽取候选的草稿分布为 q。抽到候选 v 后，以a(v)=min{1,p(v)/q(v)}接受；q(v)=0的位置不会由草稿抽到，因此无需在该事件上做除法。被接受并输出 v 的无条件概率为q(v)a(v)=min{p(v),q(v)}。目标还缺的质量正是p(v)−min(p(v),q(v))。

令 v 是本次由草稿分布 q 抽到的词，p 是同一前缀下的目标分布。a(v) 为条件接受率。求和下标 u 遍历词表；Z 是目标分布仍待补给的概率质量，也等于总体拒绝概率。拒绝后从剩余质量归一化得到的分布 r 抽样。当两分布完全相同时，Z 为零，所有草稿都接受，无需计算 r。

a(v) = min(1,p(v)q(v)),    Z = ∑umax(p(u)-q(u),0)

r(v) = max(p(v)-q(v),0)Z

P(Y = v) = min(p(v),q(v)) + Zr(v) = p(v)

Z 等于这一位置的总拒绝概率。发生拒绝后，必须从归一化的剩余质量 r 采样，才能补齐每个 token 的缺口。若直接再次按 p 采样，已接受部分对某些 token 额外加权，会得到不同分布。p=q时Z=0，拒绝事件概率为零，执行路径无需构造00的纠正分布。

三 token 词表：p=(0.5,0.3,0.2)，q=(0.2,0.5,0.3)

按词 B 验算下表：草稿抽到 B 的概率是 0.5，接受率为 0.3/0.5=0.6，所以直接输出 B 的质量是 0.5×0.6=0.3。三个词直接接受的质量依次为 0.2、0.3、0.2，总数 0.7。剩下的 0.3 全部补给 A，正好填上目标 0.5 与已接受 0.2 的差。

要从逐词接受概率求整次接受率，只须把重叠的概率质量沿词表相加。对每个词都有 min(p,q)=(p+q−|p−q|)/2；两份分布分别加到 1，于是多出来的绝对差恰好以一半的系数扣除。

α = ∑vmin(p(v),q(v)) = 1-12∑v|p(v)-q(v)|

α是分布重叠面积，也就是1减去 total variation 距离。它衡量这一历史条件下普通拒绝采样的期望接受率。单个被抽中的 token 的 a(v)、整个位置的α、实际连续接受长度，是三个不同统计量。即使两边概率最高的是同一个词，其余概率质量的分配仍会改变期望接受率。

逐位置重复上述等式，并要求每一步使用当前有效历史对应的 p 和 q，才能推出整段生成遵循目标的自回归联合分布。数学结论依赖相同的目标采样规则、正确的候选条件及非预知的调度决策；浮点近似和不同 kernel 归约仍可能改变细节。分布保持也不要求固定 seed 下与逐 token 基线逐字相同。

3　vLLM 的验证与重采样内核

本节限定普通逐位置拒绝采样分支：关闭 synthetic 模式、block verification 和 FLy 扩展。在这个分支中，每个候选按概率比进行接受检验。synthetic acceptance 用于构造指定接受行为，适合测试指定接受率下的系统开销。

代码 1　在 log 域比较 p(d)与u·q(d)

714–716 行在对数域比较接受条件。若草稿给某个词分配的概率超过目标模型，该词被提出得过于频繁，验证步骤就需要拒绝其中一部分。

均匀随机数 u 来自请求 seed 与位置；目标和草稿 logprob 都需要先完成各自归一化。比较logp>logu+logq避免显式求比值。p≥q时始终接受；p<q时，u 小于pq才接受。

温度为零时的贪心验证分支直接比较候选与目标 argmax。温度大于零时，即使草稿采用确定性 argmax，也可以把它看成集中于一个 token 的 one-hot q，再做概率纠正。此时接受概率是目标分配给该 token 的概率；拒绝后从目标分布里移除该 token 并归一化。

代码 2　非 block 模式下用 log 差构造残余概率；one-hot 草稿有独立分支

987–990 行只让目标分布相对草稿多出的那部分质量参与补采样。若某词已经被草稿过度推荐，再给它补上一份概率会继续放大偏差。

ratio=exp(logq−logp)。当q<p时，log(p−q)=logp+log(1−q/p)，实现用 log1p 计算右侧第二项；其余位置写−∞。这里给 Gumbel 采样提供的是未归一化 log 权重，公共归一化常数不影响 argmax。没有草稿 logits 时，源码将被拒绝的 one-hot 位置屏蔽。

完整草稿 logits 不仅用于生成，也可能必须保留到下一轮验证。若把 top-k、温度、词表裁剪之前的分布误当成实际 q，pq测试就对应错误的提议过程。源码注释明确指出缓存的 draft logits 处在温度处理之前，重采样分支会按 temp 缩放；其他变换需要沿 draft 路径确认在哪里已应用。

Gumbel-max 用于按给定权重抽样：为每个词表位置生成 Gumbel 噪声，再对 log 权重加噪声取最大值。它可以用于草稿采样、纠正采样或 bonus 采样。Gumbel 用于采样，草稿的接受条件仍由验证规则决定；本节的普通随机验证仍执行概率比测试。随机数流的请求/位置键、草稿与纠正域的区分也应保持稳定，避免 batch 重排使请求互相借用随机状态。

目标分布 p 还包括用户实际指定的 temperature、top-p、penalty 和 grammar 等规则。结构化输出尤其依赖候选前缀：每个验证位置的语法状态必须沿候选推进，拒绝后只提交有效前缀。DeepInfer 在 verification 前按 step 施加 bitmask，这个顺序决定验证的 p 是否与正常受约束解码一致。

4　连续接受长度的期望

令 A 为本轮连续接受的草稿数量，N=A+1为交付数量，暂不考虑 EOS 和最大输出长度截断。对非负整数 A，有E[A]=∑i=1kPr(A≥i)。把“前i−1个已接受”条件下第 i 个继续接受的概率记作ai，则生存概率si=Pr(A≥i)=∏j=1iaj。这是条件概率链式法则，无需假定各位置独立。

si = P(A ≥ i) = ∏j = 1iaj,    E[N] = 1 + ∑i = 1ksi

若所有条件接受率都取常数 a，k=4、a=0.8时，s=(0.8,0.64,0.512,0.4096)，E[N]=3.3616。第4个位置贡献0.4096个期望输出，却仍要消耗一行目标计算。若a=0.3，E[N]=1.4251。这里 a 是教学假设的条件概率。实测时按草稿位置分别统计到达该位置后的条件接受率，再将各步概率相乘。

相同总“成功标记”数量，连续前缀进展可以不同

从左向右数到第一次拒绝就停。第一组两轮分别连续接受 3 个和 0 个，普通协议每轮还交付一个纠正或额外 token，所以平均为 ((3+1)+(0+1))/2=2.5。第二组虽然也有三个成功标记，但两轮连续前缀只有 1 个和 0 个，平均就变为 ((1+1)+(0+1))/2=1.5。

如果另一个请求只有一两个输出 token 的余量，即使草稿很准，也没必要为几十个候选建立 KV 和 logits。剩余长度、语法约束、当前 batch 及上下文长度应参与预算上界。

草稿长度固定为 3 时，一轮并不会独立发出三个可任意挑选的词。设第一个被接受的概率为 a，给定第一个已接受、第二个也被接受的条件概率为 b，再给定前二者通过时第三个通过的条件概率为 c。能交付第一个草稿的概率为 a，第二个为 ab，第三个为 abc。期望接受长度为 a+ab+abc。若协议在首次拒绝时发一个纠正词，全部接受时再发一个目标词，且不遇 EOS 或长度上限，那么期望总交付数比这个长度多 1。复用这条公式前要核对实现是否确实包含末尾额外采样。

两步候选的条件接受概率依次为 0.9、0.5，则通过首步的概率为 0.9，两步都过为 0.45，期望接受 1.35 个。顺序换成 0.5、0.9，期望降到 0.95 个，尽管两项算术平均数相同。统计下一步是否值得验证时，应以“本轮确实走到这一步”的样本估计条件概率，再乘以前面连续存活的概率。

7　DSpark 的并行骨干与顺序头

纯块并行草稿在一次草稿主干前向中产生多个未来位置的 logits，避免为每个候选重复执行整套草稿 Transformer。但多个位置若独立采样，会把不同语言分支的片段拼在一起。例子是第一位置可以选“of”或“no”，第二位置分别适合“course”或“problem”；两个位置只知道共同上下文，就可能组成不匹配的“of problem”。

依图中编号读。① 目标模型从 A、B、C 生成锚点 D。② 并行骨干一次准备多个位置，顺序头给出 E、F、G、H 及各自置信度；调度器留下连续前缀 E、F、G，去掉 H。③ 目标模型并行验证，接受 E、F，在 G 处给出修正 G*。下一轮从已确认的末位继续。

DSpark 保留块并行骨干，把每位置的 base logits 先算出来，再用一个轻量顺序头补充块内依赖。顺序阶段按位置从左到右采样，后一步读取前一步选中的 token。骨干仍只执行一次，但采样链具有真实的先后关系。因此总 draft 时间应包括 parallel forward、词表投影、顺序修正和采样。

代码 11　anchor 是否参与预测决定 draft query 的数量

这个 draft 侧的 k 与目标验证侧的k+1并不冲突：前者讨论草稿骨干输入布局，后者讨论目标如何一次计算 k 个候选及 bonus 的条件分布。anchor token 的来源、query position、sample position 和 logits 行号要分别标注，否则很容易让第一个草稿跳过一位或重复预测。

8　Markov 修正的矩阵与计算量

普通一阶 Markov 头只根据前一个 token 产生对各候选词分数的加性修正。令目标词表Vt、草稿词表Vd、低秩维度 r。W1∈ℝVt×r 是嵌入表，W2 的数学形状为 r×Vd；PyTorch Linear 实际权重存成[Vd,r]。取前一个 token 的 embedding e，再算eW2得到[Vd]偏置，与当前 base logits 相加。

ei = W1[di-1],    ℓi = Ui + eiW2,    qi = softmax(ℓi/τ)

d0是 anchor，Ui为并行骨干对第 i 位置的基础 logits；qi写成温度τ下的简单 softmax 形式，具体服务还可能应用词表映射等变换。W1W2在概念上定义 token 到 token 的转移矩阵，运行时只取实际上一 token 对应的一行，无需显式建立Vt×Vd 矩阵。

代码 13　目标词表 embedding 与草稿词表 projection 具有不同角色

markov_w1按 verifier token ID 索引，markov_w2输出 draft vocab。gated 变体再用 hidden 控制偏置，rnn 变体另建跨块内位置递推的状态；它们都不能用 vanilla 的一阶条件公式描述所有依赖。

代码 14　第 i 次采样结果成为下一次 Markov 条件

prev 从 anchor 开始；每轮算 embedding 与 bias，采样后写 out_tokens 并把 prev 改为结果。bias 是否与采样融合由 dtype 及模型接口等条件控制；融合避免部分中间流量，但不会消除位置之间的因果依赖。

取Vt=Vd=131072、r=256，两个低秩矩阵共67,108,864个参数，BF16为128 MiB。完整V×V矩阵则需要32 GiB。这里“低秩”降低了转移表规模，但128 MiB 仍是实在的权重；若词表更大、并发更高，逐位置投影和采样依然可能成为明显成本。

取R=128、k=8、Vd=131072，全部 base logits 的 BF16存储为256 MiB。单个 Markov 投影步的乘加计数为2RrVd，约8.59 GFLOP，八步约68.72 GFLOP，不含采样、base head 和通信。它比D=4096的全宽 head 投影轻很多，但串行8次造成的时延不能按一次大 GEMM 峰值直接换算。

DeepInfer 的 MarkovGPTHead 同样使用 Embedding(V,r)与 ReplicatedLinear(r,V)，而其 AcceptRatePredictor 为无 bias 的标量线性头。speculators 的 ConfidenceHead 使用默认带 bias 的 Linear。阅读 checkpoint 时要核对参数命名、形状和 bias。

代码 15　DeepInfer 的参数容器清楚给出 Markov 与 confidence 两类权重

两个 head 解决不同问题：Markov 权重改变实际草稿分布 q；confidence 权重估计验证价值。候选是否被接受由目标模型的验证结果决定。

取目标词表大小 8、草稿词表大小 6、秩 2。前一个 token 的目标词表编号只选出 W1 的一行，例如 (1,2)。若 W2 对两个草稿词的列分别为 (3,0) 和 (0,4)，它们的 logit 修正量便为 3 和 8。做一次完整修正需要与 6 列做短点积，无须显式构造 8×6 的稠密转移表。用于接受率计算的 q 必须来自修正并归一化后的实际抽样分布。

9　接受概率的监督与校准

speculators 为 DSpark 构造的 confidence 训练目标是在当前前缀下草稿分布与目标分布的重叠概率质量α=∑v∈Vmin{p(v),q(v)}。这是一个0到1的软标签，一次采样的结果则记作 1（接受）或 0（拒绝）。源码先在 no_grad 中计算1−TV，再对 confidence logits 做 binary cross entropy；训练只用这个标签监督预测器，不让标签自身沿该路径反向传播。

代码 16　从分布重叠得到 soft target，再训练 confidence logits

accept_rate 按位置计算；accept_prefix 对 block 内位置累乘。c_star 被 detach 后进入 BCEWithLogits，数值是软标签也合法。这个文件还分别记录 greedy EAL 与概率接受长度，说明两者评估口径有意分开。

Lconf = -αlogc-(1-α)log(1-c)

若输入特征为hi:[D]，且拼接前一个 token 的 Markov embedding ei:[r]，置信度头读入[D+r]并产生一个 logit，再经 sigmoid 成为ci。它只估计在该条件下接受的可能性，最终验证仍读取目标 logits。speculators 训练代码从已知训练 token 构造 prev_token_ids；服务时则读取刚采样的草稿，两个前缀分布可能有差异。

这种训练与服务差异会造成置信度失准。例如一个数据子集上c≈0.9，而真实条件接受率仅0.7；连续八步的估计生存率0.98≈0.4305，实际若均为0.7则为0.05765，相差约7.47倍。后缀预算会被高估。这里只用常数条件概率作示例，真实请求应按条件前缀和位置统计。

代码 17　DeepInfer 保留上一轮记录，并将逐位置 confidence 累乘成生存概率

1246–1250 行把逐位置的置信度转换为连续接受前缀的估计。第三个草稿词即使很可靠，也要在前两个都通过时才有机会被连续接受。

accept_rates 存储的是累计乘积，confidence_raw 存储原始逐位置值。两者在同一请求状态中并存；直接把 accept_rates 再 cumprod 一次会重复累乘，使后缀概率被压得过低。

校准应检查按位置、领域、温度、上下文长度与请求阶段分组后的预测与观察。只比较全局平均 c 和全局平均接受率，可能让前段过低、后段过高互相抵消。还要检查累计生存概率的误差，因为调度直接使用这组值。对停止或被截断的位置，不能把“没验证”一律当作拒绝，否则会引入删失偏差。

纠正分布由真实 p 和 q 决定，置信度误差通常先影响预算与性能。但如果调度读取了未来候选信息，正确性也可能受影响；下一节给出一个无需模型执行的反例。

将置信度落在 0.75～0.85 的候选分在一起。若平均预测 0.80，而在受同一采样规则验证、确实走到该位置的 1,000 次尝试中仅有 610 次通过，这个桶高估了约 0.19。还要检查样本选择是否偏向某类请求。分数即便能排对高低，也可能系统性高估，直接把它当概率会给深层候选分配过多预算。

10　验证预算的因果约束

构造只有 A、B 两个 token 的分布p=q=(12,12)。正常拒绝采样应永远接受候选，输出仍各占一半。现在引入一个有问题的调度规则：看到候选是 A 就安排验证并输出它；看到候选是 B 就跳过验证，改从目标重新抽一次。输出 A 的概率变成12+(12)×(12)=34。每个被执行的采样器都很“正确”，组合后的选择规则却改变了分布。

DSpark 的第 i 位置 confidence 使用当前骨干特征和前一个 token 信息，因此第i+1位置的 confidence 可能携带di的信息。若用整段最新 confidence 穷举最佳总长度，然后反过来决定是否验证di，就可能把这个信息带入选择事件。关键约束是：是否把当前位置纳入验证的决定，不能依赖该候选取值或未来候选造成的信号。

DSpark 论文讨论了决定是否验证当前候选时可使用哪些已知信息，并给出顺序 early-stopping 方法。本文工程部分以固定源码为准：DeepInfer 把总预算选择与每条请求分配拆成两组记录，配合异步计数选择不同轮次的置信度。

固定总预算之后，每条请求的生存分数沿位置不增。若选择全局最高的若干扩展，同一请求较早位置至少与较晚位置一样有资格进入，因而可以用连续前缀长度表示结果；确定性 tie 处理也必须保持这种性质。总预算的选择与各请求之间的额度分配对应两个不同的决策。它仍依赖置信度输入只包含允许的前缀信息，以及异步记录、索引和重置都正确。

在服务中验证采样分布时，还要跟踪每个候选依据的是哪一轮历史。模型特征是否提前混入未来 token、采样缓存是否对应实际 q、断流后是否复用旧状态，都会影响前述证明的适用条件。

在 p=q=(0.5,0.5) 时，若看到候选 A 就保留它，看到 B 则丢弃并从目标再抽一次，最终 A 的概率是 0.5+0.5×0.5=0.75。调度即使没有改拒绝采样公式，也通过选择哪些提案进入验证改变了输出。设计自适应预算时要写清决定发生的时刻及其可见信息，核查为当前候选计算的置信值是否暗含该候选的取值。

14　拒绝后的逻辑回退与物理分配

验证拒绝第三个候选后，后续 query 只能看见已接受前缀。先截短逻辑长度即可恢复可见范围；若整页中还保留有效前缀，就不能连这页一起归还。回退长度和回收物理页因此可能发生在不同位置。

继续用k=4、接受两个草稿的例子。起初已有 100 个确认的 token，目标已计算99个位置。目标 forward 处理位置99—103的[anchor,d1,d2,d3,d4]，物理上可能已写入五份 KV。接受d1、d2后，新增有效 KV 只有位置99—101，共3个；输出历史长度变为103，目标已计算长度变为102，位置102等待下一轮用纠正 token 重算。

验证四个草稿时，一次目标前向可投机写出多个位置的 KV；最终能留下的只有已接受前缀对应的旧输入。设用户已拿到第 10 个词、已有 KV 到第 9 个，前向输入第 10 个词和草稿，接受一个草稿后在下一位置发出纠正词。用户看到的长度变为 12，有效 KV 到位置 11。位置 12 的物理槽可能已经写过被拒绝的词，必须等纠正词真正经过目标模型才能成为有效历史。回滚时分别维护已交付长度、有效 KV 长度与分配的页数。

本例 query_len=5、num_rejected=2，所以 computed_delta=3。这个更新不表示最后纠正 token 已经计算了 KV，它与先前 anchor 的补算错开一个位置。

连续缓存可以让尾部无效 KV 留在原地址，后续覆写；分页缓存可能继续保留部分尾页，也可能回收整块。逻辑有效长度、页表引用、allocator 所有权与真实字节清零是不同操作。只要 attention mask、有效长度和后续写入都正确，无需每次拒绝都清零整段 HBM。跨请求复用或在途异步访问仍须遵守分配器的隔离与生命周期约束。

若page=16，初始有效99个位置占7页，验证到104个位置仍在第7页内；拒绝后有效102个位置也占7页。接受长度变化没有导致可释放的整页。另一个边界例子：原有效127个位置，尝试5个 query 跨到第9页，若只保留1个 query 则回到有效128、仅需8页；是否立即归还第9页取决于预留和在途使用。显存收益需要按页边界计算。

草稿模型还可能有自己的 KV 和 stable hidden，grammar 有状态机，penalty 有 token 计数；这些状态都只能提交被接受的历史。循环注意力或 SSM 状态通常无法靠减去序列长度恢复，因为错误候选已经改变了同一块递推状态；需要保留检查点、逐步中间状态或从最近有效位置重放，具体方案由模型后端提供。因此，对第十二课中的递归模型，还须确认后端能否把递推状态恢复到最后一个有效位置。

输出层也要截断：若已接受前缀含 EOS，后续已采样 token 不能继续发送。取消后到达的异步结果必须按请求生命周期丢弃，但其设备写入仍要结束后才能安全复用相关缓冲。业务结束与设备完成的区别，在投机路径同样存在。

目标已为候选输入 C 计算出一行 K/V，后来验证却选中了纠正 token D。在该位置上，C 与 D 的 embedding 不同，因而不能把 C 已写入的槽解释为 D 的状态。提交 D 后可将它作为下一轮输入，由目标模型计算该词的 K/V，再推进有效缓存边界。若被否决的槽与保留前缀共用一页，只需先截断逻辑长度，是否回收物理页由分配器决定。

16　张量并行中的词表与请求分片

TP 通常把词表 projection 按词表维度分片，每个 rank 只产出部分词表的候选分数。顺序 Markov 采样若在每个 rank 重复执行全词表处理，会浪费计算与显存；若每一步都跨 rank 收集或归约，也会增加串行通信。vLLM 的 DSpark 路径提供一种转换：先把词表分片重排成按请求归属分片，让每个 owner 持有其请求的全词表行，再本地完成顺序链。

代码 29　按 request mod TP 分配 owner，并 all-to-all 重排 logits

每个 rank 的槽位容量为 ⌈R/TP⌉，其中 TP 为张量并行度，rank r 拥有 r、r+TP等请求。send_rows 按 owner 顺序挑 hidden；all_to_all_vocab_shards 让 owner 拿到完整词表。尾部 padding 槽位借用请求0行用于维持形状，这些填充行的结果不写回任何有效请求。

例如R=5、TP=2，则 rank0拥有请求[0,2,4]，rank1拥有[1,3,pad]。owner 顺序收集后的 token 序列为[0,2,4,1,3,pad]；恢复原 batch 时用索引[0,3,1,4,2]。每个有效请求只属于一个采样 owner，但每个 rank 在词表 projection 阶段仍承担所有请求的本地词表分片。

顺序链完成后，再 all-gather 草稿 token 及需要的置信度，恢复原请求顺序。小 token 数组通信与大 logits 重排的字节规模不同；一次 all-to-all 是否划算，取决于词表、batch、TP 拓扑和原路径重复工作的成本。

该提交在模型不支持局部词表计算、草稿 top-k 模式不兼容、在线 acceptance estimator 需要完整请求 logits 或缺少通信能力等情况下保留其他路径。融合 Markov bias、reduced vocab 与模型自定义采样核也有独立条件。部署报告必须写明实际启用分支，避免用存在于仓库中的优化代表一次运行已使用它。

CUDA Graph 覆盖草稿骨干与顺序采样时，动态内容通过固定缓冲更新，捕获形状依赖请求数和草稿上限。无效 padding 不能写入真实请求的 draft cache。TP 一致预算、owner 映射、capture 形状和有效 mask 共同决定 replay 是否正确。

两个 TP rank、两个请求 A 和 B 时，投影之后每个 rank 都有 A、B 的半个词表。若改为 rank 0 完整处理 A、rank 1 完整处理 B，则 rank 0 需收到 A 的另一半，rank 1 需收到 B 的另一半。各 rank 保留本地对应片段并发送对方需要的片段，得到完整行后才可按完整词表执行依赖归一化的采样。最终选出的 token 还要送回所有后续需要它的参与者。

这个式子假设比较同一稳定阶段、每轮串行发生草稿和验证、基线平均每 token 耗时Tbase，并忽略长度截断和跨轮重叠。分母要包含草稿骨干、head 与采样、目标验证、KV/元数据管理及必要同步。若实现有异步重叠，应改为依赖图关键路径；已经被覆盖的时间不能再完整相加。

教学设基线10毫秒/token，k=4且条件接受率均0.8，E[N]=3.3616。草稿3毫秒、验证14毫秒、其他1毫秒，共18毫秒，估计加速约1.868倍，平均每交付 token 约5.35毫秒。若接受率降为0.3而成本不变，加速仅0.792倍，平均12.63毫秒/token，较基线变慢。

增加并发后，普通 decode 已经能把多个请求合并为利用率较高的矩阵乘。投机路径额外乘上验证行数，可能挤占新请求准入，扩大 MoE 专家负载或 KV 读带宽；此前小 batch 下能摊薄的权重成本已被正常 batch 摊薄。长上下文还会让每个新增 query 读取更多历史，验证的边际成本随 attention 结构改变。

用户看到的输出节奏也不同。若每18毫秒一次返回约3个 token，平均 token 速率提高，但网络 chunk 之间仍有18毫秒空隙。客户端把 chunk 内 token 均匀播放可以改善视觉节奏，却不能改变模型真正完成的时刻。评估同时报告每轮交付、chunk 间隔、token 口径 TPOT 和延迟分位数，沿用第十三课的计时边界。

吞吐测试应保持相同模型、采样参数、输入/输出长度分布和 SLO，并报告每 GPU 秒交付的有效token 或满足约束的请求数。将草稿、被拒绝候选和 padding 全部计为输出吞吐，会夸大收益。单请求加速、固定并发吞吐和固定到达率 goodput 回答不同问题，不能用其中一个数字替代另外两个。

基线每个有效输出耗时 2 ms。若投机一轮平均交付 2.8 个有效 token，而草稿、验证、采样和状态更新合计 6 ms，则每个有效输出约耗 2.14 ms，反而慢于基线；把同样的总耗时降到 4 ms 才有 1.4 倍加速。两组试验应使用相同请求组合、目标采样规则和终止条件，并分别看用户间隔、有效吞吐以及每 GPU 秒的产出。

一种连续随机分布。给对数概率加独立 Gumbel 噪声再取最大值，可以实现分类采样。
HBM
GPU 常用的高带宽显存，用于保存权重、激活和中间结果等数据。芯片与显存之间可持续传输的字节数会限制某些算子。
KiB
二进制容量单位，1 KiB 等于 1,024 字节。
KV
键和值的合称。一个历史位置通常既提供参与匹配的键，也提供按注意力权重汇总的值。
logits
模型为词表中各个候选 token 输出的未归一化分数；经过 softmax 可得到概率。不同词表的同一数字编号不必指向同一 token。
Markov
马尔可夫假设，下一状态的分布在给定当前状态后无需更早历史。它只对模型明确选取的状态成立。
MiB
二进制容量单位，1 MiB 等于 1,048,576 字节或 1,024 KiB。
MLA
多头潜在注意力。模型把历史内容压到低维潜向量，后续计算按模型规定从该向量获得各头所需的信息。
MoE
混合专家模型。路由器给每个词元挑选少数几个专家，由选中的网络计算，再按路由权重合并结果。
MTP
多词元预测，训练时还预测后续若干位置。用它加速推理时还需要独立的验证、接受及缓存处理流程。
OOM
内存不足导致分配失败。本节需要进一步定位失败发生在哪一次收集、缓冲申请或优化器更新。
prefill
推理时处理已有提示词的阶段。模型可以同时计算多个输入位置，并留下后续生成要读的缓存。
query
注意力中发起查询的位置或它的向量。它与各个可见位置的键相乘，得到对应的一行分数。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
RMSNorm
按一个向量各分量的均方根进行归一化，再施加学习到的尺度。它不需要先减去向量均值。
SLO
服务等级目标，例如规定一定比例的请求要在给定的首词时延内完成。计算有效吞吐量时要写明采用哪项目标。
softmax
把一行分数先取指数，再各自除以这一行的指数和，得到总和为一的权重。实作时可先减去行最大值以免指数溢出。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
TPOT
Time Per Output Token，常用于表示首个输出之后平均每个词元的耗时。应注明是否排除首词以及使用了多少个生成间隔。
Transformer
用注意力混合不同位置的信息，再逐位置通过前馈网络。一个解码器通常把多层这样的计算依次连接起来。
信号
收发双方约定的完成标记。生产者更新标记前，要把标记与相应代的数据写入建立正确顺序。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
准入
调度器确认有可用资源并允许请求开始执行。准入前的等待属于排队时间。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
参数量
不同权重元素的总数；同一参数被多行、多次使用不会因此重复计数。
图桶
为某组预定输入容量和形状捕获的图，真实请求可以只占部分槽位。
图重放
重复提交一个已有的设备工作图，同一静态输入地址中的内容可在各轮改变。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
局部行号
某行相对于本请求在扁平缓冲起点的偏移，与请求的长期状态槽位是两套坐标。
工作区
算子在执行过程中为暂存中间数据而申请的区域。模型权重大小不变时，工作区仍可能随输入或算法改变。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
投影
此处指注意力与前馈层内的稠密矩阵乘。它按实际输入 token 行数重复执行，同一份权重可被多行共享。
拒绝采样
按目标与草稿概率之比决定是否接受所提 token，拒绝后按纠正分布另取一个输出。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
有效交付数
本轮真正追加到请求输出序列的 token 数，须去掉被拒候选和终止条件之后的结果。
有效吞吐
单位时间向请求提交的有效输出 token 数，草稿生成和作废位置不计入分子。
有效载荷
接收端实际要恢复的 K/V 字节，包头、填充及重复发送可另外增加链路流量。
未归一化
保留各项加权和，同时单独记录权重之和；除以对应分母后才是可直接输出的加权平均。
校准
预测概率与同类样本中的实际通过频率是否相符，判断时须控制位置及样本是否曾被验证。
概率比
当前策略与参考旧策略对同一已选动作所赋概率的比值。不能取不同 token 或不同前缀的概率相除。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
目标模型
推测解码中定义最终生成分布的模型。它一次验证多个候选位置，并在需要时提供纠正词元的分布。
纠正分布
候选被拒后，将目标概率超过草稿概率的正差归一化所得的分布。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
草稿模型
推测解码中先提出若干候选词元的模型或预测头。目标模型逐位置验证这些候选，只有符合接受规则的前缀可以直接交给用户。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
计时边界
明确一个耗时由哪两个事件的时间戳相减得到，跨主机相减前还须核对时钟关系。
词表
记录 token 与整数编号对应关系的表。词嵌入矩阵使用同一套编号查行，每行才是模型参与运算的向量。
词表分片
把分类输出的词表轴分给不同 rank，每个 rank 只算一段 token ID 的 logits。计算全局归一化或抽样时仍须协调。
词表分片
每个 rank 只计算词表中的一部分候选分数。依赖全词表的采样操作需要相应通信。
语法状态
表示当前已生成前缀在约束语法中走到了哪里，用来决定下一步允许哪些候选。
请求轨迹
按同一个请求编号整理的排队、批次映射、计算、采样及缓存状态变化。
调用链
一次注意力请求从上层接口，经编译与后端选择，到 GPU 内核执行所经过的路径。
边际交付
多分配一个草稿验证位置可增加的期望输出量，取决于前面各位置能否连续通过。
连续接受长度
从第一个草稿开始连续验证通过的数量，第一次拒绝之后的候选不会计入这段前缀。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
页表
把逻辑位置所在的页映射到实际存储块的结构。在 KV 分页中，连续的逻辑位置未必位于连续的物理页。
顺序头
先产生前一候选，再按它修正后一位置的分布，使候选之间保留条件依赖。
验证预算
本轮可分给草稿验证的查询行数，还要受临时缓冲、延迟目标和其他请求占用约束。
