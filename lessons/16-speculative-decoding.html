1　推测解码的草稿、验证与连续前缀

大模型通常每跑一轮才交付一个新词。推测解码让开销较小的模型先写一截草稿，大模型一轮检查多个位置。草稿开头连续猜对几个，就有机会一次交付几个词。先看每次都选最高分词的情形。小模型提前猜三个词 A、B、C，大模型用已有前缀和这串草稿一次算出各位置的分数。若它在第一个位置也选 A，在接着 A 的位置却选 X，本轮便交付 A、X，下一轮从这个新前缀继续。草稿 C 的分数是接着 A、B 算的，不能接到 A、X 后面。随机采样时用下一节的概率规则来判定接受与纠正。

设服务正在生成一段长回答，目标模型每次 decode 需要读入大量权重和历史 KV，小 batch 下新增一个 token 的计算未必用满设备。推测解码先让便宜的草稿器提出 k 个候选，再把它们作为已知输入交给目标模型批量计算条件分布。目标模型依然决定最终输出；草稿器决定这次尝试能否把一次昂贵迭代换成更多有效进展。

沿刚才的例子，区分本轮送进去的词和本轮预测出来的词。已有长度为 t 的已确定历史x1,…,xt，其中xt是上一轮刚采样的 anchor，目标 KV 只算到xt−1。草稿器给出d1,…,dk。目标本轮输入[xt,d1,…,dk]，共k+1个 query 位置；对应 logits 行分别预测d1、d2、…、dk以及全接受后的下一个 token。

下式中，i 是从 1 开始的草稿位置，v 是这个位置的一种候选词。两边都以已经确定的历史和它后面前 i 减 1 个草稿词为条件。p 是目标模型给 v 的概率，q 是草稿模型给同一个 v 的概率，下标 T、D 分别指目标模型和草稿模型。

pi(v) = PT(v|x1:t,d1:i-1),    qi(v) = PD(v|x1:t,d1:i-1)

目标模型可以在一次前向中计算这些验证行，因为候选 token 已经给定，causal attention 沿候选历史计算。它没有预先知道最终会接受几行。若d1、d2接受而d3拒绝，p4依赖被拒绝的d3，这一行不能继续接到纠正后的历史。普通逐位置验证只保留连续接受前缀，在第一个拒绝点采样纠正 token，然后结束本轮。

2　接受概率与拒绝后的纠正分布

先读图里只有 A、B 的例子。设同一段前文下，草稿模型把 A 的概率定为 0.75，目标模型只给 0.25。可以把概率想成大量重复抽样后各个词所占的份额。抽到 A 时只让三分之一通过，直接交付 A 的份额就降到了 0.25。草稿提出 B 的份额原本只有 0.25，把这些全部接受，再把拒绝 A 的 0.50 补给 B，恰好得到目标的 0.75。

先看一个位置，以下概率都以相同的已确认前缀为条件。目标分布为 p，实际抽取候选的草稿分布为 q。抽到候选 v 后，以a(v)=min{1,p(v)/q(v)}接受；q(v)=0的位置不会由草稿抽到，因此无需在该事件上做除法。被接受并输出 v 的无条件概率为q(v)a(v)=min{p(v),q(v)}。目标还缺的质量正是p(v)−min(p(v),q(v))。

令 v 是本次由草稿分布 q 抽到的词，p 是同一前缀下的目标分布。a(v) 为条件接受率。求和下标 u 遍历词表；Z 是目标分布仍待补给的概率质量，也等于总体拒绝概率。拒绝后从剩余质量归一化得到的分布 r 抽样。当两分布完全相同时，Z 为零，所有草稿都接受，无需计算 r。

a(v) = min(1,p(v)q(v)),    Z = ∑umax(p(u)-q(u),0)

r(v) = max(p(v)-q(v),0)Z

P(Y = v) = min(p(v),q(v)) + Zr(v) = p(v)

式中 Y 是这一轮最终交付的词。得到它有两条路，一条是草稿抽中它并通过验证，另一条是本轮先发生拒绝，再从纠正分布中抽中它。两条路互不重合，所以把它们的概率直接相加，结果就是目标给这个词的概率。

要从逐词接受概率求整次接受率，只须把重叠的概率质量沿词表相加。对每个词都有 min(p,q)=(p+q−|p−q|)/2；两份分布分别加到 1，于是多出来的绝对差恰好以一半的系数扣除。

α = ∑vmin(p(v),q(v)) = 1-12∑v|p(v)-q(v)|

α是分布重叠面积，也就是1减去 total variation 距离。它衡量这一历史条件下普通拒绝采样的期望接受率。单个被抽中的 token 的 a(v)、整个位置的α、实际连续接受长度，是三个不同统计量。即使两边概率最高的是同一个词，其余概率质量的分配仍会改变期望接受率。

逐位置重复上述等式，并要求每一步使用当前有效历史对应的 p 和 q，才能推出整段生成遵循目标的自回归联合分布。数学结论依赖相同的目标采样规则、正确的候选条件及非预知的调度决策；浮点近似和不同 kernel 归约仍可能改变细节。分布保持也不要求固定 seed 下与逐 token 基线逐字相同。

7　DSpark 的并行草稿骨干与顺序预测头

DSpark 是一种推测解码的草稿模型。它先把后面几个词的位置放在一起，用一次较重的模型计算为每个位置准备特征。随后用一个较小的预测头，从左往右逐个选词。这样，前一个词的选择可以影响后一个词，同时整套草稿骨干只运行一遍。

纯块并行草稿在一次草稿主干前向中产生多个未来位置的 logits，避免为每个候选重复执行整套草稿 Transformer。但多个位置若独立采样，会把不同语言分支的片段拼在一起。例子是第一位置可以选“of”或“no”，第二位置分别适合“course”或“problem”；若两个位置独立选择，就可能把一个分支里的“of”和另一个分支里的“problem”拼在一起。

依图中编号读。① 目标模型从 A、B、C 生成锚点 D。② 并行骨干一次准备多个位置，顺序头给出 E、F、G、H 及各自置信度；调度器留下连续前缀 E、F、G，去掉 H。③ 目标模型并行验证，接受 E、F，在 G 处给出修正 G*。下一轮从已确认的末位继续。

DSpark 保留块并行骨干，把每位置的 base logits 先算出来，再用一个轻量顺序头补充块内依赖。顺序阶段按位置从左到右采样，后一步读取前一步选中的 token。骨干仍只执行一次，但采样链具有真实的先后关系。因此总 draft 时间应包括 parallel forward、词表投影、顺序修正和采样。

8　前一词元对草稿分数的低秩修正

草稿模型已经给每个候选词打了分。上一词也能提供线索，例如某个词后面经常接特定的下一个词。如果把每一种前后搭配的分数都存下来，表会很大。这里给每个前词只存一小行数，由这行数算出各候选应加多少分。普通一阶 Markov 头只根据前一个 token 产生对各候选词分数的加性修正。令目标词表Vt、草稿词表Vd、低秩维度 r。W1∈ℝVt×r 是嵌入表，W2 的数学形状为 r×Vd；PyTorch Linear 实际权重存成[Vd,r]。取前一个 token 的 embedding e，再算eW2得到[Vd]偏置，与当前 base logits 相加。

先只取两个草稿词 A、B，查上一个词在第一张表中的那一行，得到 (1,2)。第二张表的两列分别是 (3,0)、(0,4)。第一行与两列分别做点积，修正量就是 3 和 8。假设骨干给 A、B 的基础分为 4 和 0，加完后分数变为 7 和 8，B 排到 A 前面。若以温度 1 抽样，B 的概率约为 0.731。上一词只需查表一次，所有候选都能各算出一个偏置。

把原词元位置记为 i，上一个词的编号记为 d 的第 i 减 1 项。下面按顺序写出查表得到的向量 e、加上修正的分数 ℓ 和归一化后的草稿概率 q。小例中向量有 2 个通道，算出的分数和概率也各有 2 项。

ei = W1[di-1],    ℓi = Ui + eiW2,    qi = softmax(ℓi/τ)

d0是 anchor，Ui为并行骨干对第 i 位置的基础 logits；qi写成温度τ下的简单 softmax 形式，具体服务还可能应用词表映射等变换。W1W2在概念上定义 token 到 token 的转移矩阵，运行时只取实际上一 token 对应的一行，无需显式建立Vt×Vd 矩阵。

9　接受概率的监督与校准

想决定是否多猜一个词，可以先估计这次猜测有多大机会通过。若标成 0.8 的一批候选长期只有一半通过，调度器就会把太多验证位置留给它们。把预测概率和相同条件下的实际通过比例对齐，叫置信度校准。

speculators 为 DSpark 构造的 confidence 训练目标是在当前前缀下草稿分布与目标分布的重叠概率质量α=∑v∈Vmin{p(v),q(v)}。这是一个0到1的软标签，一次采样的结果则记作 1（接受）或 0（拒绝）。源码先在 no_grad 中计算1−TV，再对 confidence logits 做 binary cross entropy；训练只用这个标签监督预测器，不让标签自身沿该路径反向传播。

问题　分别列出本轮新增的用户可见词及其位置、目标 KV 可继续复用的末位置、下一轮应送入目标模型的 token。已为 d3 和 d4 计算过的 KV 能否保留成合法历史？区分“物理槽仍在”与“有效长度”。

答案

结论　本轮交付 d1@101、d2@102、c@103。有效 KV 的最后位置为 102，下轮输入 c@103；旧草稿尾部的物理存储可仍分配，但不能作为有效前缀。

推导　本轮补算了旧词 100，以及最终确实接纳的 d1、d2。d3 的状态使用被拒的 token，位置虽与 c 一致、内容不同。d4 的上文还包含 d3，所以同样失效。
回退时更新可见长度和有效 KV 边界，后续重写对应槽位前还要满足页与设备访问的生存期约定。

15　草稿长度与临时显存

若 16 个请求各有 4 个草稿，目标每条请求需 5 行 logits。词表大小 32,768、每项 4 字节时，每行是 128 KiB，总共 80 行，即 10 MiB。若实际打包后仅有 42 行，紧凑表示只需 5.25 MiB；按最大图桶预分配的缓冲可能仍保留 10 MiB。显存核算应分别报告本轮有效元素和 allocator 实际保留的容量。

先数有几行，再乘一行的字节数。下式假设目标与草稿词表等大。R 为请求数，k 为每条请求草稿数，V 为词表大小，bT、bD分别是相关缓存的每元素字节数。若变长，应把R(k+1)替换成实际总 logits 行数。这个式子只计算指定 buffer，不包含模型权重、基础 hidden、top-k 工作区、padding 和其他副本。

Mtarget logits = R(k + 1)V bT,    Mdraft logits = RkV bD

R=256、k=8、V=131072时，目标 processed logits 若为 FP32，需要1.125 GiB；草稿完整 logits 若按 BF16保存，需要512 MiB。目标原始 logits 与处理后的 FP32副本可能同时存活，估算峰值时要把两份同时存活的缓冲都计入。使用 reduced draft vocab、词表分片或分块采样能改变临时缓冲区的容量需求，但验证仍需在一致的 token ID 空间解释 q。

代码 28　FP32 词表分块与完整请求边界

常量 MAX_CHUNK_BYTES 为230 字节，即 1 GiB。V=131072时最多2048个 FP32行；迭代器把完整请求的行放入同一分块，至少包含一个请求，因此单个超大请求可能超过名义块上限。1 GiB 是该临时缓冲区的分块目标。统计整步显存峰值时还要计入同时存活的其他张量。

前例每条请求9行，2048行预算可装227条请求，共2043行；剩余29条请求共261行形成第二块。该切块发生在验证与采样处理路径，目标前向产生的 logits、隐藏状态和 KV 仍按各自的生命周期释放。分析 OOM 时应沿每个 buffer 的分配与生命周期定位。

普通 GQA 中，一条请求新增 k 个尚未最终确定的候选位置，KV 有效载荷上界约为 2LkGdp 字节。取L=32、G=8、d=128、BF16、k=8，每条请求额外候选 KV 为1 MiB，256请求合计256 MiB；另有 anchor 的正常补算、页对齐与草稿自身缓存。MLA、跨层共享或混合状态模型应使用各自实际记录大小。

更长草稿扩大模型每轮 query、logits 和临时状态，也增加拒绝后的无效工作。即使所有草稿都已生成，自适应验证缩短目标前缀仍能省目标计算；但无法追溯收回已付出的草稿骨干与采样时间。因此“只验证更短”与“根本少生成草稿”应分别计量。

16　张量并行中的词表与请求分片

TP 通常把词表 projection 按词表维度分片，每个 rank 只产出部分词表的候选分数。顺序 Markov 采样若在每个 rank 重复执行全词表处理，会浪费计算与显存；若每一步都跨 rank 收集或归约，也会增加串行通信。vLLM 的 DSpark 路径提供一种转换：先把词表分片重排成按请求归属分片，让每个 owner 持有其请求的全词表行，再本地完成顺序链。

先取词表只有四项的教学例子，rank 0 保存词 0、1 的分数，rank 1 保存词 2、3 的分数。若批内有 A、B 两条请求，投影之后每个 rank 都有 A、B 的半个词表。若改为 rank 0 完整处理 A、rank 1 完整处理 B，则 rank 0 需收到 A 的另一半，rank 1 需收到 B 的另一半。各 rank 保留本地对应片段并发送对方需要的片段，得到完整行后才可按完整词表执行依赖归一化的采样。最终选出的 token 还要送回所有后续需要它的参与者。

代码 29　张量并行中的请求归属与词表分数交换

每个 rank 的槽位容量为 ⌈R/TP⌉，其中 TP 为张量并行度，rank r 拥有 r、r+TP等请求。send_rows 按 owner 顺序挑 hidden；all_to_all_vocab_shards 让 owner 拿到完整词表。尾部 padding 槽位借用请求0行用于维持形状，这些填充行的结果不写回任何有效请求。

再按代码算一次较大的批次。5 条请求分到两卡，每卡容量向上取整为 3。按编号除以 2 的余数分配，卡 0 负责 [0,2,4]，卡 1 负责 [1,3,填充]。两卡各自产出的草稿编号这样排好以后，请求 1 在拼接数组的第 3 项，请求 2 在第 1 项。用 [0,3,1,4,2] 逐项取回结果，就恢复了原来的请求顺序。

顺序链完成后，再 all-gather 草稿 token 及需要的置信度，恢复原请求顺序。小 token 数组通信与大 logits 重排的字节规模不同；一次 all-to-all 是否划算，取决于词表、batch、TP 拓扑和原路径重复工作的成本。

该提交在模型不支持局部词表计算、草稿 top-k 模式不兼容、在线 acceptance estimator 需要完整请求 logits 或缺少通信能力等情况下保留其他路径。融合 Markov bias、reduced vocab 与模型自定义采样核也有独立条件。部署报告必须写明实际启用分支，避免用存在于仓库中的优化代表一次运行已使用它。

CUDA Graph 覆盖草稿骨干与顺序采样时，动态内容通过固定缓冲更新，捕获形状依赖请求数和草稿上限。无效 padding 不能写入真实请求的 draft cache。TP 一致预算、owner 映射、capture 形状和有效 mask 共同决定 replay 是否正确。

17　接受率与端到端加速比

要比较相同数量的有效输出。假设推测解码平均每轮交付的词数为 E[N]。普通解码每出一个词用一份基线时间，交付这么多词所用的时间就是两者相乘。再除以推测解码一轮的实际墙钟耗时，就得到下式的加速比。

Slatency ≈ E[N] TbaseTdraft + Tverify + Tother

这个式子假设比较同一稳定阶段、每轮串行发生草稿和验证、基线平均每 token 耗时Tbase，并忽略长度截断和跨轮重叠。分母要包含草稿骨干、head 与采样、目标验证、KV/元数据管理及必要同步。若实现有异步重叠，应改为依赖图关键路径；已经被覆盖的时间不能再完整相加。

教学设基线10毫秒/token，k=4且条件接受率均0.8，E[N]=3.3616。草稿3毫秒、验证14毫秒、其他1毫秒，共18毫秒，普通解码交付同样多的词需约 33.616 毫秒，除以 18 毫秒，估计加速约 1.868 倍，平均每交付 token 约5.35毫秒。若接受率降为0.3而成本不变，加速仅0.792倍，平均12.63毫秒/token，较基线变慢。

增加并发后，普通 decode 已经能把多个请求合并为利用率较高的矩阵乘。投机路径额外乘上验证行数，可能挤占新请求准入，扩大 MoE 专家负载或 KV 读带宽；此前小 batch 下能摊薄的权重成本已被正常 batch 摊薄。长上下文还会让每个新增 query 读取更多历史，验证的边际成本随 attention 结构改变。

用户看到的输出节奏也不同。若每18毫秒一次返回约3个 token，平均 token 速率提高，但网络 chunk 之间仍有18毫秒空隙。客户端把 chunk 内 token 均匀播放可以改善视觉节奏，却不能改变模型真正完成的时刻。评估同时报告每轮交付、chunk 间隔、token 口径 TPOT 和延迟分位数，沿用第十三课「推理服务指标与 KV 分页」中的客户端计时边界。

吞吐测试应保持相同模型、采样参数、输入/输出长度分布和 SLO，并报告每 GPU 秒交付的有效token 或满足约束的请求数。将草稿、被拒绝候选和 padding 全部计为输出吞吐，会夸大收益。单请求加速、固定并发吞吐和固定到达率 goodput 回答不同问题，不能用其中一个数字替代另外两个。

普通题 05草稿器加速后的有效吞吐

情境　同一份请求轨迹在一个不重叠的轮序列上比较两版服务，采样参数相同。从本轮输入就绪到下一轮可以开始的墙钟已包含起草、验证、纠正和等待。旧版平均 10 ms 交付 2 个有效词，新版平均 9 ms 交付 1.5 个。两版均用完整窗口的总交付词数除以总墙钟比较。

问题　将两组数据换为 token/s，再求新版在 每轮耗时 9 ms 下至少需平均交付多少词才持平。为了判定下降来自接受长度还是计时边界改变，分别列出要记录的词数和时间事件。

答案

结论　旧版 200 token/s，新版约 166.7 token/s。9 ms 内平均至少交付 1.8 个词才能与旧版持平。

推导　把 ms 换为秒，得 20.010 和 1.50.009。打平条件为 x0.009=200，解得 x=1.8。

18　解码数值校验与对照实验

若关闭推测解码时输出正常，一开启就在拒绝后出现重复词，先固定一个前缀和一份草稿。让目标模型对相同前缀分别运行一次并行验证和逐词前向。比较第一处分歧的位置，就能区分偏差来自计算目标分数、接受判断，还是回退后的状态。

情景面试题 01高接受率下的采样偏差检验

情境　固定一个前缀，目标采样先调温度再做 top-p。启用草稿验证后总体接受率仍高，但反复独立生成首个词，某个目标分布非零的低频词出现偏少。可在小词表上枚举所有候选，并取得变换后的目标概率和实际起草用概率。

问题　请把检查分成实际分布、直接接受的概率质量，以及拒绝后重新采样补足的概率质量三步。要保存哪些向量，哪种偏差分别指向截断顺序错误、验证器用错 q 和纠正分支错误？怎样避免一次固定随机种子的差异被误判为分布不正确？

答案

结论　用同一前缀重建最终 p 和实际采样的 q，然后逐词检查直接接受 min(p,q)、剩余质量 (p−q) 的正部及其归一化；最后按两条路径相加与 p 比较。

推导　若 p 与目标独立采样的处理后分布已不同，先查温度、掩码、top-p、归一顺序。若 p 正确而直接接受质量偏离，记录实际 q 及接受概率，特别检查筛选或 logits 行错位。
若直接部分正确但最终缺某些词，则检查拒绝概率、正部与重采样归一。枚举能在小例子上排除抽样波动；大样本再用多次独立抽样和误差区间复核。逐项启用批处理、图重放、缓存，定位引入偏差的环节。

按一个向量各分量的均方根进行归一化，再施加学习到的尺度。它不需要先减去向量均值。
SLO
服务等级目标，例如规定一定比例的请求要在给定的首词时延内完成。计算有效吞吐量时要写明采用哪项目标。
softmax
把一行分数先取指数，再各自除以这一行的指数和，得到总和为一的权重。实作时可先减去行最大值以免指数溢出。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
TPOT
Time Per Output Token，常用于表示首个输出之后平均每个词元的耗时。应注明是否排除首词以及使用了多少个生成间隔。
Transformer
用注意力混合不同位置的信息，再逐位置通过前馈网络。一个解码器通常把多层这样的计算依次连接起来。
信号
收发双方约定的完成标记。生产者更新标记前，要把标记与相应代的数据写入建立正确顺序。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
准入
调度器确认有可用资源并允许请求开始执行。准入前的等待属于排队时间。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
参数量
不同权重元素的总数；同一参数被多行、多次使用不会因此重复计数。
图桶
为某组预定输入容量和形状捕获的图，真实请求可以只占部分槽位。
图重放
重复提交一个已有的设备工作图，同一静态输入地址中的内容可在各轮改变。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
局部行号
某行相对于本请求在扁平缓冲起点的偏移，与请求的长期状态槽位是两套坐标。
工作区
算子在执行过程中为暂存中间数据而申请的区域。模型权重大小不变时，工作区仍可能随输入或算法改变。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
投影
此处指注意力与前馈层内的稠密矩阵乘。它按实际输入 token 行数重复执行，同一份权重可被多行共享。
拒绝采样
按目标与草稿概率之比决定是否接受所提 token，拒绝后按纠正分布另取一个输出。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
有效交付数
本轮真正追加到请求输出序列的 token 数，须去掉被拒候选和终止条件之后的结果。
有效吞吐
单位时间向请求提交的有效输出 token 数，草稿生成和作废位置不计入分子。
有效载荷
接收端实际要恢复的 K/V 字节，包头、填充及重复发送可另外增加链路流量。
未归一化
保留各项加权和，同时单独记录权重之和；除以对应分母后才是可直接输出的加权平均。
校准
预测概率与同类样本中的实际通过频率是否相符，判断时须控制位置及样本是否曾被验证。
概率比
当前策略与参考旧策略对同一已选动作所赋概率的比值。不能取不同 token 或不同前缀的概率相除。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
目标模型
推测解码中定义最终生成分布的模型。它一次验证多个候选位置，并在需要时提供纠正词元的分布。
纠正分布
候选被拒后，将目标概率超过草稿概率的正差归一化所得的分布。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
草稿模型
推测解码中先提出若干候选词元的模型或预测头。目标模型逐位置验证这些候选，只有符合接受规则的前缀可以直接交给用户。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
计时边界
明确一个耗时由哪两个事件的时间戳相减得到，跨主机相减前还须核对时钟关系。
词表
记录 token 与整数编号对应关系的表。词嵌入矩阵使用同一套编号查行，每行才是模型参与运算的向量。
词表分片
把分类输出的词表轴分给不同 rank，每个 rank 只算一段 token ID 的 logits。计算全局归一化或抽样时仍须协调。
词表分片
每个 rank 只计算词表中的一部分候选分数。依赖全词表的采样操作需要相应通信。
语法状态
表示当前已生成前缀在约束语法中走到了哪里，用来决定下一步允许哪些候选。
请求轨迹
按同一个请求编号整理的排队、批次映射、计算、采样及缓存状态变化。
调用链
一次注意力请求从上层接口，经编译与后端选择，到 GPU 内核执行所经过的路径。
边际交付
多分配一个草稿验证位置可增加的期望输出量，取决于前面各位置能否连续通过。
连续接受长度
从第一个草稿开始连续验证通过的数量，第一次拒绝之后的候选不会计入这段前缀。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
页表
把逻辑位置所在的页映射到实际存储块的结构。在 KV 分页中，连续的逻辑位置未必位于连续的物理页。
顺序头
先产生前一候选，再按它修正后一位置的分布，使候选之间保留条件依赖。
验证预算
本轮可分给草稿验证的查询行数，还要受临时缓冲、延迟目标和其他请求占用约束。
