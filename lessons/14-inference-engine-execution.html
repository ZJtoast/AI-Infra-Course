1　生成引擎的单步执行

生成引擎在每一轮做三个决定：选哪些请求，给每个请求算哪些位置，把结果写回谁的记录。只有请求 A 时，刚选出一个词，下一轮就把它送回来。加入请求 B 后，两个请求可以合用一次矩阵乘，各自的历史和输出仍得分开。引擎保留的槽位用来认出“这是哪个请求”，批内行号只描述“这一次排在哪里”。

跟着 A、B 走一轮。A 已经有了上一步生成的 token，这次只需把它作为一行输入。B 的提示开头已有缓存，调度器可以让它只算剩下的几行。模型执行器按计划把这些行排在一起，交给 GPU。等结果回来，A 的输出归 A；B 若算到了提示末尾，也能拿到自己的第一个输出 token。

代码 1　调度、执行与采样在源码中有独立接口

scheduler_output 是本轮计划。execute_model 以 non_block=True 发起执行，返回 future（716 行）；采样可能通过独立 sample_tokens 入口完成。返回 None 时，沿后续的采样分支查找本轮 token。

有些请求规定输出必须符合一种格式，例如 JSON。采样前，引擎用一张掩码标出按当前已生成内容允许接在后面的 token，选词时只考虑这些候选。CPU 可以趁模型前向计算时准备掩码，采样要等分数和这张掩码都就绪。

若 A 的用户在 GPU 计算期间取消请求，本轮返回后，core.py 第 726–731 行先处理执行期间到达的 abort，再调用 update_from_output。只有请求仍然有效，引擎才把本轮生成的 token 加入待发送结果。请求取消属于控制状态，计算完成属于设备状态，两者需要在结果处理边界汇合；否则可能出现取消后仍继续追加输出或重复释放缓存。

2　请求槽位与批内顺序

一条请求可能连续生成几百步，本轮 batch 的行号却会因其他请求结束而变化。若把采样器状态绑在 batch 行号上，删掉第一行就会让后面所有请求错用邻居的状态。引入持久槽位后，每轮只需更新一张短映射表。

vLLM 的 GPU Model Runner V2（简称 MRV2）负责把一轮调度计划变成 GPU 实际执行的计算。它给每个活跃请求分配稳定槽位，在那里保存历史 token、页表和采样参数。即使本轮顺序变化，长期数据也能留在原处。

4　增量更新与缓冲复用

相邻 decode 轮次通常只增加少量 token 或页表项。StagedWriteTensor 先记录待更新的行号、起始列和新值，再用一次批量 kernel 应用这些差量。假设一张[1024,4096]的 INT32表容量16 MiB，本轮只有32行各修改1个元素，有效值只需128 B；实际还要携带索引、起点和累计长度，并支付 kernel 启动成本。这个比较解释增量更新为何有价值，也说明极小更新未必获得按字节比例计算的加速。

例如槽 7 的第 100 列要填入 42，槽 9 的第 20、21 列要填入 51、52。CPU 可以把三个新值紧排成 [42,51,52]，另记目标行 [7,9]、目标起始列 [100,20]。读完第一段时已经用掉 1 个新值，读完第二段共用掉 3 个。GPU 依照这些边界拆开数据，就能分别写回原表。

5　采样结果从 GPU 到 CPU 的异步复制

GPU 写入设备缓冲后，还要等设备到主机的复制完成，CPU 才能读取主机副本。先在复制流上安排传输，再用事件标出主机副本何时可读，调度线程就可以把等待推迟到真正需要该 token 的位置。

一次执行会留下三个不同的时刻。首先 CPU 提交任务并拿到一个 future，以后能用它取结果。然后 GPU 算完各候选的分数并选出 token，这时设备上已有答案。最后 token 编号从设备复制到主机（D2H），CPU 才能用这一份数据拼出响应。

Tserial = C + G + D,    Tsteady ≥ max(C,G,D)

真实 D 可能与 C 共用 CPU 线程，拷贝也可能与 attention 争抢带宽；grammar 更新、取消、抢占和推测接受数会增加依赖。此时max(C,G,D)只给出理想下界。优化要观察 GPU 空隙和等待来源，集中缩短关键路径上的等待。

采样 kernel 结束后，设备端索引可能已经就绪；若下一步是 CPU 更新语法状态，则还要等 D2H 复制到主机缓冲。只等待采样事件后读取主机内存，仍可能读到上一轮的 token。反之，下一步仍在同一设备流上消费时，显式全机同步又可能多等其他请求。应在结果写入完成与首个消费者读取之间建立依赖。

6　SGLang 的批次重叠与共享页表

SGLang 是大语言模型推理框架。它的运行时可以让多个用户共用同一套模型，把不同请求这一轮要算的词组成一个批次。调度线程为它们安排本轮工作，GPU 执行模型，之后才知道要把哪些词交给哪些请求。假设 A 的计算已完成，B 正在 GPU 上算，CPU 此时可以整理 A 的结果。若整理 A 要回收的槽还被 B 读取，就必须等相应读取结束。

SGLang 的 overlap 循环先接收请求、生成本轮 plan 并发起 run_batch，再处理前一轮结果，最后按依赖发起本轮采样。结果处理可能修改请求索引、页映射或共享内存池，而本轮 GPU 可能还在读取这些共享结构。设备端的读写安全取决于两条流之间的事件依赖。

代码 11　当前轮已发起时，前一轮结果才进入处理

假设前一批按 [A,B] 排列，新一批按 [B,C] 排列。batch.copy() 把这一次的批次信息和结果一起入队，稍后取结果时就能按对应的请求顺序处理。代码在入队前还安排了一次等待，因为处理上一批时可能改写新一批尚在读取的共享表。

WAR 是 write after read，指先读后写。后续写入必须等此前对同一块缓冲的读取结束。已有精确 shared_read_done_event 时只等该事件；缺少精确边界时退回等待 forward_stream（2153 行）。清空事件引用防止下一阶段误用旧事件。

例如格式只允许输出 true 或 false。上一轮若已接受前缀 tr，下一轮只允许能继续拼出 true 的候选 token。CPU 要先取得已接受的内容，才能更新语法状态并给下一轮准备掩码。这条依赖结束的时刻，和 GPU 何时读完页表是两件可以分别测量的事。

01　图的节点、依赖与可执行实例

一次推理要将新 token ID 复制到设备，再运行 embedding、矩阵乘、采样。将每次 copy 或 kernel 画成节点，从写入数据的操作向读取该数据的操作画一条有向边。stream 中有序提交形成顺序；跨 stream 需要 event 或其他明确依赖。两条互不依赖的分支可以并行，真实调度仍受 SM、拷贝引擎、带宽及其他在途工作限制。

捕获结束后，CUDA 得到一张描述各操作及其先后关系的图。实例化时，它根据这张图准备可执行对象 graphExec。引擎随后把这个对象提交到一条 CUDA 流，GPU 才真正执行图中的操作。相同的可执行图可以提交多轮，每轮都重新计算。若编译器先把两个相邻算子合并成一个内核，图里记录的就是合并后的那一次调用。

例如图里有两条分支，一条写本批的 logits，一条把上一批的统计值复制回 CPU。它们访问互不重叠的缓冲区，统计复制可以和本批计算并行。若统计读的恰好是即将被覆盖的那块缓冲区，就要先等统计读完，再写入新结果。这样沿每一条边都能指出究竟是哪份数据需要等待。

9　Gumbel-Max 的随机扰动采样

只有“甲”和“乙”两个候选时，总挑分高者会让乙永远出不来。抽样希望分高者更常赢，同时给乙一定机会。Gumbel-Max 为每个候选独立抽一个特定分布的扰动，加到原分数，再挑新的最大值。把两边都加同一个随机数，排名完全不动，因此“独立”在这里有实际作用。

对每个候选 i 独立抽取 Ui，它在开区间 (0,1) 上均匀分布。把它变成 Gumbel 噪声 Gi，加到经正温度 T 缩放的 logit zi/T 上。y 是各带噪分数中最大者的候选编号；同一候选的两次对数都使用它自己的随机数。

Gi = -ln(-lnUi),    y = argmaxi(zi/T + Gi)

教学例子令概率为[0.6,0.3,0.1]，logits 取各自自然对数，T=1，并指定U=[0.2,0.9,0.4]。三个噪声约为[−0.4759,2.2504,0.0874]，加噪分数约[−0.9867,1.0464,−2.2152]，因此本次选中第1号 token，尽管原始概率最大的 token 为第0号。一次抽样可以选低概率项，长期分布才对应给定概率。

以词 1 单算一遍。它的均匀样本是 0.9，噪声 −ln(−ln0.9)≈2.2504；原始对数概率 ln0.3≈−1.2040，相加约为 1.0464。最后比较的是三个这样的和。词 0 的原概率虽为 0.6，但它本轮抽到的噪声是负数。

可以用指数竞争理解这个等价关系：Ei=−lnUi服从单位速率指数分布，Ei/exp(zi/T)的速率为exp(zi/T)。独立指数变量中第 i 项最先到达的概率等于它的速率除以总速率，正好得到 softmax。取最小Ei/exp(zi/T)，与取最大ziT−lnEi等价。

14　结构化输出的语法状态

假设服务要求模型输出一个 JSON 对象，其中 ok 字段只能是布尔值。已经写到 {"ok": 时，后面可以接 true 或 false。若已经写完 true，后面就该按对象的规则继续，例如闭合右花括号。记录「当前已经走到哪一步、下一步还能接什么」的，是这条请求自己的语法状态。

JSON schema 或语法约束通常先编译成可随生成 token 更新状态的匹配器。每个请求持有自己的当前状态：已经接受了哪些 token、下一步哪些 token 仍有机会形成合法完整输出。采样前根据状态生成词表 mask，将不允许的候选排除；采样后将被接受 token 送回匹配器，再决定下一步。

如果所有候选都被过滤，服务需要把约束冲突当作明确异常处理，不能无条件对全负无穷 logits 执行常规采样并接受返回值。排查时记录 schema、tokenizer 版本、已提交 token、回退长度和停止条件，有助于区分 grammar 错误、mask 行错配与采样数值问题。

15　TensorRT-LLM 的容量筛选与逐轮组批

TensorRT-LLM 是 NVIDIA 的大模型推理软件。请求还没出完词就要保留历史，占显存；把它排进这一轮又会占 token 预算。设显存能留下 A、B、C，但这一轮只够算其中两条。先决定留下谁，再决定谁本轮执行，比把两种限制都叫“批大小”更容易读懂实际排程。

TensorRT-LLM 的 SimpleScheduler 将这两件事交给两个调度器。容量调度器先检查哪些请求可以继续占用资源，哪些需要暂停。随后，小批次调度器从候选中挑出本轮要做的工作，分为编码输入、处理提示（context）和继续生成（generation）三类。

代码 26　容量候选集合继续经过本轮组批选择

in-flight batching 表示不同请求可以在迭代边界加入或离开，不要求整批所有请求同时完成。实现仍需知道某个请求处于哪一轮、哪种状态，以及当前 KV 和模型特有状态的所有权。不同引擎对在途的表示方式不同，不能照搬另一个框架的队列长度或状态枚举值。

16　预留完成空间与批次利用率

取单池教学模型，总容量8页，已运行 A 实际占2页，继续到完成还可能再占用 4 页。当前空闲6页，但扣除 A 未来需求后，新请求可承诺的空间只有2页。若 B 到完成还需3页，它在保证不驱逐策略下不能进入；仅看“现在空闲6页”会误判准入。A 若提前停止，未用到的预算可在后续调度重新释放出来。

TensorRT-LLM 把这种「先给已接纳请求留足后续空间」的策略称为 GUARANTEED_NO_EVICT。模型若为不同窗口长度准备了独立的页池，调度器就逐池检查。预留先体现在可承诺的数量上，物理页可以等请求真的写到下一个位置时再交给它。

结论　物理未写 6 页，可新承诺 2 页；缺 1 页，暂不能接纳。旧承诺改为实占不会新增余量。

推导　第一次计算为 8−2=6 和 8−2−4=2。要接纳新请求，至少要释放一页已占用空间，或撤销一页预留。
把一页预留空间用于实际写入后，已占页数变为 3，预留页数降为 3，仍是 8−3−3=2。计算配额与页配额各自都必须满足，前者的余量无法抵消后者。

一次跨请求串词发生后，下一轮的 batch 顺序、页表或缓冲内容往往已变。应随提交冻结该轮的请求顺序、绝对位置、持久槽、设备事件和输出行映射。按“计划→输入→设备结果→交付”逐边界与正确运行对齐，最早出现的差异才用于定位；用最新的槽表反查上一轮可能得到另一个完全合法的请求。

通用矩阵乘法。左矩阵的行与右矩阵的列逐项相乘、求和，得到输出的一个元素；训练和推理中的线性层大量使用这种运算。

图形处理器，使用大量线程并行处理数据。需要许多独立运算或数据复用时，它常比逐项在 CPU 上执行更合适。

注意力中用来与查询匹配的向量。每个可见位置提供一个键，其分数决定同位置的值参与汇总的权重。

混合专家模型。路由器给每个词元挑选少数几个专家，由选中的网络计算，再按路由权重合并结果。

query
注意力中发起查询的位置或它的向量。它与各个可见位置的键相乘，得到对应的一行分数。
shape
张量形状，按顺序列出每一维的长度。即使元素总数相同，批次轴与通道轴的互换也会改变算子的含义。

流式多处理器。NVIDIA GPU 在 SM 上驻留线程块并调度其中的 warp，寄存器和共享内存会限制可同时驻留的块数。
softmax

token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TPOT
Time Per Output Token，常用于表示首个输出之后平均每个词元的耗时。应注明是否排除首词以及使用了多少个生成间隔。
Transformer
用注意力混合不同位置的信息，再逐位置通过前馈网络。一个解码器通常把多层这样的计算依次连接起来。
TTFT
Time To First Token，从请求的约定起点到看到第一个输出词元的时长。比较数据时应写明起点在客户端还是服务端。
value
注意力要汇总的内容向量。它与同位置的键配对，并按注意力权重计入输出。
互连
设备间传输数据的链路及交换结构。比较系统时要区分片内、单节点内与跨节点的范围。
共享内存
同一线程块中的线程可以共同访问的片上存储，用于暂存可复用数据。程序需要安排写入与读取的同步。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
准入
调度器确认有可用资源并允许请求开始执行。准入前的等待属于排队时间。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
前缀命中
复用已经计算好的前缀 K/V。新增查询仍要读取掩码允许的前缀位置。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
图捕获
把可表示的张量计算及依赖记录成图，以便编译器分析和生成内核。torch.compile 捕获张量计算及其依赖；CUDA Graph 捕获提交给设备的操作及其依赖。
图桶
为某组预定输入容量和形状捕获的图，真实请求可以只占部分槽位。
图重放
重复提交一个已有的设备工作图，同一静态输入地址中的内容可在各轮改变。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
复制引擎
GPU 中负责特定数据传输的硬件引擎。使用独立引擎只是实现重叠的条件之一，数据依赖和流同步同样重要。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
复用长度
可以复用已有计算结果的连续前缀长度。估算本轮开销时，应分别记录序列已推进的位置数和本轮还需计算的查询行数。
完成事件
通信流记录的完成标记。其他 CUDA 流须建立对该事件的依赖后才能使用相应结果。
完整块
块内所有键对当前查询块中的每一行都可见，可省去逐元素的掩码判定。
对数概率
某 token 归一化概率的自然对数。由单行 logits 计算时须扣去全词表的对数归一化常数。
屏障
程序中规定的同步点或状态。哪些线程或设备必须到达，取决于屏障的参与范围和约定的完成条件。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
引用计数
记录物理页或树节点仍被多少使用者持有，释放时还需考虑设备上的在途访问。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
托管内存
由 CUDA 统一管理、可从受支持的处理器访问的内存。地址能被访问和数据当前位于哪一级物理存储是两个问题。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
持久槽位
请求在引擎长期状态数组中的位置。动态批次重排后须重新映射到这个位置。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
时间线
将不同线程、CUDA 流及设备活动按时间展开，可结合事件与请求编号追踪先后依赖。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
暂存
在训练状态继续变化前，先复制一份可独立读取的快照供后台写盘。暂存结束和检查点可供恢复是两个不同的完成时刻。
有效行
由一次实际路由产生的输入行。为满足对齐要求而补出的行也占空间，但不对应任何 token。
未归一化
保留各项加权和，同时单独记录权重之和；除以对应分母后才是可直接输出的加权平均。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
模型执行器
根据调度结果和缓存位置准备本轮张量、提交模型运算并将输出行映回请求的组件。
流水线
把搬运、计算等相互依赖的阶段错开执行。不同数据块可以重叠，但消费某个块之前仍要确认它已准备好。
消费者
读取共享槽位数据并据此计算的一方。可以开始读，与生产者可以覆盖同一槽，通常由不同完成事件决定。
物化
把一个中间结果完整写到可供后续算子读取的存储中。融合可以让一些中间值只存在于片上。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
稳态窗口
完成预热后，用来对比同一工作负载的测量区间，应剔除一次性捕获和初始化。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
统一虚拟寻址
主机与设备可以统一解释某些虚拟地址；能被 GPU 寻址的缓冲仍可能实际位于主机内存。
缓冲复用
多次任务使用同一块内存。在先前读取完成之前覆盖它，可能使旧任务读到新内容。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
视图
共享底层存储但拥有自身形状、步长和偏移的张量表示。释放其中一个视图时，其他持有者仍可能让整块存储无法回收。
词表
记录 token 与整数编号对应关系的表。词嵌入矩阵使用同一套编号查行，每行才是模型参与运算的向量。
语法状态
表示当前已生成前缀在约束语法中走到了哪里，用来决定下一步允许哪些候选。
请求轨迹
按同一个请求编号整理的排队、批次映射、计算、采样及缓存状态变化。
载荷
应用需要传送的数据。协议头、编码开销和重传都会占用链路，有效载荷只统计应用数据本身。
连续批处理
每一轮重新选择要运行的请求，可补入新请求并移走已结束请求。
速度比
完成相同有效工作量时，原耗时与新耗时之比。若按输出速率计算，则用新速率除以原速率。
逻辑位置
某个 token 在这条请求中的序列下标。它决定所查的旋转角，搬动保存该 token 的物理页不会改变这个下标。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
量化
用有限个离散码近似表示原数值。尺度、零点和分组方式决定恢复后的数值及误差。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
页表
把逻辑位置所在的页映射到实际存储块的结构。在 KV 分页中，连续的逻辑位置未必位于连续的物理页。
预热
在正式计时前运行若干次，让编译、缓存建立或一次性初始化尽量离开稳态样本。
驻留
线程块已获得在 SM 上运行所需的寄存器、共享内存和调度名额。块被接纳后，其线程仍可能等待数据。
