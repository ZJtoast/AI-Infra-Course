1　智能体强化学习的策略、轨迹与奖励

训练服务里有三种角色。模型按可见的对话给下一步动作分配概率，这套选择规则叫策略；环境执行动作并返回新信息；训练器用任务结果调整策略。一次从拿到题目到结束的完整经过叫轨迹。比如模型提出运行测试，环境返回“第 2 项失败”，这个返回会影响下一步判断，文字本身却是环境写的。

在代码修复任务中，模型根据题目生成“运行测试”的工具调用。测试器回复“第 2 项失败”，模型据此修改函数，再运行测试，全部通过后结束。这一趟实际交互叫一次 rollout。任务可以约定全部通过得 1 分，这个分数是奖励。

策略π把状态映射到动作分布。在语言模型中，状态包含当前可见 token、工具观测和必要的任务信息，动作通常是下一个由模型生成的 token。工具返回内容改变后续状态，却不属于策略自己采样的动作。reward 可以来自测试通过、规则校验、人工偏好模型或成本项；reward model 与生成模型、value model 承担不同职责。

一次训练更新中的分工

组件输入与输出主要资源
Rollout / policy生成任务上下文→动作token、行为logprob、版本生成 GPU、KV、调度队列
环境 / 工具动作→观测、执行结果、终止原因CPU、沙箱、存储、外部服务等待
Reward轨迹与证据→标量或过程奖励规则CPU或奖励模型GPU
Advantage估计奖励、组关系或value→每动作优势归约、分组、可选critic计算
Trainertoken、mask、行为概率、优势→新参数反向、优化器状态、分布式通信
权重发布与安装训练布局→生成布局及版本切换导出、传输、加载、缓存重建

沿着这条轨迹，先由生成服务采样两次动作，测试器给出最终奖励，再由训练器更新参数。更新后的权重要交回生成服务，下一批任务才会用上新策略。若生成服务同时还在跑上一批任务，样本就需要记下它由哪一版策略生成。

把第一次工具调用记为动作 A，修改函数记为动作 B。训练动作 A 时，前缀只到题目。训练动作 B 时，前缀中已经有“第 2 项失败”。两者都可以用最终通过测试的奖励来训练，但当时模型究竟看见过什么，仍应按动作发生时的顺序保存。

2　轨迹、动作掩码与逐 token 概率

上一节的两次模型动作中间隔着工具回复。整段文字都可能影响下一步预测，但算策略损失时只给“模型自己写的词”计分。动作掩码用一串与 token 等长的 0 和 1 标出这些位置，1 表示该位置的动作参加损失计算。

把一次交互中各段 token 依次拼接成[P0,A0,E0,A1]：提示P0长3，第一段动作A0长2，环境观测E0长4，第二段动作A1长3，总长12。对应 loss mask 为[0,0,0,1,1,0,0,0,0,1,1,1]，只有5个动作位置贡献策略损失。attention 仍须让A1看到前面的环境观测；loss mask 为0不会自动删除观测，也不会把它从后续 token 的条件里移走。

3　PPO 的价值基线与 GRPO 的组内优势

一次测试通过能拿到奖励，但更新策略时还想知道，这次结果比原先预期好多少。这份差额叫优势。近端策略优化（PPO）通常用一个价值模型估计“从这里继续能得多少分”。组相对策略优化（GRPO）则可以让模型对同一道题答几次，用同组回答的表现做参照。

同一道题采两次，奖励分别为 1 和 0。若用组内均值 0.5 作基准，两个结果高出或低于基准的量分别是 +0.5 和 −0.5。这个简化算例只做中心化：它先给动作带来一个方向，再讨论实际算法怎样按组缩放、怎样限制每次更新的幅度。

奖励 r 是环境或奖励模型给出的反馈。优势 A 估计这次动作的回报比基准高或低多少。策略梯度通常以 A 乘动作 logprob 梯度：正优势鼓励相应动作，负优势降低其相对概率。为了减少方差，PPO 常用 critic 估计状态 value，再用时间差分残差构造优势；critic 需要额外前向、训练参数、优化器状态和数据同步。

先追踪 PPO 上栏的一步。把这一步真实奖励加上下一个状态的折扣价值，得到对当前价值的一次新估计。用它减去当前状态的原价值预测，差额就是 δt。只看一个差会对单步噪声敏感，因而把后续各步的差以 γλ 为比率递减相加。对终止位置取后续价值和优势为零，拆出第一项即可从后往前递推。

t 是当前生成步，T 是这条轨迹的结束边界，j 从 0 起数后续步。γ 衡量下一步价值的折扣，λ 控制使用较远残差的程度。At 是当前动作的优势估计。终止处取后续优势为零，从最后一个有效步倒推；若是仅因长度限制截断，边界价值应按实际采样约定处理。

At=∑j=0T−1−t(γλ)jδt+j=δt+γλAt+1,At∈R

δt = rt + γV(st + 1)-V(st),    At = δt + γλAt + 1

只看连续两个动作。若 γ=0.9、λ=1，第一步奖励 0，末步奖励 1，两个状态价值分别为 0.4、0.6，且末步真实终止，那么优势从后向前算。末步残差为 1−0.6=0.4，首步残差为 0+0.9×0.6−0.4=0.14，首步优势为 0.14+0.9×0.4=0.50。若只是工具超时截断但任务可继续，终点价值能否取零要看训练端对截断的定义，不能照抄真实终止的数值。

这是 GAE 的倒序递推表达，γ控制未来奖励折扣，λ控制多步残差累计。终止与时间截断需要不同的 bootstrap 约定：任务真正结束时通常不再估计后续 value；因预算中断的轨迹是否 bootstrap 取决于所定义的任务。工具观测 token 不应被机械地当成额外策略动作增加折扣步数。

4　PPO 概率比的分母

设模型在看到测试失败后，决定重新运行某个测试。采样时旧策略给这个动作的概率是 0.2，训练器用当前参数对同一段前缀再算一次，概率是 0.3。两者相除得 1.5，表示当前策略选择这一步的概率是原来的 1.5 倍。

先考虑固定旧策略πold产生样本、当前策略πθ正在更新的基本情况。比较同一段前缀下、同一个已选动作的概率时，ρt=πθ(at∣st)πold(at∣st)。这个比率反映新策略相对旧策略给该动作提高或降低了多少概率；它与两个不同 token 的概率比较无关。log 域相减再 exp，可以直接使用保存的逐 token logprob。

ρt = exp(logπθ(at|st)-logπold(at|st))

下式的 A 是上一节得到的动作优势，ε 是允许的裁剪幅度。先照原概率比计算一次收益，再把概率比限制在给定区间后算一次，PPO 取两项中较小的值作为要最大化的目标。

Jt = min(ρtAt,clip(ρt,1-ε,1 + ε)At)

最大化 J 对应最小化−J。取ϵ=0.2、A=2、ρ=1.5，两个候选为3和2.4，选2.4，过大的正向提升被截住。取A=−2、ρ=1.5，两个候选为−3和−2.4，选−3，错误动作概率变高仍受惩罚。取A=−2、ρ=0.5，选−1.6，过度降低负优势动作的收益也被限制。第二个例子中起作用的是未裁剪的 −3：提高负优势动作的概率，目标值会继续下降。

5　veRL 异步训练中的行为策略与旧策略

veRL 是把语言模型生成、奖励计算和策略训练组织在一起的强化学习框架。若训练器更新时采样器还在写上一条回答，这条回答里的词仍来自先前权重。举例说，第 10 版模型选了某个词，到第 12 版才用它训练，保存的生成概率要能指回第 10 版。

对同一个前缀、同一个已选 token，可以留下三条记录。生成端记下当时实际抽中它的概率；训练端收到样本后，用本批固定的一版权重重新打分；每做一次小批更新，再用当前权重打分。后两项各有自己的作用，图中用三个位置把它们区分开。

异步 rollout 实际由行为策略μ生成，样本到达训练端时，参数版本可能已经改变。veRL 的 decoupled 模式重新计算固定πold的 logprobs，作为随后 mini-batch 更新的 proximal anchor；训练中的πθ继续变化。于是存在两类偏差：πθ相对πold的更新，以及πold相对实际μ的数据分布差异。

6　分布式损失的有效 token 分母

设 DP rank0只有一个有效动作，损失4；rank1有三个有效动作，损失都为1。按全体有效动作等权计算的平均损失是4+1+1+14=1.75；先算每 rank 平均再平均得到4+12=2.5，改变了样本权重。变长轨迹、动态 packing 和多轮工具观测都容易让每个 rank 有效 token 数不同。

公式里的 r 是卡号，t 是动作所在的位置。m 是有效动作掩码，ℓ 是该位置的损失。分子累加所有被选中的损失，分母数这些位置有几个。第一张卡的一个动作和第二张卡的每个动作都各占四分之一。

L = ∑r∑tmr,tℓr,t∑r∑tmr,t

设 N 是整次更新所有 rank 的有效 token 总数，Sr 是 rank r 的未归一化损失和，P 为 rank 数。若底层对梯度取平均，就让本地反向的标量为 PSr/N。在下式中乘 P 可抵消梯度通信时的平均因子；若底层用 SUM，本地只需 Sr/N。

1P∑r∇θ(PSrN)=∑r∇θSrN(N>0)

仍取前例，两个本地损失和分别是 4 和 3，全局有效动作数为 4。如果两卡梯度最后取平均，本地分别用损失和乘二分之一，得到 2 和 1.5。通信再平均，目标恰为 1.75。若一轮包含多个微批，分母还要覆盖整轮所有微批的有效动作。

假设两个 rank 各算一行局部平均 loss。rank 0 有 2 个有效动作、损失和 6，rank 1 有 6 个有效动作、损失和 6。各自均值为 3、1，直接平均得到 2，但全局每个动作等权的目标是 128=1.5。实现时先按有效 mask 统计全局分母，再结合框架对梯度是求和还是平均来选择本地缩放。工具返回和 padding 可以占很多序列位置，却不能稀释动作分母。用两个 rank 的有效动作数刻意不同，最容易验出归一化错误。

AReaL 是面向语言模型强化学习的异步训练系统。生成工人可以在训练器更新时继续做题，但如果它们远远跑在前面，排队等待学习的回答就会越来越旧。可以按模型版本给出额度：接纳一项新任务占用名额，更新向前推进再开放下一批。接下来对照代码里已完成与仍在途的两种计数。

代码 14　并发余量与策略版本余量共同限制新任务

accepted 记录此前累计成功的任务数，running 是当前在途数。任务完成时 running 减一、accepted 加一，两个量的和保持不变。版本推进才打开新一批额度。

公式左边的 C 是能再接多少个任务。第一项用并发上限减去在途数 R；第二项先按当前版本 v、允许的版本差 s 和每批数量 B 算出累计上限，再扣掉已接受数 A 和在途数 R。两项取较小者。

C = min(Cmax-R,(v + s + 1)B-A-R)

例中版本额度覆盖 7 批，每批 8 个，共 56 个。已接受和在途合计 52 个，版本余量为 4。

取当前版本 v=5，最多允许落后 s=1 个策略版本，消费批量 B=8，已接受 A=42，在途 R=10，并发上限 30。并发余量 20，版本余量 56−52=4，最多再提交 4 个。若还有一个失败尝试退出，running 减少且 accepted 不增加，额度重新释放。实现允许容量返回负数，准入方需要在正额度时才启动新任务。

从版本 50 恢复，B=8，s=1。初始化 accepted=400 且 running=0，版本余量为 16。漏掉这一步会算出 416，短时间内生成出多批旧样本。

这个公式约束总供应量。某条轨迹的实际年龄还由生成跨度和消费顺序决定。记录行为版本区间 [46,48]、消费版本 50，可以报告最旧动作差 4 版，最新动作差 2 版。还应记录采样和训练使用该样本的时刻。将这段时间与版本变化、训练暂停记录和环境响应耗时对照，才能区分不同的滞后原因。

11　权重分桶传输与缓冲复用

给生成服务发布新模型时，许多层的参数要依次从训练侧送到生成侧。把几项权重装进一块可重复使用的缓冲，这块缓冲就是传输桶。先发一桶，接收方取走后再装下一桶，就能给搬运过程设定显存或主存上限。

一个 1T 参数 BF16 模型的单份权重为 2 TB，按十进制计。在有效聚合带宽 200 GB/s 的单条限制吞吐的传输路径上，搬完一份的下界是 10 秒。若生成复制组各要一份，汇总入流量随副本数增长。树形广播可以让中间节点转发，源端直连带宽与全网累计字节需要分开计量。

12　训练与生成共享 GPU 的切换成本

训练和生成都要用模型权重，但占用显存的方式不同。训练要留梯度、优化器状态和反向激活；生成要给各请求留 KV 缓存。让同一批卡分时承担两种角色叫共置。若给训练和生成各分一批卡，它们可以同时处理不同任务，但新权重要从训练池送到生成池。

沿图下方的五步看同一组 GPU。先为生成收集模型权重，加载提示词并生成回答；收集回答后，再把权重切回训练所需的分片，最后才能执行模型更新。中间的数字代表 GPU 与 rank，彩色分区代表模型分片。即使训练和生成共用四张卡，二者的并行布局仍可能不同，切换所需的重排应单独计时。

代码 21　separate_async 把同步周期和 mini-batch 大小联系起来

代码要求 train_batch_size 等于 parameter_sync_step×ppo_mini_batch_size，并对独立生成资源与权重传输后端做配置检查。改变同步频率会同时影响训练样本和固定旧策略的管理。

这里每个同步周期包含若干训练小批。例如固定每小批 8 条、每 4 个小批同步一次，这个周期对应 32 条训练样本。持续运行的生成池一直占着设备，代码还要求有奖励模型时给它单独的资源池。

假设独立生成池每秒完成 2 个有效组，还差 40 组。训练设备闲置并能将供给提到 4 组/秒，原本需要 20 秒，借卡后生成只需 10 秒，理论节约 10 秒。借出和归还合计 6 秒则仍有 4 秒余量。若只差 8 组，原本 4 秒、借卡后 2 秒，节省 2 秒，切换会拖长训练等待。生产中用最近一段的实测切换开销和有效组供给估算这个临界点。

八卡课堂推演可以先把 4 卡划给生成、4 卡划给训练。固定模型、任务和优化器，给工具注入 50 至 500 毫秒的已知长尾；同步与异步各跟踪一组完成时刻、trainer 等样本时间、生成池空闲原因及权重安装停顿。训练质量按相同有效动作数和相同 GPU 小时各比较一次，二者分别反映样本效率和系统效率。

设备可借用 12 s，其中只有扣除切换开销后的时间可用于 rollout。若迁入权重与返回训练各用 3 s，只剩 6 s 可生成；还要看这 6 s 内接受的组能否在版本过期前被训练器消费。比较两种放置时把“生成完成”“组奖励齐全”“训练实际消费”三个总数并排记录，估算训练实际使用样本的 GPU 成本时，以最后一项核对有效组数，并按训练步归集 GPU 用时。

13　同一权重下的 logprob 偏差

logprob 是实际选中 token 的概率取自然对数。设生成器和训练器使用同一版权重，同一动作在生成端记为 0.20，在训练端重算为 0.21。直接送进概率比会得到 1.05，看起来像更新了策略。因此要先查这两份概率是怎样从同一段输入算出来的。

先固定 token IDs、上下文、温度、模型版本和词表约束，再在训练端与生成端分别计算同一已选动作的对数概率。此时差值反映数值实现和输入布局。另取不同版本重算得到的差值则还包含策略本身的变化。把两次对照放在同一批轨迹上，才有办法解释 PPO 里 ratio 的来源。

代码 22　生成端调用与训练侧对应的 logprob 计算

代码中每一列 k 放的是同一批预测位置上的一组候选编号。循环总是把原来的 logits 交给打分函数，只换这一列的编号；最后沿末维把结果叠回去。比较已选动作时，先在两端找同一行、同一编号对应的分数。

同一个 token 的打分还依赖上游 logits。两端 reduction 顺序、attention 分块和 MoE top-k 选择发生变化时，统一最后的 logprob 函数只能消除其中一部分差异。

该提交的 TitanRL parity 说明要求两端匹配 TP 度数，并限制 sequence parallel。固定计算次序、禁用部分低精度归约、固定 attention 的 split 数都会改变性能。共享定义或复用编译产物可以减少重复编译；可复用范围取决于 shape、dtype、设备和编译配置，逐 bit 一致还要在所用路径核对。

先固定整条 token ID 和观察位置，关闭随机采样，每一步都给两端喂入同一个已知的下一个 token（teacher forcing）；否则第一个采样词不同就会使后面所有前缀失去可比性。在首个偏离位置比较 logits、归一化后的所选词 logprob 和 top-k 边界附近的差距。若 logits 一致而日志不同，先查温度、截断、词表分片归约和标签位移；若 logits 已偏离，再逐层找最早差异。

将组 g 写入“已消费”放得太早，可能在参数尚未提交便崩溃，恢复后跳过一次从未生效的更新。写得太晚则可能在恢复新权重后重复使用 g。可让最近一次已提交检查点携带该步真实消费的组 ID，恢复以这份清单为准；工具侧再按尝试键查外部状态。训练消费和外部副作用是不同系统的两个提交事件，单凭一个本地布尔值不能同时证明二者。

情境　训练步 40 的模型、优化器和消费清单已原子提交，清单含 g7。g8 的奖励和轨迹已持久化，尚未进入任何提交步。g9 已用幂等键 K 发出有外部副作用的工具调用，机器在写回执前崩溃。外部服务能按 K 查询结果，查询超时时不保证操作未执行。

键和值的合称。一个历史位置通常既提供参与匹配的键，也提供按注意力权重汇总的值。

模型为词表中各个候选 token 输出的未归一化分数；经过 softmax 可得到概率。不同词表的同一数字编号不必指向同一 token。

混合专家模型。路由器给每个词元挑选少数几个专家，由选中的网络计算，再按路由权重合并结果。

浮点格式中的“非数”，可由未定义计算产生。比较与归约对 NaN 的处理需要按运算和实现核实。

近端策略优化，通过限制新旧策略概率比对目标的贡献，使一次更新不过度偏离采样策略。
prefill
推理时处理已有提示词的阶段。模型可以同时计算多个输入位置，并留下后续生成要读的缓存。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
rollout
策略与任务环境实际交互生成一条轨迹的过程，既包含模型动作，也可能包含环境返回。
shape
张量形状，按顺序列出每一维的长度。即使元素总数相同，批次轴与通道轴的互换也会改变算子的含义。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
value
注意力要汇总的内容向量。它与同位置的键配对，并按注意力权重计入输出。

准入
调度器确认有可用资源并允许请求开始执行。准入前的等待属于排队时间。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
前缀命中
复用已经计算好的前缀 K/V。新增查询仍要读取掩码允许的前缀位置。
动作掩码
在拼接轨迹中标出哪些位置是模型产生、应计入策略损失的动作。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
对数概率
某 token 归一化概率的自然对数。由单行 logits 计算时须扣去全词表的对数归一化常数。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
常驻
让已启动的工作单元在内核内部反复处理多个任务，而非处理完一块便退出。具体任务领取方式由程序决定。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
恢复点
已完整提交且仍可读取的模型、优化器、数据游标等一致状态。从已完整提交的步骤中选择最近的一步。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
概率比
当前策略与参考旧策略对同一已选动作所赋概率的比值。不能取不同 token 或不同前缀的概率相除。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
激活
模型处理本次输入时产生的中间张量。它的形状和寿命依赖批量、序列长度以及接下来是否需要反向传播。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
策略版本
生成某段动作所用的权重身份，跨版本的轨迹须能追溯到各段实际行为策略。
行为策略
实际采出这条轨迹的策略及版本，异步训练时可能与训练端重新计算概率的版本不同。
词表
记录 token 与整数编号对应关系的表。词嵌入矩阵使用同一套编号查行，每行才是模型参与运算的向量。
词表分片
把分类输出的词表轴分给不同 rank，每个 rank 只算一段 token ID 的 logits。计算全局归一化或抽样时仍须协调。
调用链
一次注意力请求从上层接口，经编译与后端选择，到 GPU 内核执行所经过的路径。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
量化
用有限个离散码近似表示原数值。尺度、零点和分组方式决定恢复后的数值及误差。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
