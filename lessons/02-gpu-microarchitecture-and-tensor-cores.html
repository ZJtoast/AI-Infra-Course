1　GPU 的执行层次

从输出的一个元素反向看，程序先决定哪个线程算它，再决定哪些线程必须交换数据。线程块界定了可直接协作的范围；只有看清这层关系，才知道结果应放寄存器、共享内存还是全局内存。

由内向外看，32 个 lane 组成一个 warp，线程块中的多个 warp 在同一 SM 上协作，整个 grid 才分布到 GPU 的多个 SM。图中 132 对应论文讨论的 H100 SXM 的 SM 数。Block (SM) 表示线程块在一个 SM 上执行；同一 SM 的寄存器和共享内存如果还有余量，可以同时驻留多个线程块。

以矩阵乘法为例，先确定同一个输出块分给了哪些线程，再检查它们读入的地址是否连续、相同数据能复用几次。若线程因访存而暂停，SM 可以调度其他已就绪的 warp。

生产中经常遇到这样的差异：同样的线性层，prefill 一次处理几千个 token，decode 每步只有少量新 token。前者给矩阵分块提供大量独立工作，后者的行数较小，可能让很多 SM 无事可做。把 batch 调大后，性能变化还取决于权重复用、并行任务数量和显存容量。要定位差异，还要追踪线程怎样分工、数据从哪一级存储读入。

1.1　Grid、SM 与算术指令

一个 grid 中的块通常多于设备能同时容纳的块。先完成的块释放寄存器和共享内存后，后续块才有机会驻留。因此增加 grid 大小增加的是待执行工作。

启动内核时，程序指定线程块网格（grid）的尺寸、每块的线程数、动态 shared memory 字节和 stream。一般的 CTA（thread block）在其生命周期驻留于一个 SM；一个 SM 可同时容纳多个 CTA。线程按线性线程号组成 32 线程的 warp，warp scheduler 从已驻留且操作数就绪的 warp 选择下一条指令。一个 warp 的指令可能发往整数、浮点、Tensor、特殊函数或加载存储管线。不同 GPU 的调度分区数、发射能力与共享资源需按架构核对。

一条 global load 沿 lane 地址形成内存请求，经过适用的 L1/TEX、L2，必要时才去显存。shared memory 由程序显式寻址，适合块内复用与排列；寄存器是线程私有的操作数和累加器。声明在内核中的局部变量若溢出或需要可寻址存储，可落入 local 地址空间，实际可能访问缓存和显存。把“线程私有”误读为“总在片上”会漏掉代价。

图　指令调度、数据搬运与累加存储的位置

例如一个 block 以 256 线程处理 128×128 个输出。这 256 个线程组成 8 个 warp，共同负责 16,384 个输出元素。每个线程按分工持有若干累加器，一段 K 分块可以先被合作者搬到 shared，再被多个 warp 消费。扩大输出 tile 有利于重用输入，同时也增加累加器寄存器或 TMEM 需求。第 18 课用 LaunchStats 与实际执行计数检验这两种效应。

2.1　分支分歧与活跃线程

相邻两条线程若选择不同分支，一次指令发射可能只有部分 lane 产生有效结果。分析分歧要数同一 warp 内各分支的活动线程；两个不同 warp 各走一条整齐的路径，情况就不同。

假设同一 warp 中，编号为偶数的线程执行路径 A，这条路径有 L 条指令，奇数 lane 计算同长度的路径 B。两条路径有不同的指令流时，硬件需要在不同的活跃线程集合上执行这些指令；每条路径只有半数 lane 做有效工作。如果只是很短的条件赋值，编译器可能选择 predication：指令带谓词执行，条件为假的线程不产生相应结果。反汇编能看到这里生成的是跳转还是带谓词的指令。

向量加法的尾部掩码仅影响最后一个 warp，损失为 24 个线程槽位；长度增长后，这个尾部浪费占比会迅速下降。相反，如果每个 warp 都按数据值走多条长路径，损失可能遍布整个 kernel。生产中的不规则稀疏访问、不同长度序列和专家路由，需要同时考虑工作量分布与访存布局。

Volta 及后续架构支持 independent thread scheduling，线程可保有各自的执行状态。它没有消除 warp 内不同路径的执行成本，也不能保证同一 warp 中的共享内存读写天然同步。需要交换数据时，应使用参与线程集合正确的 __syncwarp、shuffle 或 block 屏障，不能依赖“大家大概同时走到这里”。

SIMT 与 Independent Thread Scheduling

若一条算术指令只对 16 个 lane 生效，warp 仍可能占一个发射机会，但有效元素数只有满 32 lane 的一半。若编译器把短 if 转成带谓词的指令，反汇编也可能不出现跳转。比较分支版本时既看每条指令有多少有效 lane，也看执行了多少条指令。

global、local、shared 是 CUDA 的存储空间概念，HBM、片上 SRAM 是物理实现概念。尤其容易混淆的是 local memory：它属于单线程私有地址空间，却可能落到设备内存并经过缓存。局部数组采用动态下标、变量过多导致寄存器溢出等情况，都可能引入 local load/store。

3.1　统一地址与物理存储

代码 3　同一指针在 CPU 初始化、GPU 计算

cudaMallocManaged 分配托管内存。CPU 先调用 initArray 填写数组 A 和 B，随后 GPU 使用相同的指针值访问它们。运行时和硬件会按平台能力处理访问、映射与迁移；具体行为受设备属性、驻留位置和内存建议影响。要知道首次 GPU 访问搬了多少数据，可以在时间线上查看托管内存迁移记录。

4.1　矩阵转置的访存布局

把输入矩阵逐行读入时，若立刻按转置位置写回，原来相邻的列往往落到相距一个行跨度的地址上。共享内存提供了一次块内交换顺序的机会，使全局读取和全局写回可以各自按连续方向安排。

行主序矩阵 X[r,c] 的地址偏移为 (r×N+c)×4。同一 warp 内相邻线程读取相邻列，因此它们访问的地址连续；直接把结果写到转置矩阵 Y[c,r] 时，相邻 lane 的写地址相差原矩阵高度×4。若高度为 1024，这个步长就是 4096 字节，32 个输出通常散落到不同 segment。把读取写得连续，不能自动保证写出也连续。

解决办法是在 shared memory 中改变线程与数据的对应关系。线程先按原矩阵的一行协作装入 tile，再按另一种线程索引读出，最后沿目标矩阵的一行连续写入。这样 global 的读和写都能连续，但 shared 内部的访问还要单独核算。下一节会用源码算出这个交换的代价。

合并访存与 shared memory 的官方说明

取宽度 N=128 的 FP32 行主矩阵，warp 的 lane 沿输入列 c 递增，读地址每步加 4 B。直接写 Y[c,r] 且 Y 的行宽也是 128 时，写地址每步加 512 B，32 个 lane 落入 32 个不同的 32 B sector。通过 shared 让线程交换行列角色，可使全局读写都沿连续列进行；随后需检查 shared 中的读取是否改为同 bank 的不同地址。

5.1　分块复用与访存量

对 C 的一个输出块，A 的同一行要和多列 B 做点积，B 的同一列又要服务多行 A。分块的收益来自这些重复使用。只算从显存搬进来多少字节，而没有数每块数据随后用了几次，就解释不了分块尺寸的作用。

沿 K 方向推进一轮，要读入 A 和 B 各一个方块，每块含 T2 个元素，共 2T2 个 FP32；计算 T2 个输出，每个输出做 T 次乘加，按一次乘加计 2 FLOPs，总计 2T3FLOPs。忽略最后输出写回，本轮 global 输入请求的算术强度为 T4 FLOP/byte。T=32 时，一轮读取 8192 字节，执行 65536 FLOPs，得到 8 FLOP/byte。

AItile=2T3(2T2)×4=T4 FLOP/B

把 K 设为 4096，固定一个 32×32 输出块，128 轮总共请求 1,048,576 字节输入，最后写出 4096 字节。总计算量为 8,388,608 FLOPs，包含写回的强度约为 7.97 FLOP/byte。直接让每个输出各自重新读取两条长度为 K 的向量，其输入请求数会高出约 32 倍；实际 HBM 流量的差异还会被缓存复用改变。

按一次 K 迭代核算：两个输入块各有 32×32 个 FP32 元素，合计 2×32×32×4=8192 字节。走完 K=4096 要 4096/32=128 轮，故输入总量是 128×8192=1048576 字节。输出块只在累加结束后写一次。

shared memory 中保存两块 32×32 FP32，需要 8 KiB。若双缓冲保存当前轮和下一轮输入，需要约 16 KiB。更大的 tile 可以增加复用，也会增加 shared 和寄存器需求，并改变可驻留 block 数。这个 kernel 用一个线程计算一个输出，因此 T=32 已经是 1024 个线程。若 T 增至 64，仍按这个分工就需要 4096 个线程，超过每块的线程数上限。高性能 GEMM 通过每线程持有多个输出、warp tile 和更深的流水线扩大复用范围。

这条思路可以对应第一课的线性层：多个 token 共用权重 tile，输入 tile 在多个输出通道间复用。decode 的 M 很小时，完整 tile 的有效行数减少，线程与计算槽位也可能被尾部掩码浪费。选择 kernel 时需要同时知道 M、N、K、dtype 和布局。

边缘若只剩 1 行有效，而实现仍按 T 行计算完整的 T×T 输出块，那么“每个读入元素重复使用 T 次”的理想账要按有效输出重计。比较分块参数时可同时报告逻辑 FLOP/执行 FLOP 与 DRAM bytes；前者低说明做了无效工作，后者高说明数据复用差，两种现象也可同时出现。

6　共享内存的 bank 冲突

对本节 FP32 例子，NVIDIA shared memory 的 32 个 bank 按连续 4 字节字交错映射。两个 lane 读取同一 bank 的不同地址，会形成 bank conflict；多个 lane 读取完全相同的字，可以广播。判断冲突时，必须区分“同 bank”与“同地址”，也要按具体指令及数据宽度分析。

在 32 列的 FP32 共享数组中，沿同一列读取相邻两行，字下标相差 32，bank 号随即重复。给每行末尾补一个字，行跨度变成 33；相邻行的 bank 号就向前移动一格。补齐会多占共享内存，是否值得要看冲突发生在哪条指令上。

bank(a) = ⌊a4⌋mod32

7　占用率与延迟隐藏

一个 warp 发出访存指令后，下一条依赖该数据的指令可能暂时不能执行。warp scheduler 可以选择另一组已经就绪的 warp 发射指令，让计算资源继续工作。这是 latency hiding。它通常依靠驻留线程的状态已经保存在 SM 上，无须像操作系统切换进程那样把全部寄存器写回主存。

例如四个驻留 warp 都在等同一轮内存访问，它们都暂时无法发射下一条依赖指令。若另一组独立 warp 已经就绪，调度器才能利用这段等待。占用率给出的是潜在候选数量。

occupancy 是某个 SM 上驻留 warp 数与该硬件允许的最大驻留 warp 数之比。它计量可驻留的执行上下文；其中多少 warp 当前就绪、多少在等屏障或内存，需要进一步观察。GPU 使用率高也不能反推出每条指令都有足够的有效 lane。

假设某调度器某周期有 6 个驻留 warp，其中 4 个等内存、1 个等屏障，只剩 1 个可发射。若该周期发出它的一条指令，则 active=6、eligible=1、issued=1。读性能报告时还要检查单位是每调度器每周期的平均还是总计。驻留数量描述的是已分配资源的 warp 数，发射数量描述的是该周期选中的指令数。

7.1　寄存器与共享内存的占用上限

资源按整个线程块分配。即使剩余寄存器还能容纳半个块，只要装不下下一个完整块，就不能再增加驻留块数。因此每线程多用少量寄存器，有时会跨过一道整数门槛，使并发块数突然下降。

Nresident 数一个 SM 可以同时驻留的整块数。先用每个 SM 的各项限额分别除以每块用量，再向下取整；能同时满足的块数取最小值。式中四项依次按寄存器、共享内存、线程和架构允许的块数上限计量。

Nresident = min(⌊65536256 × 64⌋,⌊9624⌋,⌊2048256⌋,16) = 4

把四个上限分别算出来。每块寄存器数是 256×64=16384，所以寄存器允许 65536/16384=4 块；共享内存允许 96/24=4 块；线程数允许 2048/256=8 块；硬件块数上限是 16。四项最小值为 4。每块有 256/32=8 个 warp，所以占用率的分子是 4×8=32 个 warp。

4 个 block 共 1024 线程，也就是 32 个 warp，occupancy 为 3264=50%。若寄存器升到每线程 96 个，寄存器约束允许 ⌊65536/(256×96)⌋=2 块，occupancy 降为 25%。若寄存器仍为 64，但双缓冲把 shared 升到 48 KiB，shared 约束同样只允许 2 块。

7.2　指令级并行

一个线程若要先读入地址再用该地址发下一次读取，两次操作之间有真依赖。循环展开可以暴露几条彼此独立的读取，却无法消去这条地址依赖。判断指令级并行度时，要沿数据的使用顺序看。

同一个线程可用不同寄存器分别累加几组互不依赖的结果。若所有指令都依赖同一个累加器的上一轮结果，就会形成长依赖链；多个输出部分和可以交错计算，让指令级并行帮助隐藏延迟。这会增加寄存器占用，和 warp 级并行形成资源权衡。

用一个纯教学延迟模型说明：某执行通路每周期最多发射一条独立指令，依赖结果需要 20 周期后才能使用；若每个 warp 只能提供一条独立指令，大约需要 20 个就绪 warp 才能持续填满这条通路。每个 warp 若能提供 4 条独立指令，所需 warp 数可降低。真实 SM 有多个调度与执行通路，延迟、吞吐及发射规则必须按架构和指令检查。

还要检查 grid 是否足够大。即使某个 block 的资源使用允许很高 occupancy，整个 grid 只有几个 block，也无法让上百个 SM 都获得工作。小 batch decode、过大的输出 tile 和任务分布不均，都可能造成这种并行度不足。

Occupancy、寄存器分配与延迟隐藏

把延迟隐藏写成一份发射记录。教学模型里每个调度器每周期最多发射一条、乘加的依赖延迟为 4 周期。若一个 warp 反复更新同一累加器，第一次在周期 0 发射，下次最早在周期 4 取到新值。周期 1 至 3 仍可选其他就绪 warp。另一种做法是给同一 warp 四个独立累加器，轮流发射，它在周期 4 才需要第一个结果。两种办法分别靠线程级和指令级并行覆盖延迟。增加累加器会消耗寄存器，可能降低驻留数；比较时要同时看每线程寄存器、eligible warp、发射利用率和未剖析的内核时间。

8.3　Hopper 的 TMA、mbarrier 与 WGMMA

9　异步搬运的依赖

一个 warp 等数据时，SM 可以调度其他已就绪的 warp。再把范围扩到整机，主机可以准备下一块输入，设备的复制引擎和计算单元则可以同时搬运、计算先前的不同数据块。CUDA stream 是有序任务队列，同一 stream 中先提交的复制、kernel 和事件建立顺序关系。不同 stream 提供潜在并发机会，实际能否重叠取决于依赖、硬件资源、内存类型与提交时机。

PCIe 支持设备互连，但 GPU P2P 是否可用由 GPU、平台、驱动、IOMMU/ACS 配置和连接方式共同决定。路径经过 CPU host bridge，描述的是连接经过哪一级 PCIe 桥；直接 P2P 的可用性还要通过设备对的访问能力检查。拓扑给出连接条件，能力查询和运行时选择决定可用通路。

单个请求若依次经过 GPU→PCIe→NIC→网络，链路稳态载荷速率不能高于路径上最慢的一段。若中转实现还要求整块先完整落入主存、再从主存发送，则两段可能需要相加而非只取瓶颈。先确定能否流水，才能选用按最小带宽或按分段耗时的估算。

10.1　GPUDirect RDMA 的数据路径

若 GPU 数据先拷到主机内存再交给网卡，主机中转会多出拷贝和同步。GPUDirect RDMA 让网卡对已注册的设备内存发起读写，从数据路径中省去这次中转；缓冲区何时可以复用仍须看传输完成条件。

远程直接内存访问（RDMA）允许网卡按事先注册的内存范围搬运跨机数据。发送端或接收端 NIC 按已注册内存区域、访问权限和传输请求执行数据搬运，常见接口包含 queue pair、work request 与 completion。内存注册把虚拟地址范围与设备可访问的映射、权限联系起来；completion 用来判断某项操作达到了接口规定的完成状态。网络远端写入完成、接收应用得知数据已就绪，以及后续 GPU 能安全读取，是需要衔接的不同事件。

InfiniBand 是一套专用网络体系；RoCE 将 RDMA 机制运行在 Ethernet 环境上，RoCEv2 使用 UDP/IP 封装。RDMA 的数据路径可以减少远端 CPU 的逐消息参与，但 CPU 仍可能负责初始化、注册、提交或控制逻辑。RoCE 的拥塞控制与交换网络配置会影响可持续吞吐及尾延迟。

普通主机缓冲路径可能先把 GPU 数据复制到 CPU DRAM，再由 NIC 发送；GPUDirect RDMA 使支持的 NIC 与 GPU 显存直接交换数据，减少主机缓冲中转。GPU 内存依旧要经过本地 IO 连接和网络，远端也要接收并写入目标内存。它没有消除物理链路成本，且需要相应的驱动、内存映射和拓扑支持。

NCCL 负责 all-reduce、all-gather、reduce-scatter 等通信语义及其执行组织，可以根据环境使用不同通路。从 NCCL 的传输日志可查看本次跨机通信选用了哪条网络路径。RDMA 路径可用后，还可分别调整集合通信的分块和同步安排，比较整次通信的耗时。第五课会沿 NCCL 源码展开 collective 算法与网络完成条件，本课先把硬件路径和这些接口建立对应。

12.2　MI355X 的 wavefront 与 LDS

把针对 32 个 lane 的归约移植到 64 个 work-item 的 wavefront 时，先检查交换步数和参与掩码。机械照搬可能只合并了其中一半的贡献，即使程序能正常编译也会得到错误结果。

MI355X 采用 CDNA4；官方指令集文档把一个 wavefront 定义为一组 64 个 work-item，并说明每个 CU 的 LDS 有 160 kB、64 个 bank。CUDA 的 thread/block/warp 与 HIP 的相应概念便于建立联系，但本课基于 32 lane、32 bank 的数值推导不能直接作为 CDNA4 的答案。矩阵指令的 fragment 映射也必须按 AMD ISA 与所用编译器检查。

12.3　TPU7x 的片上存储与互连

沿一个矩阵块看 TPU：计算单元消耗片上的操作数，需要先从更大的存储层搬进来；跨芯片切分时还得交换归约结果。由这个块的复用次数与交换次数出发，才容易判断容量、带宽和互连中谁先限制吞吐。

TPU7x 每颗芯片包含两个 TensorCore 和四个 SparseCore；这里 TensorCore 是 TPU 的架构组件名称，不能与 NVIDIA 单个 Tensor Core 做数量比较。VMEM 是供自定义 kernel 使用的片上 SRAM，矩阵计算由 MXU 等单元承担。块大小需要适配片上容量和计算通路，读 Pallas kernel 时应追踪 HBM 与 VMEM 之间的搬运及复用。

12.4　Trainium2 的 SBUF 与 PSUM

Trainium2 的 NKI 架构文档把数据存放的位置分为 HBM、SBUF 和 PSUM。每个 NeuronCore-v3 的 SBUF 为 28 MiB，PSUM 为 2 MiB；HBM 与 SBUF 之间由 DMA 搬运，PSUM 与 SBUF 之间通过计算引擎指令移动。矩阵部分和通常需要在 PSUM 中累计，再按后续操作需要转回 SBUF。

由此可以理解为何 kernel 的 tile 形状既受总字节数约束，也受 partition dimension 和引擎数据通路约束。把一个张量算成“少于 28 MiB”仅检查了容量，尚未证明布局可执行。不同引擎对同一片缓冲的并行访问也要满足对应规则，这与 CUDA 中只数 shared 总字节数同样不够的道理相通。

NeuronLink-v3 提供芯片间互连，厂商文档列出的每芯片互连带宽为 1.28 TB/s。具体实例的连接形状、参与芯片数与 collective 实现仍要单独确认。比较 NKI、Pallas、HIP 和 CUDA 实现时，可沿同一块输入追踪其存储位置、搬运者和结果的写入位置，再根据同步点与资源占用判断并发上限。

设备属性也要读对层级。deviceQuery 同时打印 sharedMemPerBlock、sharedMemPerMultiprocessor、regsPerBlock、maxThreadsPerMultiProcessor 等字段。regsPerBlock 是单 block 上限，不能拿它替代每 SM 的寄存器总量；计算 occupancy 时还需 kernel 编译后的资源使用与硬件分配粒度。API 上限、可选 shared carveout 和当前 kernel 的动态 shared 分配是不同对象。

增大 tile 可以提高数据复用，也会增加每个线程块所需的片上资源。双缓冲会占用更多共享内存，收益取决于搬运能否与计算重叠。算子融合减少了中间结果的显存读写，同时可能增加寄存器占用。

本课术语
API
供程序调用的接口。函数返回、设备执行结束和远端可见可能发生在不同时间，应按接口的约定判断。
bank
共享内存中可并行服务的一组存储单元。多个线程同次访问同一 bank 内的不同地址时，可能需要分批服务。
BF16
16 位浮点格式，使用 8 位指数和 7 位显式尾数。指数范围接近 FP32，小数有效位更少。
Blackwell
NVIDIA GPU 架构。此处的具体指令和数据格式要结合芯片目标确认，例如 SM100 内核使用的张量内存。
CTA
Cooperative Thread Array，即一个 CUDA 线程块。块内的线程可共享内存并使用块级屏障同步。
CTA
线程块在 NVIDIA 技术文档和 PTX 中的名称（cooperative thread array）。一个 CTA 的线程在同一 SM 上协作执行。
cubin
包含目标 GPU 机器码的 CUDA 二进制文件。运行前需检查它的目标架构与当前设备兼容。
CUDA
NVIDIA 的 GPU 编程平台。主机程序通过运行时或驱动提交内核，GPU 按线程块调度工作。
CuTe
CUTLASS 中用于表达张量形状、步长、线程分工和布局的工具。它可以描述同一逻辑元素由哪个线程访问。
D2H
从设备到主机的复制，例如将 GPU 显存中的结果拷入 CPU 可读内存。异步接口返回时，复制可能仍在进行。
decode
推理时利用已有状态生成后续词元的阶段。普通自回归生成中，每条序列每轮通常新增一个位置。
DMA
直接内存访问。复制引擎或网卡可在已授权的缓冲区之间搬运字节，提交操作之后需要检查它的完成条件。
DRAM
动态随机存储器。性能报告里的 DRAM 流量通常指设备与外部显存之间的实际传输量。
E4M3
由 1 位符号、4 位指数和 3 位显式尾数组成的 FP8 格式。具体有限最大值和特殊值还需核对采用的格式变体。
EP
专家并行。不同设备持有不同专家，路由器选完专家后，词元及其结果常常要跨设备传输。
FLOP
一次浮点算术运算的计数单位。按本节约定，乘法和加法各计一次；除以时间才得到吞吐量 FLOP/s。
FLOP/s
每秒完成的浮点操作数。报告吞吐率时要注明数据精度，以及分子采用有效工作量还是设备实际执行量。
FLOPs
一次给定运算所需的浮点操作总数。本课程通常将一次乘加计为两次操作，吞吐率另用 FLOP/s 表示。
FMA
融合乘加指令计算 a×b+c；在浮点工作量统计中通常计作两次运算。
FP16
通常指 IEEE 半精度浮点数，使用 5 位指数和 10 位显式尾数。与 BF16 相比，精度与可表示范围的取舍不同。
FP32
32 位浮点格式，具有 8 位指数和 23 位显式尾数。在低精度乘法中常用作累加器或保存统计量。
FP64
64 位浮点格式。它能表示更高精度的数，特定硬件上的峰值吞吐可能与 FP32 相差很大。
FP8
一组 8 位浮点格式。使用前应区分 E4M3、E5M2 等编码，并说明缩放因子和累加精度。
fragment
协作完成一次矩阵运算时，分布在各线程寄存器中的矩阵片段。单个线程持有其中一部分，具体元素映射由指令规定。
GEMM
通用矩阵乘法。左矩阵的行与右矩阵的列逐项相乘、求和，得到输出的一个元素；训练和推理中的线性层大量使用这种运算。
GiB
二进制容量单位，1 GiB 等于 1,073,741,824 字节；1 GB 按十进制等于十亿字节。
GPU
图形处理器，使用大量线程并行处理数据。需要许多独立运算或数据复用时，它常比逐项在 CPU 上执行更合适。
GPUDirect RDMA
让受支持的网卡等外设直接访问 GPU 显存的机制，可减少经主机内存中转的数据拷贝。
H2D
从主机到设备的复制。若计算内核要读取复制结果，两项操作之间需要流顺序或显式依赖。
H2D
从主机内存向设备内存搬运数据；相反方向通常记为 D2H。
HBM
GPU 常用的高带宽显存，用于保存权重、激活和中间结果等数据。芯片与显存之间可持续传输的字节数会限制某些算子。
Hopper
NVIDIA GPU 架构，H100 属于这一代。相关内核可利用 TMA 搬运和 warp 组矩阵乘等特性。
InfiniBand
用于节点互联的网络体系，可承载 RDMA 传输。NCCL 集合通信的结果语义与底层选择哪一种网络操作属于不同层次。
ISA
指令集架构，规定指令、操作数与执行语义。PTX 虚拟指令和 GPU 的实际机器指令处在不同层次。
JIT
即时编译。运行时根据实际输入或硬件生成可执行代码，首次编译费用与后续重复执行费用应分开报告。
KiB
二进制容量单位，1 KiB 等于 1,024 字节。
KV
键和值的合称。一个历史位置通常既提供参与匹配的键，也提供按注意力权重汇总的值。
L2
GPU 上多个 SM 共享的二级缓存。L2 命中可免去一次更远的显存访问，因此 L2 流量和 HBM 流量通常不同。
lane
一个线程在 warp 中的编号。分析访存时，先列出同一条指令下各个 lane 的地址，再判断它们覆盖哪些内存区间。
lane
一个 warp 内线程的位置编号。在 NVIDIA GPU 上通常为 0 到 31；边界判断可能让一部分 lane 不执行本次访存。
launch
一次内核启动。相同名字的内核可在不同时间、用不同的网格和输入启动，因此查计数器时还要确认具体实例。
LDS
AMD 计算单元内供工作组共享的片上数据存储。分析访问时须按对应架构的 bank 数和寻址规则计算。
mbarrier
位于共享内存中的屏障对象，用于记录参与者或异步事务在指定阶段是否完成。等待者还要匹配当前阶段。
MiB
二进制容量单位，1 MiB 等于 1,048,576 字节或 1,024 KiB。
MMA
矩阵乘加，把两个小矩阵相乘后加到累加矩阵。参与线程和操作数布局由具体指令规定。
MoE
混合专家模型。路由器给每个词元挑选少数几个专家，由选中的网络计算，再按路由权重合并结果。
NCCL
NVIDIA 的多 GPU 通信库，负责组织集合通信和点对点传输。它会根据参与设备、消息与拓扑选择可用路径。
NIC
网络接口卡，负责节点之间的网络收发。与 GPU 的 PCIe 拓扑会影响设备之间搬运数据的路径。
Nsight Compute
面向 GPU 内核的性能分析工具。它采集指令、访存和执行管线计数，并结合源码定位一个内核内部的限制。
Nsight Systems
系统级性能分析工具，用同一条时间轴呈现 CPU、CUDA API、GPU 内核和通信活动，可追踪请求耗时落在哪段依赖上。
NUMA
非统一内存访问架构。CPU 核、主存和 PCIe 设备按拓扑分组，跨组访问的时延和可用带宽可能不同。
NVFP4
NVIDIA 的分组缩放 FP4 表示，使用小组共享尺度。只将元素数乘以四位会低估实际存储量。
NVLink
面向 GPU 等设备的高速互连。实际可达带宽取决于链路数量、拓扑和传输方向。
P2P
设备能按受支持的方式直接访问另一设备的内存。它描述访问能力，实际走 NVLink 还是 PCIe 仍取决于拓扑。
PCIe
主机与 GPU、网卡等设备之间的互连标准。设备位于哪个根端口或交换机下，会影响传输所经的链路。
prefill
推理时处理已有提示词的阶段。模型可以同时计算多个输入位置，并留下后续生成要读的缓存。
PSUM
Trainium 上保存张量引擎累加结果的片上存储。后续使用通常需按 NKI 定义的路径将结果搬到合适的缓冲。
PTX
NVIDIA 的虚拟指令集。工具链还要把 PTX 编译成目标 GPU 的机器指令，才能判断最终实际执行了什么。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
RDMA
远程直接内存访问。网卡按已注册的地址和权限读写对端内存，软件还要按照传输协议检查完成和可见条件。
RoCE
在以太网上承载 RDMA 的一组协议。链路拥塞、丢包控制与网卡配置会影响性能。
SASS
面向某种 NVIDIA GPU 架构的机器指令。反汇编可以查看编译器实际选用了哪些装载、运算和同步指令。
scale-out
用网络把多个节点或节点内的高速互联域连接起来。跨域通信要考虑网卡、网络拓扑和协议额外开销。
sector
统计合并访存时使用的地址区间；本例按 32 字节划分。多个线程落在同一段内时只计一次被触及的区间。
shape
张量形状，按顺序列出每一维的长度。即使元素总数相同，批次轴与通道轴的互换也会改变算子的含义。
SM
流式多处理器。NVIDIA GPU 在 SM 上驻留线程块并调度其中的 warp，寄存器和共享内存会限制可同时驻留的块数。
SM
流式多处理器，是 NVIDIA GPU 上接纳线程块、调度 warp 并提供寄存器及片上存储资源的执行单元。
SM100
Blackwell 数据中心 GPU 使用的一种目标架构。SM100 对应的指令与布局要求不能直接移用于所有 Blackwell 型号。
SM90
NVIDIA 的 GPU 架构目标编号，对应 Hopper 系列。带附加后缀的目标可能开放仅该架构支持的指令。
softmax
把一行分数先取指数，再各自除以这一行的指数和，得到总和为一的权重。实作时可先减去行最大值以免指数溢出。
SparseCore
TPU 上针对特定稀疏运算和嵌入访问提供的专用硬件。比较这类硬件时，应按支持的运算和实际吞吐计量。
SRAM
片上静态随机存储器。GPU 的共享内存和部分缓存使用这类存储，容量通常小于外部显存。
Tensor Core
GPU 中执行指定小矩阵乘加等操作的专用计算单元。可用的矩阵形状、输入格式和协作线程范围由架构与指令决定。
Tensor Core
GPU 上执行小块矩阵乘加的专用计算单元，支持的输入格式、累加精度和分块形状随架构变化。
tensor map
描述张量地址、形状、步长等信息的描述符，供支持的硬件搬运指令解释多维访问。
Tensor Memory
部分 Blackwell 架构为矩阵计算提供的片上存储。指令用专门的寻址与读写协议访问，不能把它当成普通线程寄存器。
tile
计算时一次处理的一小块数据。划分 tile 可以让线程重复利用已搬进片上的数据，同时限制临时存储量。
TileLang
用分块和流水线描述高性能算子的语言工具。编译器根据目标后端降低成具体线程与内存操作。
TMA
Tensor Memory Accelerator，按照张量描述符搬运多维数据的硬件单元。计算线程通过屏障等机制确认数据可读。
TMEM
Blackwell 的张量内存。部分矩阵指令把累加结果保存在这里，再由指定线程读取或继续计算。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
Transformer
用注意力混合不同位置的信息，再逐位置通过前馈网络。一个解码器通常把多层这样的计算依次连接起来。
warp
NVIDIA GPU 的线程执行组，通常由 32 个线程组成。同组线程执行同一条指令，掩码决定本次哪些线程参与。
WGMMA
Hopper 的 warp 组矩阵乘加指令。多个 warp 协作发起运算，程序可在结果提交后等待它完成。
WMMA
CUDA 的 warp 级矩阵乘加接口，参与线程共同持有操作数片段并执行矩阵乘加。
互连
设备间传输数据的链路及交换结构。比较系统时要区分片内、单节点内与跨节点的范围。
信号
收发双方约定的完成标记。生产者更新标记前，要把标记与相应代的数据写入建立正确顺序。
元素数
张量各维长度的乘积。将它乘以每个元素的字节数，得到连续有效数据的大小，尚未计入对齐和分配器开销。
共享内存
同一线程块中的线程可以共同访问的片上存储，用于暂存可复用数据。程序需要安排写入与读取的同步。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
关键路径
由依赖关系串起来、决定当前工作何时结束的任务序列。缩短没有阻挡后续工作的任务，可能不会改变总耗时。
内存注册
把一个内存区间及其访问权限登记到 RDMA 设备，使网卡能够校验并执行对该区间的 DMA 操作。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
占用率
GPU 中活跃 warp 数相对硬件上限的比例。活跃的 warp 可能正在等数据，因此还要检查其中多少已具备发射条件。
反汇编
把编译好的机器指令还原成可读的助记符，用于核对编译器实际生成的操作。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
吞吐量
单位时间完成的工作量，例如每秒生成的词元数。比较吞吐量时，两次测量须统计同一种工作，并采用一致的起止条件。
固定提交
用 Git 提交哈希锁定本课所引用的源码版本，避免行号随主分支变化。
地址空间
PTX 用来区分全局内存、共享内存等存储区域的寻址范围。相同位模式放到不同空间中未必指向同一个对象。
块掩码
按查询块和键块记录哪些块可能存在可见元素。整块全空时，内核可以跳过该块的计算。
复制引擎
GPU 中负责特定数据传输的硬件引擎。使用独立引擎只是实现重叠的条件之一，数据依赖和流同步同样重要。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
完成事件
通信流记录的完成标记。其他 CUDA 流须建立对该事件的依赖后才能使用相应结果。
寄存器
线程存放局部值的片上资源。每线程用量过高时可能减少同时驻留的线程块，也可能导致部分值被移到内存。
寄存器
处理器为线程分配的片上操作数存储。线程不能用普通指令直接读取另一个线程的同名寄存器。
屏障
程序中规定的同步点或状态。哪些线程或设备必须到达，取决于屏障的参与范围和约定的完成条件。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
托管内存
由 CUDA 统一管理、可从受支持的处理器访问的内存。地址能被访问和数据当前位于哪一级物理存储是两个问题。
投影
此处指注意力与前馈层内的稠密矩阵乘。它按实际输入 token 行数重复执行，同一份权重可被多行共享。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
指令级并行
当后一条指令不必等待前一条结果时，处理器有机会交错发射多条独立指令。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
数据重排
按后续算子所需的顺序重新组织元素，可能增加读写流量和执行时间。是否影响端到端耗时取决于它是否落在关键路径上。
时间线
将不同线程、CUDA 流及设备活动按时间展开，可结合事件与请求编号追踪先后依赖。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
暂存
在训练状态继续变化前，先复制一份可独立读取的快照供后台写盘。暂存结束和检查点可供恢复是两个不同的完成时刻。
有效行
由一次实际路由产生的输入行。为满足对齐要求而补出的行也占空间，但不对应任何 token。
权重复用
已读入同一批权重后，连续对多行输入做点积，因而每个 token 分摊的权重读取量减少。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
步长
某个坐标轴上的下标增加 1 时，物理地址要前进的元素数。换算成字节还须乘元素大小。
流水线
把搬运、计算等相互依赖的阶段错开执行。不同数据块可以重叠，但消费某个块之前仍要确认它已准备好。
消息大小
一次集合通信中每个进程交给接口的逻辑载荷字节数。实在线路上传输的总字节数还与算法、参与数有关。
消费者
读取共享槽位数据并据此计算的一方。可以开始读，与生产者可以覆盖同一槽，通常由不同完成事件决定。
激活
模型处理本次输入时产生的中间张量。它的形状和寿命依赖批量、序列长度以及接下来是否需要反向传播。
片上容量
线程块可用的寄存器与共享内存等片上资源。估算时要按实际存放位置分别核对各类资源，不能只把所有字节混加。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
算术强度
以指定存储层次为边界，用浮点运算数除以跨过该层次的字节数，单位为 FLOP/B。
累加器
矩阵乘加中保存旧结果和更新后部分和的寄存器或专用存储。本例的线程分别持有输出片段中的若干元素。
线程块
一次内核启动中的一组协作线程。块内线程可以使用同一片共享内存，并在块级屏障处等待彼此。
线程组
为了搬运、发出矩阵指令或等待结果而协作的一组线程。组的大小和角色由内核及所用指令规定。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
行主序
同一行的相邻列在内存中连续存放。下一行的起点距离当前行起点一个行步长。
计时边界
明确一个耗时由哪两个事件的时间戳相减得到，跨主机相减前还须核对时钟关系。
载荷
应用需要传送的数据。协议头、编码开销和重传都会占用链路，有效载荷只统计应用数据本身。
速度比
完成相同有效工作量时，原耗时与新耗时之比。若按输出速率计算，则用新速率除以原速率。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
量化
用有限个离散码近似表示原数值。尺度、零点和分组方式决定恢复后的数值及误差。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
预取
在后续层开始计算前就发起参数传输。预取越早，计算等待参数的时间可能越短，但完整参数与当前层数据同时占用显存的时间也可能越长。
预热
在正式计时前运行若干次，让编译、缓存建立或一次性初始化尽量离开稳态样本。
驻留
线程块已获得在 SM 上运行所需的寄存器、共享内存和调度名额。块被接纳后，其线程仍可能等待数据。
