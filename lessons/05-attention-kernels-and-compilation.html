1　8K 注意力分数矩阵的显存开销

只看最终输出的形状，很容易低估注意力显存：输出的行数随序列长度增长，而逐项保存所有 query 与 key 的分数需要一张方阵。长度加倍时，这张中间表的元素数会变成四倍。

考虑单层、batch=1、32 个查询头、每个头 128 维、序列长度 8192 的 prefill。先采用普通 MHA，Q、K、V 的逻辑形状均为 [1,32,8192,128]。一次 QK⊤ 为每个 query 计算对所有 key 的分数，随后按行 softmax，再与 V 相乘。这里只讨论 Attention 核心，投影、RoPE、残差和 MLP 已在第一课单独计账。

沿用第 1 课的记号，Z 是缩放后的点积分数，P 是沿键的位置轴归一化得到的概率。若一行所有合法分数都相同，就会均匀读取这些值；只有先算出这一行的分母，才能得到各自占比。

Z = QK⊤/d,    P = softmax(Z),    O = PV

若 Z 和 P 都以两字节元素保存，每个 [1,32,8192,8192] 张量各占 4 GiB；同样 dtype 的 Q 只占 64 MiB。如果 softmax 中间结果使用 FP32，那个中间张量还会翻倍。训练还需处理保存与反向所需的状态。分数矩阵在数学表达式中存在，是否给它分配完整 HBM 存储，则由实现决定。

本例的容量与计算量；不计投影和 softmax 指令

对象形状或计算式结果
Q、K、V、O 各一个32×8192×128×2byte各 64 MiB
S 或 P 各一个32×81922×2byte各 4 GiB

dense attention 的所有有效 query-key 对仍然参与计算。FlashAttention 通过分块，把一小块分数立即用于指数归约和 V 加权，避免把完整 S、P 写入 HBM。对于既定因果掩码，右上角无效区域可直接跳过。改变了求值次序与存储方式后，浮点舍入路径会变化；数学上的精确 attention 不承诺与另一个实现逐位一致。FP8 等低精度路径还需额外评估量化误差。

处理完一个 key 块，要留下足以合并下一块的归一化状态。进入异步流水线后，还要确定最后一个消费者何时读完缓冲。后面的源码沿这两种依赖追到实际的 attention 调用。

FlashAttention 原论文：IO-aware exact attention

一条输出行最终只需要 dv 个值。即使在数学上对 8192 个 key 都打分，也可边读一个块边累计这一行的分母与加权分子，最后写 dv 个输出。省去的是把全部分数写到 HBM、随后读回的往返；输入 K、V 及每个合法 QK 点积仍须按算法处理。

2　在线 softmax 的三个累积量

处理第二个块时，第一块的输出已经是一个平均数。要与新块合并，还得知道旧平均数背后有多少指数权重，以及这些权重以哪个最大值为基准。这就是每行除了向量还要保存两个标量的原因。

选定一个查询位置，只跟踪它的一行分数，令 sj 为已经包含 1d 的分数，vj 是长度 dv 的 value 向量。直接 softmax 需要所有 sj 的归一化分母。把 key 分成块后，每个块都能先算一个局部分母；难点在于不同块减去的最大值不同，旧状态必须换到同一个指数坐标系。

固定一条查询，sj 是它对位置 j 已缩放的分数，vj 是该处的值行。m 是本轮指数的共同基准，ℓ 累积相对指数的和，u 累积相同指数乘值的和。ℓ 是标量，u 的宽度和值相同；每个输出通道都用同一个 ℓ 作分母。

m = maxjsj,    ℓ = ∑jesj-m,    u = ∑jesj-mvj

O = u/ℓ

从旧基准 m 换到共同基准 m′，每个旧指数都多乘同一个因子。因为它与位置无关，可以移到累积和之外；分子里的值向量也按同一因子缩放。

esj−m′=em−m′esj−m

m 是一个标量，ℓ 是一个标量，u 有 dv 个元素。对于 Br 个 query 行，三者形状分别为 [Br]、[Br]、[Br,dv]。u 尚未归一化，除以本行的指数和才得到最终 O。第一次处理有效块以前可设 m=−∞、ℓ=0、u=0；全遮挡行需要额外处理，不能直接依赖 −∞ 的普通代数。

设新块的最大值为 mb，新基准 m′=max(m,mb)。以前每一项 es−m 乘以 α=em−m′，就恢复成 es−m′。分母和加权和必须同时乘 α。只修正分母会改变所有旧 value 的权重；只修正输出也无法得到正确归一化。

m′ = max(m,mb),    α = em-m′

ℓ′ = αℓ + ∑j ∈ besj-m′

u′ = αu + ∑j ∈ besj-m′vj

稳定 softmax 可以从一个普通加权平均推出来。每个分数 s 的未归一化权重是 exp(s)。从整行统一减去最大值 m，只会令分子和分母同乘 exp(−m)，相除后不变。分块时先保存局部最大值 m、分母 l 和加权分子 u。新块若把最大值从 m 抬到 M，旧的 l 和 u 都要乘 exp(m−M) 才能与新块的权重相加。假设旧块只有分数 0、值 2，新块只有分数 ln 3、值 6，合并时旧块在新基准下的权重为 13，结果 23+613+1=5。仅保留每块归一化后的均值会丢掉两块的权重比。

4　注意力分块与片上容量

临时分数块随行块高和列块宽的乘积增长。扩大某一边会增加每次搬运后的复用机会，也会挤占其他操作数或累加器的片上空间。选块大小时要同时给 Q、K、V 和跨轮状态留位置。

取 Br=Bc=d=dv=128，Q、K、V 各块采用 BF16。Q、K、V 三个输入块各占 32 KiB，单份合计 96 KiB；FP32 输出累加器有 64 KiB 的逻辑容量，FP32 分数 tile 也有 64 KiB。这些对象可能分布在寄存器、shared 或 TMEM，生命周期还可能重叠。把所有尺寸相加只能作为对象账本，不能直接当作每 CTA 的 shared 使用量。实际分配要由对应架构的布局和编译资源报告确认。

增大 Br 能让一块 K/V 服务更多 query 行，减少重复装载；同时会放大 Q、分数和输出状态。增大 Bc 能减少循环次数，却增加每轮分数暂存和归约工作。再加入多级缓冲，输入空间近似随 stage 数增长。较大的 tile 也可能让每个 SM 能同时驻留的 CTA 更少，因此吞吐不会随 tile 单调提升。

[128,128] FP32 累加器按逻辑尺寸是 64 KiB。64 KiB 是结果的逻辑大小。实际存放时，结果可以分布在各 lane 的寄存器、架构专用存储，或因实现而暂存。判断占用率要把每一块映射到实际存储类型并加上流水槽数，再分别套相应资源上限。

4.2　FlashAttention-2 的并行划分

若两个工作块分别处理同一 query 的前半和后半历史，就必须额外合并两个分母和输出。让工作块分别负责不同 query 行，每行在本块内扫完自己的可见历史，就能减少跨块归约。

如果只有 B×H 个 CTA，batch 很小、head 不多时，即使序列很长，并发运行的线程块也可能不足以让全部 SM 都有工作。将 query 方向也切成独立 tile，每个 CTA 维护自己的 m、ℓ、u，并遍历所需 K/V，可以把本例扩展为 32×64=2048 个 query tile 工作项。不同 CTA 读取重叠 K/V，缓存能否缓解重复读取还与调度次序有关。

CTA 内也存在划分选择。若多个 warp 各算同一批 query 的不同 key 部分，必须再合并它们的分母和输出；若各 warp 负责不同 query 行，共享读入的 K/V 后可各自完成行归约和输出。FlashAttention-2 的 sliced-Q 分工减少了这类 warp 间中间结果通信，配合延后归一化，降低非矩阵指令开销。该原则不规定后来所有架构采用同一寄存器布局。

5　反向传播的概率重算与激活存储

7.1　在线 softmax 的延迟重缩放

稳定 softmax 常把迄今已处理分数中的最大值作为基准，使所有指数≤1；数学上也可以选一个稍小的公共基准，只要指数没有溢出且分子分母使用同一基准。若最大值每增加一点都缩放整个 dv 维输出，向量乘法开销会很大。保留旧基准一段时间，可以减少这类重缩放。

ℓ(m′)=em−m′ℓ(m),u(m′)=em−m′u(m)

两项分别是每行一个指数和、每行一个值向量和。读出时相除，共同因子会抵消。因此可以在指数范围允许时沿用旧基准，把矢量重缩放留到真正换基准的那一步。

8　Decode 的分块 KV 归并

prefill 有很多 query tile，可以把不同查询行交给不同线程块并行计算；单请求单 token decode 的 Lq=1，即使历史很长，每个 head 的 query 方向仍只有一个工作项。把历史 KV 切成多个 split，可让更多 CTA 并行扫描，再合并局部结果。代价是局部输出的写回、第二阶段归约和额外提交；短历史或大 batch 下可能不划算。

局部输出 Oa、Ob 已各自归一化，不能简单求平均，因为两个 split 的概率质量不同。设 La、Lb 是各 split 的自然对数 LSE，若至少一块的对数质量有限，先取 m=max(La,Lb)，再求 L=m+ln(eLa−m+eLb−m)。两个已归一化输出的权重分别为 eLa−L 和 eLb−L，二者之和为 1。

从两块合起来的原始 softmax 分式反推。记 Za、Zb 为两块的指数总和。局部输出已经除过自己的 Z，因此合并前先乘回来，两个分子相加后再除以 Za+Zb。每块只需交付一行 1×v 的输出和一个标量。

O=ZaOa+ZbObZa+Zb,ZaZa+Zb=exp(La−log(Za+Zb))

L = ln(eLa + eLb),    O = eLa-LOa + eLb-LOb

SageAttention 的 INT8 打分与 K 平滑

上一代 FlashAttention 在保持密集配对的同时调整了存储与排程。现在改变点积输入的表示。设一条 query 的值为 1，三条标量 key 为 100,100.1,100.2，三个 value 为 0,0,1，头维 1。由于只有第三个 value 非零，最终输出就是第三个 key 的概率。三条 key 都很大，却只差 0.1，最后一位能否保留下来会直接改变输出。

用一组对称 INT8 码来表示三条 key，恢复步长取最大绝对值除以 127，编码为“数值除以步长、就近舍入”。如果直接编码，步长是 100.2/127；三条 key 都会落入码 127。打分再也分不出三者，第三项概率会成为 1/3。若先用整条 key 序列的均值 100.1 做中心化，三个数变成 −0.1,0,0.1，步长是 0.1/127，可得到 −127,0,127。在这个忽略尺度舍入的小例里，三者的分数差都能恢复，第三项概率约为 0.3672。

一条 key 有 d 个通道，均值 μK 也是 d 维，按每个通道沿 token 轴求出。对固定 query qi，减掉这个向量会使同一行所有分数一起减少 ci=qi·μK/d。所有指数同时乘 e−ci，归一化时共同因子消去。如果还要返回未平移的自然对数 LSE，需把 ci 加回去。每个 KV 块若各减自己的均值，会使同一行各块失去不同的偏移，须先纠正块间差异。

设一个注意力头的通道数为 64。用 BF16 保存一行 Q 需要 64×2=128 B。SageAttention3 推理路径将每个值编码为 4 位的 E2M1，两个码装进一个字节，共 32 B；每连续 16 个元素共用一个 E4M3 的一字节尺度，还要 4 B。因此 128 行 Q 的主体加尺度占 128×36=4608 B。原始输入、对齐填充和临时结果若同时存在，还得另外计入峰值。

9.3　SLA 的关键块计算与边缘块补偿

NSA 让模型读摘要和少量原始块。扩散 Transformer 面对的是另一种取舍：图像或视频的一大批位置同时更新，一些块权重很小，另一些块单看并不突出，合起来却可能影响输出。Sparse–Linear Attention（SLA）先判别块的重要性，再为中间这一档计算较便宜的补偿。这里沿用论文的双向注意力设定。

设一个头有 S 个位置，Q、K 为 S×d，V 为 S×v。将查询和键分别按 b 行和 c 行分块，暂取 S 能被 b 和 c 整除。每块沿位置求均值，查询缩为 S/b 行，键缩为 S/c 行。两者相乘，每个数对应一对块。

用 Q¯、K¯ 分别表示查询块和键块的均值表。Pc 的第 i 行给查询块 i 的全部候选键块排序；先用均值做点积，再沿键块所在的列轴做 softmax。每个格子的权重只用于分派计算。

对查询块 i，取分数最高的一档为关键块集合 Ci，最低一档略去，其余为边缘块集合 Li。将关键块所含行拼成 KC、VC；若有 n 个关键位置，则下面的分数矩阵为 b×n，每个查询行只在这 n 个位置中归一化。

Qi 是查询块 i 的 b 行原始查询。上标 s 标出稀疏分支：Pis 是它在 n 个入选原始位置上的概率（b×n），Ois 是乘回同序的值后得到的输出（b×v）。

剩余块走线性分支。先在各块中汇总键、值的贡献，每个查询即可复用这些统计量。先固定一个查询 q（1×d），记 L 为分到线性分支的所有原始位置。给查询和键各生成 r 维特征，把二者内积作为非负权重。只要该行权重和为正，归一化后的输出就是下面的分式。

分子括号内，每个键的 r×1 特征列和自己的 1×v 值行做外积；分母只累加这些特征列。两项都与本次查询无关，所以可以按键块各算一次，等不同查询块选定自己的边缘集合后再合并。输出投影需要微调学习，因为这个分支采用自己的权重函数与分母。

14　CUDA Graph 的捕获与重放

解码步骤常由许多很短的 GPU 操作组成。如果每次都等主机逐个提交，设备可能在两条指令之间空等。图重放复用的是已经安排好的操作和依赖；输入值可以写入原缓冲，抓图时记录的地址仍须有效。

模型编译完成后，各个 GPU 内核仍要按依赖顺序提交。逐个由 CPU 发起时，每次提交都有固定开销。在每个 kernel 很短的 decode 场景中，提交与调度空隙可能占据明显比例。CUDA Graph 将一段满足捕获条件的 GPU 操作及依赖保存下来，后续 replay 可以减少逐次提交开销。它保留这段工作本身，通常不会减少 Attention 必须读取的历史 KV。

普通 stream capture 的 replay 复用捕获时记录的虚拟地址、shape 和 layout。输入数值可以更新到这些固定存储，随意给 Python 变量绑定一个新张量并不会改写图内记录的地址。动态 Python 控制流也不会在 replay 时重新执行；已支持的设备侧条件节点等功能要按所用 API 的支持条件启用。

torch.compile 的动态 shape 可以生成适用于多个尺寸的代码；同一份普通 CUDA Graph 仍具有捕获时的 shape/layout。组合使用时，运行时可能为不同尺寸捕获不同图或选择回退。reduce-overhead 模式会尝试利用 CUDA Graph 降低开销，但并不保证每个模型、每个输入和每个区域都被捕获。

为满 4 行图喂 3 条真实请求时，填充行即使不交付 logits 也可能经过 scatter 写 KV。应给它独立安全的临时槽或在写操作上明确屏蔽，并确保不会更新真实长度、随机数状态或回收计数。只检查输出切片前三行无法覆盖这些副作用。

15　Attention 优化的端到端耗时

若一次请求的注意力只占 4 ms，其余步骤占 6 ms，即使注意力降至 2 ms，总耗时也只从 10 ms 降至 8 ms。要把内核加速换算到端到端收益，先量它在原请求里占多少时间。

假设团队要优化一个同时处理长 prefill 和短 decode 的服务。先分别记录两个阶段提交给内核的输入形状：prefill 的 Lq 通常很大，decode 的 Lq 很小而 Lk 随历史增长。再记录 dtype、HqG、mask、head dimension、KV 布局和是否训练。相同模型名称可能走不同后端，形状分布比单个方阵 benchmark 更能解释收益。

15.1　算子边界的正确性检查

写前向参考实现时，必须明确打分缩放、掩码、查询头到 KV 头的映射，以及 score_mod 在哪一步生效，再用高精度小输入比较逐元素结果。测试长度跨越 tile 边界，如 127、128、129；加入非方形 query/key、零有效行、极端分数、不同 stride 及允许的 head dimension。测试全遮挡行时按接口约定判断输出，将接口规定的特殊返回值与普通浮点误差分开检查。

训练需同时比较 dQ/dK/dV，以及接口声明支持的辅助参数梯度；dropout 要固定对应随机过程。低精度需要区分原始输入参考、量化后反量化参考和 kernel 输出。Graph 路径另测连续两次不同输入、持有旧输出、多 stream 合法依赖、bucket 尾部与缓存更新，防止只在第一次调用正确。

最后把数值验证与计时分开：先确认做了相同有效工作，再记录冷编译与稳态时间、峰值/保留显存、生成后端和请求分布。详细 profiler 能帮助解释瓶颈，但其采样会扰动运行，最终延迟应以独立计时验证。本课未进行这些设备测量，前述表格用于组织后续实验。

把误差拆成逐元素差与整行概率质量两类。先用短序列高精度参考逐位置核对，再对跨 tile 长度检查行和、因果屏蔽与首个偏离坐标。对有 dropout 的训练还须固定同一掩码；否则两条正确实现也会因随机样本不同而给出不同梯度。

16　Attention 调用链

沿一次调用依次看模型层传了什么张量、后端按哪些条件选内核、内核又实际执行了什么掩码。同一个 attention 接口名可以通向不同路径，复现实验时这三层信息必须能够对上。

排查 Attention 的数值误差时，可先比对实际掩码、每个块的起止位置，以及每行累计的最大值和指数和。若误差只在图重放时出现，则应检查输入地址、有效长度和缓冲复用事件。

若分块版本只在长度 129 时偏离，先比较第 128 行的逻辑位置与可见列，再比对第一个 tile 结束后的 m、l、u，最后比较合入单项尾块后的状态。前一阶段一致、后一阶段首度不符，直接将排查范围缩至尾块加载、掩码或重缩放。若 eager 与图重放才有差别，则先确认两者实际拿到的是同一输入行。

token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。

Triton
用分块数组表达 GPU 内核的编程语言与编译器。开发者指定每个程序实例处理的块，编译器生成线程层面的实现。
TTFT
Time To First Token，从请求的约定起点到看到第一个输出词元的时长。比较数据时应写明起点在客户端还是服务端。
value
注意力要汇总的内容向量。它与同位置的键配对，并按注意力权重计入输出。
warp
NVIDIA GPU 的线程执行组，通常由 32 个线程组成。同组线程执行同一条指令，掩码决定本次哪些线程参与。
WGMMA
Hopper 的 warp 组矩阵乘加指令。多个 warp 协作发起运算，程序可在结果提交后等待它完成。
上游梯度
后续网络已经算出的损失对本层输出的导数。本层以它为输入，分别求权重梯度和输入梯度。

缓存分配器已从设备取得并继续持有的显存，包括正在被张量使用的块及暂时空闲、留待复用的块。
元素数
张量各维长度的乘积。将它乘以每个元素的字节数，得到连续有效数据的大小，尚未计入对齐和分配器开销。
共享内存
同一线程块中的线程可以共同访问的片上存储，用于暂存可复用数据。程序需要安排写入与读取的同步。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分数矩阵
一个头把每个查询与各个键分别点积后得到的矩阵。行对应查询位置，列对应键位置，完整存储的空间随两种位置数的乘积增长。
分桶
把若干实际批量映射到少量预先支持的形状。一条请求量为 3 的批次可选择容量为 4 的桶，空位需要正确屏蔽。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
分组量化
一组元素共用一份缩放参数。组变小时，各组更能适配自己的数值范围，同时需要保存更多缩放参数。
占用率
GPU 中活跃 warp 数相对硬件上限的比例。活跃的 warp 可能正在等数据，因此还要检查其中多少已具备发射条件。
参考实现
优先保证计算语义清楚、结果可复核的对照实现。它与被测内核必须使用相同输入和掩码定义。
反量化
把低精度码结合尺度和可选零点，恢复到用于算术的数值。它可单独执行，也可融合到内核中。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
因果掩码
限制一个位置只能访问自身和允许的过去位置，防止预测时读到未来内容。对角线的对齐方式取决于查询与键对应的绝对位置。
因果注意力
每个位置只使用自己及允许的更早位置，防止未来的信息泄漏到当前的预测中。
固定提交
用 Git 提交哈希锁定本课所引用的源码版本，避免行号随主分支变化。
图中断
捕获期间遇到当前编译器无法纳入同一张图的操作，程序需要从这里拆开执行。
图捕获
把可表示的张量计算及依赖记录成图，以便编译器分析和生成内核。torch.compile 捕获张量计算及其依赖；CUDA Graph 捕获提交给设备的操作及其依赖。
图桶
为某组预定输入容量和形状捕获的图，真实请求可以只占部分槽位。
图重放
重复提交一个已有的设备工作图，同一静态输入地址中的内容可在各轮改变。
在线 softmax
按块读入分数，只保存当前行最大值和按它计算的指数和。遇到更大的分数时先把旧和换到新基准，最后可得到整行一致的归一化结果。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
寄存器
线程存放局部值的片上资源。每线程用量过高时可能减少同时驻留的线程块，也可能导致部分值被移到内存。
屏障
程序中规定的同步点或状态。哪些线程或设备必须到达，取决于屏障的参与范围和约定的完成条件。
工作区
算子在执行过程中为暂存中间数据而申请的区域。模型权重大小不变时，工作区仍可能随输入或算法改变。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
归约轴
矩阵乘中将乘积相加的那一维。不同归约分组的尺度不同时，应先分别恢复各组的部分和。
投影
此处指注意力与前馈层内的稠密矩阵乘。它按实际输入 token 行数重复执行，同一份权重可被多行共享。
指数基准
为计算稳定性而从当前所有分数中共同减去的数。合并两块时，两块的指数和与加权和都须换算到同一基准。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
时间线
将不同线程、CUDA 流及设备活动按时间展开，可结合事件与请求编号追踪先后依赖。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
暂存
在训练状态继续变化前，先复制一份可独立读取的快照供后台写盘。暂存结束和检查点可供恢复是两个不同的完成时刻。
有效行
由一次实际路由产生的输入行。为满足对齐要求而补出的行也占空间，但不对应任何 token。
未归一化
保留各项加权和，同时单独记录权重之和；除以对应分母后才是可直接输出的加权平均。
查询头
以一组 Q 通道独立计算注意力分布的头。多个查询头即使共用 K、V，也保留各自的打分和概率。
概率比
当前策略与参考旧策略对同一已选动作所赋概率的比值。不能取不同 token 或不同前缀的概率相除。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
步长
某个坐标轴上的下标增加 1 时，物理地址要前进的元素数。换算成字节还须乘元素大小。
注意力头
独立计算一套打分、归一化权重和加权输出的通道组。
流水线
把搬运、计算等相互依赖的阶段错开执行。不同数据块可以重叠，但消费某个块之前仍要确认它已准备好。
消费者
读取共享槽位数据并据此计算的一方。可以开始读，与生产者可以覆盖同一槽，通常由不同完成事件决定。
激活
模型处理本次输入时产生的中间张量。它的形状和寿命依赖批量、序列长度以及接下来是否需要反向传播。
物化
把一个中间结果完整写到可供后续算子读取的存储中。融合可以让一些中间值只存在于片上。
稳定 softmax
在求指数前，从一行所有合法分数中减去同一个最大值。分子和分母同时缩放，概率不变，指数溢出的风险降低。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
累加器
矩阵乘加中保存旧结果和更新后部分和的寄存器或专用存储。本例的线程分别持有输出片段中的若干元素。
线程块
一次内核启动中的一组协作线程。块内线程可以使用同一片共享内存，并在块级屏障处等待彼此。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
缓冲复用
多次任务使用同一块内存。在先前读取完成之前覆盖它，可能使旧任务读到新内容。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
计时边界
明确一个耗时由哪两个事件的时间戳相减得到，跨主机相减前还须核对时钟关系。
输入梯度
损失相对于共享输入各分量的偏导。多条分支都读同一输入时，各分支的梯度贡献要按元素相加。
速度比
完成相同有效工作量时，原耗时与新耗时之比。若按输出速率计算，则用新速率除以原速率。
逻辑位置
某个 token 在这条请求中的序列下标。它决定所查的旋转角，搬动保存该 token 的物理页不会改变这个下标。
部分块
同一个分块内既有可见位置，也有被掩蔽的位置。内核若整块执行，有效配对数会小于它实际计算的格数。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
重缩放
当在线 softmax 更换指数基准时，把已积累的旧指数和、旧加权和换算到新基准。
量化
用有限个离散码近似表示原数值。尺度、零点和分组方式决定恢复后的数值及误差。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
页表
把逻辑位置所在的页映射到实际存储块的结构。在 KV 分页中，连续的逻辑位置未必位于连续的物理页。
预取
在后续层开始计算前就发起参数传输。预取越早，计算等待参数的时间可能越短，但完整参数与当前层数据同时占用显存的时间也可能越长。
预热
在正式计时前运行若干次，让编译、缓存建立或一次性初始化尽量离开稳态样本。
饱和
超出可表示范围的数值被夹到最近端点，恢复时无法区分它原先超出了多少。
驻留
线程块已获得在 SM 上运行所需的寄存器、共享内存和调度名额。块被接纳后，其线程仍可能等待数据。
