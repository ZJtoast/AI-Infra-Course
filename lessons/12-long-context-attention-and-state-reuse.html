1　长上下文解码的键值缓存容量

模型接着一篇长文写下一个词时，每一层都需要某种历史。最直接的办法是给读过的每个位置留一行键和一行值。键用来给历史位置打分，值是最终拿来加权的内容。读入第 5 个 token 后，一层便各有 5 行；换成 20 层，每层都要单独记这 5 个位置。后面几种架构分别改变每行存多宽、保留哪些行，或者干脆把多次写入合到一个状态里。

先考虑使用标准 K/V 缓存的解码器：L 层，每层有 G 个 KV 头，每头宽 d，每个元素占 p 字节；B 个等长请求，每个保存 S 个 token。若每层分别保存全部 K 与 V，原始缓存为2LBSGdp 字节。位置编码通常已经作用在保存的 K 上；分页、量化 scale、分片复制、窗口状态和 allocator 开销需要另计。

沿一个请求的一个位置数起。一个 KV 头要留下两条长度为 d 的向量，所以占两倍的 d 乘 p 字节。先乘这一层的头数 G，再乘层数 L，得到整个模型为一个位置留下的字节数。最后按每条请求的 S 个位置和 B 条独立请求放大。

CKV = 2LBSGdp

取L=32、G=8、d=128、BF16的p=2，一个 token 跨全部层为128 KiB。8192 token 占1 GiB，131072占16 GiB，1048576占128 GiB。8 条相同长度的独立请求同时运行时，历史缓存合计为单条请求的 8 倍。模型权重仍可共享。这些数值用来判断缓存能否全部常驻显存。每轮的读取量还取决于注意力访问哪些位置。

把数字代入：每层每个位置有 8 个头，每个头存两条 128 元素向量，每个元素 2 字节，一共 4096 字节。32 层合计 131072 字节，即 128 KiB。8192 个位置再乘 128 KiB 正好是 1 GiB，因此表中序列长度每翻一倍，相同设置下缓存也翻一倍。

MHA 令每个 query head 有独立 K/V；MQA 让全部 query head 共享一组 K/V；GQA 让若干 query head 共享一组。共享改变了键值数量，各 query 仍有自己的投影、分数与输出。张量并行若把 KV head 复制到多个 rank，应按本卡实际持有的头数计算容量。

模型的历史还要从两个方向看。扩到多长会放不下，取决于长期保存了多少字节，以及计算时还要为哪些临时结果留空间。生成一个词要花多少时间，则要追踪本轮先扫描了哪些候选、最后读了哪些键和值。

若一层保存 1000 条主记录，每条 100 B，每次 query 只读其中 20 条，这一层的常驻主记录仍为 100000 B，而理想单次有效读取为 2000 B。若每次选 20 条还需扫描 1000 条索引键，则又有独立的扫描量。排查 OOM 还需看是否物化整张 query×历史分数矩阵。用同一个“稀疏率 2%”无法代替这几笔账。

3　MLA 的位置旋转、缓存容量与解码读取

上一节将内容键与位置键分开缓存。沿着同一个当前查询，看它与两个历史位置的点积，就能看到分开处理的原因。假设整条内容键都用 RoPE 编入位置，令 i 是当前查询位置，j 是某一历史位置，R 表示该位置的旋转矩阵。q 是一行 d 维查询，历史位置 j 的一行 r 维潜向量先经过键上投影，变成 d 维内容键，再进行旋转。

sij=(qRi)(cjUKRj)⊤

sij=q·(RiRj⊤)·(UK)⊤·cj⊤1×dd×dd×rr×1

Ri 与 Rj 都是 d×d，乘积记录相对相位。同一个 i 遇到不同 j，这个乘积也变，当前查询就无法只变换一次。取 q=[1,1]、内容键 [2,0] 作检查，历史的相对旋转若从零变成半周，点积就从 2 变为 −2。解耦之后，让单独的短位置键承担这个差别，内容部分仍然可以吸收。

代码 3　naive 和吸收路径保存的缓存形状不同

展开路径按本地头分别保存键和值。吸收路径的两个缓存分别是 B×S×512 和 B×S×64，都没有头这一轴。因此在这份参考实现中，各张量并行进程都保存一份潜缓存和位置缓存。增加头的分片数，只减少每个进程负责的头数。

按上一节 671B 配置的头数和宽度，假定单卡、每个缓存元素用 BF16。展开路径在每层为一个位置保存 128 个头，每个头 192 个键元素和 128 个值元素，合计 40960 个元素，即 81920 字节。吸收路径只存 512 个内容元素和 64 个位置元素，即 1152 字节。按相同历史长度比较，前者约为后者的 71.1 倍。

再按层数核一次单位。若取 32 层，512 维潜向量和 64 维位置键均用 BF16，每个位置跨层占 32(512+64)×2=36864 字节，即 36 KiB。220 个位置共占 36 GiB。对照官方 671B 配置的 61 层，同一假设下每个位置跨层要占 70272 字节，1048576 个位置合计 68.625 GiB。

读入一段提示词时，同一批中有多行查询。把某段历史展开一次，多行查询可以重复利用这些键和值做矩阵乘法。逐词解码时，一个请求只有一行新查询，展开全段历史的代价就难以摊薄。实现可以据此为两阶段选择不同内核，比较时要同时计入临时展开和实际读取的字节数。

分页只管理缓存空间与寻址，不会自行减少每轮数学上要访问的全部历史。若采用 dense MLA，潜变量仍随 S 增长，解码 仍要沿历史归约。要进一步限制读取量，需要选择历史位置、压缩时间维，或把历史融合进递归状态。

4　DeepSeek Sparse Attention 的位置筛选与主注意力

MLA 把每行历史存窄了，生成一个词时仍会读到所有可见行。DeepSeek Sparse Attention（DSA）再加一道筛选。先用比较窄的索引键给各行排序，留下少数位置，再从这些位置读取主注意力所需的潜向量和位置键。这样省下的是未入选行的主注意力读取与计算，索引本身仍须打分。

从图 2 的绿色索引支路沿箭头看，Lightning Indexer 为每个历史位置生成一个分数。Top-k Selector 比较这些分数，返回排名靠前的位置编号。再沿主注意力支路看，各头用这些编号取相同的缓存行，但会用自己的主查询重新计算注意力权重。

把两张缓存按行排开，以下只算一个当前查询。令 S 为包括当前位置在内的可见 token 数，C 为 S×r 的潜缓存，KR 为 S×dR 的位置键。稠密 MLA 要在全部 S 行上计算内容项和位置项。DeepSeek Sparse Attention（DSA）在两项打分之前插入一道检索，选择单位是一条历史 token 记录。

其中 r 是每行共用的内容潜宽，dR 是单独缓存的位置键宽；两张表的第 j 行属于同一个历史 token。

令索引查询 QI 有 HI 个头，每行宽 dI，索引键 KI 每个位置只有一行，形状 S×dI。一次乘法得到 HI×S 的相似度矩阵。ReLU 逐元素作用，随后用当前 token 生成的 1×HI 权重汇总索引头，形成一行用于排序的分数。

HI 数索引查询头，dI 数一个头的索引通道。KI（S×dI）是与这些查询配对的索引键。R 记截去负数之后的响应，第 h 行、第 j 列来自头 h 与位置 j；w 是当前输入生成的逐头权重，u 是用 w 归约各头后的一行位置分数。

R=ReLU(QI·(KI)⊤)HI×SHI×dIdI×S

u=w·R1×S1×HIHI×S

R 的一列收集不同索引头对同一位置的响应。先截去每个头的负响应，再以 w 合并，才能让某个头发现的匹配参与排序。TopK 的返回值是位置编号；在这些编号上进行第二次注意力时，缩放、softmax 和值聚合仍属于原来的主头。

记 J 为 Top-k 返回的位置编号列表。CJ 是按 J 取出的内容潜行，KJR 是同序的位置键，|J| 是列表中有效位置数。

4.2　CSA 的重叠压缩记录与局部窗口

QSA 用块键做索引，选中后回到原始 token。DeepSeek-V4 的 Compressed Sparse Attention（CSA）进一步改变主注意力读到的对象：每 m 个 token 产出一条压缩 KV 记录，检索选中的就是这条记录。下面推导 V4 技术报告的重叠压缩器，V4.1 的分层索引和压缩器变更另见本课后文。

从图 3 下方的输入往上看，同一批历史会经过两套投影。右侧压缩器生成较窄的索引键，查询用它们排出要读的记录号。左侧压缩器生成对应的主键值记录。沿 Concatenation（拼接）的另一根输入线看，最近几个位置还保留着原始键和值。主注意力把入选的压缩行和这些原始行放进同一次归一化。

先算读取量。设选 k 个块、每块 m 行，若逐词展开，主头通常需要处理 km 行远端记录。若能在每个块完成时把它写成一行，检索同样 k 个编号就只需读 k 行。难点在写入时：未来查询还没出现，却必须决定每个通道保留哪些词的信息。CSA 为内容与权重各做一次投影，让模型学习这次压缩。

令 Xj 是第 j 个完整组的 m×D 隐藏状态，主记录宽 d。当前组和前一组经两套 D×d 投影形成内容，再沿位置堆叠成 2m×d 的矩阵 Y。门分数以相同次序投影，加上两套 m×d 的可学习位置偏置，得到 Z。首组缺少前一组时，将缺失行屏蔽。

下标 j 是本次发布的组号，D 是输入隐藏宽度。Wa,Wb 分别投影当前组、前一组的内容，Ua,Ub 分别生成这两组的门分数，四张权重都是 D×d。Ba,Bb 为两组各自的 m×d 位置偏置。Yj,Zj 按相同顺序排成两张 2m×d 表，才能用同一格的门为同一格的内容加权。

Yj=[XjWaXj−1Wb]2m×d

Zj=[XjUa+BaXj−1Ub+Bb]2m×d

固定内容通道 c，u 为来源表中的行号。Au,c 是第 u 行在这一列的权重，分母遍历所有有效源行。C~j,c 是这一列加权后留下的一个数。第一组缺少前一组时，缺失行的门分数置为负无穷，因此对分母贡献 0。

固定通道 c 后，求和下标 u 遍历源行。这一步得到 C~j∈R1×d，经 RMSNorm 和部分 RoPE 后才成为发布的主记录 Cj。

对每一个通道 c，权重在可见的源行上加到 1。不同通道可以从不同位置取主要贡献。相邻记录共享一个源组，但这组在两条记录中分别使用不同的投影。m=4 时，第二条记录覆盖位置 0 至 7，第三条覆盖 4 至 11；每完成四个位置才新增一条记录。给记录做归一化和部分 RoPE 后，主缓存有 M=⌊S/m⌋ 行、d 列。

单独检查两个源行、两个特征的微型池化。若两行内容分别是 [2,8]、[6,4]，第一列的归一化权重为 [0.75,0.25]，第二列为 [0.25,0.75]，压缩行就是 [3,5]。每列权重都各自加到 1。若错把 softmax 放到特征轴上，这两个加权平均便失去了按位置选取内容的含义。

6　索引扫描、分数缓冲与 Top-K 开销

上一节的主头只读 2048 行，负责找出这 2048 行的索引器却还要扫描历史。先追一个查询，若长度为 S，每个索引头都会产出 S 个点积结果。有多少个头，就有多少行这样的分数。算法还要沿头轴汇总，再对位置排序。这里数的是需要计算的分数；内核若边算边汇总，可以省去中间表的显存写入。

7　IndexCache 的跨层索引复用

9　时间维压缩的 KV 记录

接着追踪手册里的两个相邻位置。设模型每读两个词元才向全局缓存追加一行，那么读到第一个时，需要暂存它的内容和门控分数。第二个到达后，两者才能一起参与压缩。对查询而言，要分清“这条记录代表哪个位置”和“什么时候可以读这条记录”。

先看 V4 的两种时间压缩方案。CSA（Compressed Sparse Attention）对历史做较低倍率压缩，再用 indexer 选取少量压缩记录；HCA（Heavily Compressed Attention）采用更强压缩，直接对全部可见压缩记录做 dense attention。前者保留较细粒度并支付选择开销，后者减少记录总数、避免 indexer，却让更多原始 token 合并到同一表示。

公开实现文档给出的 V4典型压缩率为 CSA 的4与 HCA 的128。百万 token 对应约262144和8192个压缩条目；CSA 还从自己的池中选 Top-K，HCA 读取全部可见池。CSA 的重叠压缩窗口还要按具体实现核对可见时刻，不能把下文 V4.1的ratio=2非重叠示例直接套过去。两类全局分支均可结合局部滑动窗口。

10　CSA2 的跨层缓存与位置复用

如果连续几层都要在同一段历史里找线索，可以分别考虑三项开支：写历史、给历史建立索引、按当前查询挑选位置。共用前一层的记录，仍可为这一层重挑位置；连挑选也共用，则两层读同一组编号。CSA2 用下面三种模式安排这些选择。

CSA2将这种复用组织成 Full、Reindex 和 Reuse 三种静态模式。Full 生成当前共享段的主 KV、index key 并选择位置；Reindex 复用已有缓存，用本层 index query 重新选择；Reuse 继续复用已有 Top-K。模式描述的是跨层历史与选择数据流，各层主 attention 仍会执行。

复用最终选择集合，会少算几次 indexer；复用 index key，会少存几份索引缓存；复用主要 KV，会少存几份主缓存。这三个决定可以分开。DeepInfer 用三张 layer map 显式表示来源，并在初始化时校验嵌套分段：一个 Top-K 共享段必须落在同一个 index-K 段中，后者又落在同一个主 KV 段中。

三种来源关系同时存在。图中24层重算选择，25层复用24层的位置；两层均读取20层拥有的历史记录。

例如层24重新生成自己的 index query 与 head 权重，读取层20拥有的 index key，在层20选出的候选块内挑选位置；其主 attention 读取层20的全局 KV。层25可继续使用层24的 Top-K，但仍有自己的主 attention query、输出投影与残差。

14　前缀缓存命中后的窗口恢复与有界重放

用户在相同手册末尾追加一个问题时，服务端可能还保存了手册前缀的全局记录。可是下一步还依赖最近几个词和压缩时积下的状态。DeepInfer 是这里对照的推理实现。把缺失处之前的少量位置再执行一遍，就有机会补出需要的局部状态，重放多远由保存的边界决定。

前缀命中需要的不仅有全局块 KV，还可能有滑动窗口和压缩器状态。DeepInfer 文档说明了如何保存滑动窗口状态，以及状态缺失时怎样通过有界重放尝试恢复：在指定边界保存部分 encoder 状态，命中前缀但缺少对应窗口状态时，重放前缀末尾128个 token，再接新后缀。已有全局块 KV 继续复用，不因这次重放而重新覆盖。

先用两层、每层窗口宽 3 的例子数依赖。位置 4 在第二层读取第一层的位置 2、3、4。再往前看，第一层的位置 2 要读取输入位置 0、1、2。因此第二层位置 4 可以受位置 0 影响。如果只从位置 2 开始重放，第一层重算的位置 2 已经少看两个词，重放包含了最后三个位置也可能得出不同结果。

重放窗口从 s 开始，重放中位置 i 的可见范围为[max(s,i−127),i]。原始全程执行的同一位置还可能读取 s 之前的窗口，因而第一层边界就可能不同；跨多层传播后，最后128个 token 的状态也可能改变。DeepInfer 明确将该路径称为近似 SWA 恢复。它可以把恢复工作限制在固定长度，但不能自动保证逐位等价。

Kireplay = [max(s,i-W + 1),i],    W = 128

若只考虑20层、每层宽128的纯因果局部依赖，每往前追一层，最远能再往左走 127 个位置。最远历史跨度为20×127，连同当前位置共2541个 token；工程上按块扩展可采用2560长度。DeepInfer 文档用最后2560个 token 说明 decoder SWA 的更完整重构，并以128长度有界重放换取更低成本。实际模型还存在共享全局 KV 等依赖，应以实现定义的恢复语义为准。

前缀缓存命中长度也会为恢复和 speculative 回退预留尾部。该实现文档给出128窗口加6个余量的134边界，并按128的块对齐处理状态命中。这里的6属于这份实现的回退与环形槽策略；调整 draft 长度或窗口后应重新检查。

恢复方案需要区分三种事件：全局块 KV 仍在且 SWA 快照也在，可以从匹配边界恢复；全局块 KV 在而 SWA 缺失，可按配置重放；两者都缺失，就需要重新计算对应前缀。服务指标至少同时记录命中长度、重放 token 数、恢复耗时与质量变化，单一命中率无法解释所有首 token 延迟。

15　线性注意力的外积状态与查询读出

一行历史键值可以反复读，也可以将它的贡献加到一张固定大小的状态表。要判断后者什么时候成立，先把输出拆成每个位置的贡献。这里统一用行向量，键和查询宽 d，值宽 v。先考虑以点积本身为权重的情形。

例如键宽 2、值宽 1，开始时状态是一列两个零。第一个键是（1，0），值为 2，写入后状态为（2，0）的列向量。第二个键是（0，1），值为 5，状态变成（2，5）。此时查询（1，2）读出 12。逐位置算也一样：第一个位置的点积分数是 1，贡献 2，第二个位置的分数是 2，贡献 10。

固定头和时刻 t。qt 是本步 d 维查询，kj 和 vj 是第 j 步的键行和值行。将共同的查询从求和号内提出，就可先把每步 kj⊤vj 这一张 d×v 的外积表相加；和记为 St，追加一步只需在旧表上加一张新外积。

ot=∑j=1t(qtkj⊤)vj=qt(∑j=1tkj⊤vj)

括号里没有查询。位置 j 一到，就把一个键列和一个值行做外积，累加到状态。每行状态对应一个键通道，每列对应一个值通道。旧位置可以在写完后释放，下一次读出只需当前查询。

St=St−1+kt⊤·vtd×vd×vd×11×v

ot=qt·St1×v1×dd×v

如果要按正特征核归一化，把键和查询先映到同一特征空间，同时维护一个累积键列 zt=zt−1+ϕ(kt)⊤。分子仍从矩阵读取，分母从该列读取，再用标量除这一行。普通 softmax 的指数点积不能直接用上面的有限维原始键外积精确代替。

例如直接使用非负的键和查询作为特征，沿用两笔历史，累计键列的两个分量各为 1。查询（1，2）从该列读出分母 3，分子仍是 12，所以归一化输出为 4。直接把两个位置的分数 1、2 除以它们的和，再给数值 2、5 加权，也会得到 4。

设 L=32 层，每层 H=16 个头，d=v=128。若状态用 FP32，每个请求要存 LHdv×4=32MiB。同样的头数和宽度，若逐位置保存 BF16 键值，则每个 token 增加 LH(d+v)×2=256KiB。在这个例子里，历史长到 128 个位置，两种有效载荷才相等。实际模型还可能另存卷积窗口和混合注意力层的 KV。

每来一个词，仍须读写 d×v 个状态分量。解码的批量较小时，搬运这张表可能占去大部分时间；预填充含许多连续位置，可将块内的部分工作改写为矩阵乘。

未归一线性状态从零开始，先写 k=[1,0]、v=2，再写同一 k、v=5，状态沿第一行的和为 7。同一 query 沿第一方向读取只得到 7，无法问“第二次那条具体记录是什么”。普通 KV 表保留两行则可分别赋注意力权重。递归减少的是历史存储形式，代价是可表达的历史检索方式改变。

状态中的不同历史会互相叠加，模型无法像位置缓存那样任意回读某个原始 token。下面的 Delta 规则针对已有映射计算修正量，缓解相同 key 重复写入造成的积累，但仍保留有限状态的表达边界。

16　Delta 规则的预测误差与定向写入

先看一个标量状态的简例。键取 1，状态目前会为这个键读出 3，新观测值为 5。差值是 2；若按一半的力度修正，状态写成 3+0.5×2=4。再遇到同一个键，就会读到更接近新观测的 4。下面把一个数换成矩阵，用键来指定修正作用的方向。

若状态已经能由 key 准确预测 value，再把完整 value 写一次会重复强化旧内容。Delta 规则先用当前状态做预测，只写回真实值与预测值的差。后续同一个 key 再来读取时，这次修正才体现出来。

沿用上节的行向量，状态 S 有 d 行 v 列，行对应键通道，列对应值通道。本步先用标量 α 衰减旧状态，再让当前键从中读取一个 v 维预测。用观测值减去预测值，逐坐标得到差额。标量 β 控制补写多少，键的转置决定把这些差额写到状态的哪些行。

S¯t=αtSt−1d×v

v^t=kt·S¯t1×v1×dd×v

St=S¯t+βt·kt⊤·(vt−v^t)d×vd×11×v

用刚才的键再读写完的状态。把更新式左乘 kt，两个键的内积只剩一个标量。这一步能检验本次写入究竟纠正了多少误差。

ktSt=v^t+βt(ktkt⊤)(vt−v^t)1×v

若 k 是单位向量，β=1 会一次命中目标，β=1/2 只走一半。另一键与 k 不正交时也会读到这次修正，这解释了为何同样大小的状态矩阵可能出现记忆干扰。下面对照循环中预测、写入和读出的先后。

上一节的 Delta 规则已经把历史写进固定大小的矩阵。Kimi Delta Attention（KDA）继续使用这张矩阵，但细化了遗忘的范围。每个头维护一张 d×v 的状态矩阵，键方向决定写入哪一部分，查询方向决定读出哪一部分。仍取行向量，k、q 为 1×d，目标值 vt 为 1×v。头下标暂略。

给定键 k，一张状态 S 会预测 kS。要让记忆更接近当前观测，可把平方误差对 S 求导。梯度是键的转置与预测误差的外积，形状恰好为 d×v。若直接写入完整目标值，重复遇到已经学会的键值对仍会累加；改写预测误差，就能在命中目标时停止修正。

下标 t 表示处理第 t 个输入。kt 是本步的键，vt 是它要写下的目标值。L(S) 是状态 S 当前预测与目标间的平方误差的一半。固定第 a 个键通道和第 b 个值通道，状态元素 Sab 只影响预测的第 b 项，影响系数为 kt,a。这一项的误差乘这个系数，正是梯度矩阵的第 (a,b) 格。

L(S)=12‖ktS−vt‖22

∇SL=kt⊤·(ktS−vt)d×vd×11×v

St−1 是上一步留下的状态，S¯t 是按行衰减后的中间状态。用本步键读它，再从真实值中减去预测，得到误差行 et。沿键的方向补写后，新状态为 St；qt 是本步查询，ot 是用它读新状态的结果。

18　Mamba 的选择性状态与 SSD 分块递推

Mamba 用一份随词元更新的状态保存历史。读到新词时，先让旧状态衰减，再写入由当前词决定的新信息。若旧状态是 6，保留一半后再写入 2，新状态就是 5。下一步从 5 开始。模型可以随输入调整写入、衰减和读出，因此称为选择性状态空间模型。

选择性状态空间模型也用固定状态表示历史。以简化的单头 SSD 的离散递推式为例，St=exp(at)St−1+xtbt⊤，其中 x 有 P 维、b 有 N 维，状态为P×N，输出yt=Stct。输入相关的 b、c 和步长等决定写入与读取。这里没有 Delta 规则中的“读取误差再修正”项，两个家族的状态更新需要分别理解。

Mamba-2 用结构化状态空间对偶（SSD）把下面这种递推改写为分块计算。块内可以先算出两样东西：本块自己的输入对输出贡献多少，以及如果从零开始，本块结束时会留下多少状态。再把前一块传来的状态补进去。这一点可以直接从原论文图 5 看出来。

先看左上矩阵。对角块把一段输入映到同一段输出；左下方的非对角块则表示较早一段对后面输出的贡献。下方把这些贡献拆成三步，先由输入写出块末状态，再沿块边界传播状态，最后由状态补到后续块的输出。这样，块内的大矩阵乘可以并行，只把较小的状态送过边界。

St = eatSt-1 + xtbt⊤,    yt = Stct

把同一块中位置 a 到 b 的递推逐次代入。每经过后面一个位置，已有状态都再乘一次衰减。令 λi=exp(ai) 为标量，xibi⊤ 为 P×N 的写入；末端状态正好分成“从前一块传来”和“本块自己写入”两部分。

Sb=(∏i=abλi)Sa−1+∑j=ab(∏i=j+1bλi)xjbj⊤P×N

空乘积取 1，所以最后一次写入不再衰减。右边第二项只涉及本块，各块可同时算；第一项只需要前一块的末状态。两项相加后再右乘 N×1 的读取向量，就得到 P×1 输出。这正是原图中块内贡献与越过块边界的贡献。

用一维状态手算：α=12，四步写入为[1,2,3,4]，初始0，则状态依次[1,2.5,4.25,6.125]。按两步一块，第一块的零初态末状态为2.5，第二块为5.5；每块对入块状态的衰减为14，所以第二块末为5.5+0.25×2.5=6.125。块内可先算，跨块只需传递相应状态与变换。

19　递归状态的复用与回退

推测解码先让草稿模型提出几个候选 token，再由目标模型验证。假设候选有 5 个，验证只通过开头的 2 个，下一次计算就要从第 2 个之后接着走。普通 attention 为每个位置分别存键和值，可以通过页表截断到接受的 token 长度；递归模型把多个 token 写进同一个状态，最终状态不能直接删除最后几行恢复早先时刻。要恢复这次验证留下的进度，可以读取第 2 步后的状态快照，或者从更早的有效状态重放这 2 步。逆推可能遭遇不可逆门控和舍入，通常不能作为可靠恢复方案。

前缀缓存可以保存特定边界的递归状态，但缓存身份必须覆盖模型版本、权重、adapter、token 序列、位置与状态格式。混合模型还须同时恢复 attention 页、递归矩阵、短卷积窗口及压缩器尾组；其中任意一份只恢复到另一时刻，后缀输出就可能错误。

连续 batch 中，每条序列拥有独立状态槽。请求完成后释放、槽位复用前初始化、分支请求采用复制或写时复制，都是模型语义的一部分。共享可变状态而不隔离写入，会让一个请求污染另一个请求，即使所有张量形状仍合法。

20　混合架构中的历史与固定状态

同一条请求多生成一个 token，Kimi-K3 的 69 个 KDA 层各自在原来的矩阵里更新一次，24 个 Gated MLA 层则各追加一个位置的记录。估算显存时，先把 69 份固定大小的状态相加，再按历史长度计算另 24 层的记录。

把每条请求的所有 递归状态合计为 C 字节，所有注意力层每新增一个位置合计写入 K 字节。历史有 S 个位置时，两类状态一共占 C+SK。历史从 S 变成 2S 时，变成 C+2SK，倍率只有在 SK 远大于 C 时才接近 2。例如，设固定状态占 4 MiB，每个位置合计追加 1 KiB。1024 个位置占 1 MiB，加上固定状态共 5 MiB。增至 2048 个位置时，历史占 2 MiB，总量是 6 MiB。这组数值用于演算。复制请求、前缀共享和 TP 复制会进一步改变这两项。

在 Qwen3.8-Flash-Next 中，同一个 token 经过 GDN 层时改写递归状态，经过 QSA 层时，索引器先给小块打分，再读取入选块里各位置的键和值。因此，估算一次读取的字节数要看选中几个块，估算历史缓存容量还要计入留给后续查询的块。

Qwen 还会用邻近几个 token 构成的片段查 N-gram 嵌入表。所有请求共用训练好的表。两个请求查到同一表项时会读取同一组参数。若表放在主机内存，推理引擎可以提前取下一批表项，让传输和 GPU 上正在进行的计算重叠。DeepSeek-V4.1 的 Engram 查表也应单列在模型参数预算中。

还有一类数据只在层与层之间传递。Qwen 的四路门控残差让本层从四条分支读入特征，再将结果写回分支。活跃 token 增多时，同时保留的分支激活也会增加。推测解码还会临时保存候选位置的状态，直到验证完成。估算峰值显存时，这些临时数据要加在参数和请求历史之上。

正确性应同时核对位置和数值：小序列上把所选位置展开为稠密注意力掩码，比较主 attention 输出；验证候选坐标还原、因果可见性与无效哨兵；比较逐 token 递归与分块执行；从同一边界保存并恢复全部状态后继续同一后缀。量化、不同归约次序与近似重放分别设置容差或质量指标，不能用一条宽松阈值掩盖坐标错误。

模型层数、压缩比和记录格式可对照各节链接的配置与对应源码版本。由这些参数可算出理想记录字节数；真实显存峰值还要加上分配器保留空间和同时存活的临时缓冲。

估算并发时，逐卡扣掉权重、同时在用的临时缓冲和预留空间，再用剩余空间除以这张卡上每条请求占用的状态。举个小例子，两张卡各剩 12 GiB，等长请求在第一张卡占 3 GiB，在第二张卡占 2 GiB。前者能放 4 条，后者能放 6 条。同一请求必须经过两张卡，这组设备最多同时容纳 4 条。

BF16
16 位浮点格式，使用 8 位指数和 7 位显式尾数。指数范围接近 FP32，小数有效位更少。
combine
将各专家输出送回来源 rank，再按原 token 的槽位与权重求和。
CP
上下文并行。把序列位置分给多个设备，各设备处理自己的查询位置，并设法获得它们需要的历史信息。
decode
推理时利用已有状态生成后续词元的阶段。普通自回归生成中，每条序列每轮通常新增一个位置。
DSpark
DeepSeek-V4.1-Flash 的推测解码组件，生成候选后按置信度安排验证；实际交付数同时受验证结果和停止条件限制。
E4M3
由 1 位符号、4 位指数和 3 位显式尾数组成的 FP8 格式。具体有限最大值和特殊值还需核对采用的格式变体。
Engram
模型的条件记忆模块，根据输入相关索引取出记录并融合到隐藏状态。活跃读取量和总容量是两个不同指标。
FFN
前馈网络。Transformer 常对每个词元单独应用同一组通道投影与非线性，不在这一步混合不同位置。
FP32
32 位浮点格式，具有 8 位指数和 23 位显式尾数。在低精度乘法中常用作累加器或保存统计量。
FP4
一组 4 位浮点表示。很多实现需按一小组数共享尺度，比较容量和误差时必须连同尺度计算。
FP8
一组 8 位浮点格式。使用前应区分 E4M3、E5M2 等编码，并说明缩放因子和累加精度。
GDN
Gated DeltaNet，用门控与误差校正更新递归状态。其历史状态容量不必随每个新词元线性增长。
GEMM
通用矩阵乘法。左矩阵的行与右矩阵的列逐项相乘、求和，得到输出的一个元素；训练和推理中的线性层大量使用这种运算。
GiB
二进制容量单位，1 GiB 等于 1,073,741,824 字节；1 GB 按十进制等于十亿字节。
GQA
分组查询注意力。多组查询头各自共享一组键和值，可以减少解码时需保存和读取的 KV 数据。
guard
复用某份编译结果前，运行时检查的一组条件，例如形状、数据类型或某个 Python 值。检查失败可能触发重编译。
HBM
GPU 常用的高带宽显存，用于保存权重、激活和中间结果等数据。芯片与显存之间可持续传输的字节数会限制某些算子。
int4
此处是 CUDA 的四元素 int 向量类型，四个分量分别可保存一个索引。
KDA
Kimi Delta Attention。一种带门控的递推更新，每个头维护状态矩阵，用当前键和值修改状态，再由查询读出。
key
注意力中用来与查询匹配的向量。每个可见位置提供一个键，其分数决定同位置的值参与汇总的权重。
KiB
二进制容量单位，1 KiB 等于 1,024 字节。
KV
键和值的合称。一个历史位置通常既提供参与匹配的键，也提供按注意力权重汇总的值。
KV 头
共享一套键和值的注意力头。使用 GQA 时应按 KV 头数估算缓存容量。
logits
模型为词表中各个候选 token 输出的未归一化分数；经过 softmax 可得到概率。不同词表的同一数字编号不必指向同一 token。
LSA
NCCL 设备通信中的可直接装载与存储的地址访问路径，适用范围取决于对端内存与硬件互连。
Markov
马尔可夫假设，下一状态的分布在给定当前状态后无需更早历史。它只对模型明确选取的状态成立。
MHA
多头注意力。常见实现为每个查询头配一组独立的键和值，再把各头的输出拼接起来。
MiB
二进制容量单位，1 MiB 等于 1,048,576 字节或 1,024 KiB。
MLA
多头潜在注意力。模型把历史内容压到低维潜向量，后续计算按模型规定从该向量获得各头所需的信息。
MLP
前馈网络，在每个位置的通道维上施加线性变换和非线性函数。常见解码器先扩展通道再投影回残差宽度。
MoE
混合专家模型。路由器给每个词元挑选少数几个专家，由选中的网络计算，再按路由权重合并结果。
MQA
多查询注意力。在同一层中让多个查询头共用同一组键和值，以减少缓存容量及读取量。
MTP
多词元预测，训练时还预测后续若干位置。用它加速推理时还需要独立的验证、接受及缓存处理流程。
Muon
用于矩阵参数的优化器，对动量矩阵施加近似正交化。维度不适用这种更新的参数通常交给其他优化器。
OOM
内存不足导致分配失败。本节需要进一步定位失败发生在哪一次收集、缓冲申请或优化器更新。
prefill
推理时处理已有提示词的阶段。模型可以同时计算多个输入位置，并留下后续生成要读的缓存。
PV
注意力权重矩阵与值矩阵的乘积。在线计算时可以先用未归一化的权重累加分子，最后按行除以分母。
QK
查询矩阵与键矩阵转置相乘，结果的行对应查询、列对应键。除以头维平方根等缩放可在乘法前或后实现。
QSA
Qwen 对应混合模型中的注意力分支，与递归层穿插使用；估算历史状态时要按实际两类层数分别核算。
query
注意力中发起查询的位置或它的向量。它与各个可见位置的键相乘，得到对应的一行分数。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
Reindex
复用共享的索引键，在当前层根据自己的查询重选位置。
RoPE
旋转位置编码。它按位置在若干二维平面中旋转查询和键，使两者的点积包含相对位置带来的相位差。
SM100
Blackwell 数据中心 GPU 使用的一种目标架构。SM100 对应的指令与布局要求不能直接移用于所有 Blackwell 型号。
softmax
把一行分数先取指数，再各自除以这一行的指数和，得到总和为一的权重。实作时可先减去行最大值以免指数溢出。
SWA
滑动窗口注意力。一个查询只访问附近的历史位置，窗口外的依赖能否丢弃取决于模型其他层和状态。
tensor map
描述张量地址、形状、步长等信息的描述符，供支持的硬件搬运指令解释多维访问。
tile
计算时一次处理的一小块数据。划分 tile 可以让线程重复利用已搬进片上的数据，同时限制临时存储量。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
Top-K
按分数挑出最高的 K 项。排序稳定性、并列项和掩码会影响返回的下标，正确性检查需说明约定。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
value
注意力要汇总的内容向量。它与同位置的键配对，并按注意力权重计入输出。
临时张量
一次更新期间为中间计算额外分配的张量。操作结束后即便可释放，也可能在这一步把显存推到峰值。
位置分量
专门携带位置变化的那部分查询或键。不同位置的旋转通常不能一并吸收到一个固定内容投影中。
候选块
筛选时作为一个单位的一组原始位置。算候选上限时应将块数乘每块的位置数，再考虑越界及掩码。
元素数
张量各维长度的乘积。将它乘以每个元素的字节数，得到连续有效数据的大小，尚未计入对齐和分配器开销。
全局 KV
随历史保留、可由后续全局注意力访问的 KV 及对应模型口径中的索引状态。滑窗、工作区和分配对齐还需分别核算。
全局记录
为超过局部窗口的历史保存的可检索记录，生成它的层与读取它的层可能不同。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分数矩阵
一个头把每个查询与各个键分别点积后得到的矩阵。行对应查询位置，列对应键位置，完整存储的空间随两种位置数的乘积增长。
分数缓冲
保存候选位置分数的中间张量。按 query 分块可缩小一次需要驻留的行数。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
前缀命中
复用已经计算好的前缀 K/V。新增查询仍要读取掩码允许的前缀位置。
半字节
一个字节中的四个比特。解包格式必须指明先读取低四位还是高四位。
参数量
不同权重元素的总数；同一参数被多行、多次使用不会因此重复计数。
参考实现
优先保证计算语义清楚、结果可复核的对照实现。它与被测内核必须使用相同输入和掩码定义。
反量化
把低精度码结合尺度和可选零点，恢复到用于算术的数值。它可单独执行，也可融合到内核中。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
局部窗口
局部注意力层可读取的最近一段历史，缓存容量通常在窗口填满后停止随序列增长。
局部行号
某行相对于本请求在扁平缓冲起点的偏移，与请求的长期状态槽位是两套坐标。
工作区
算子在执行过程中为暂存中间数据而申请的区域。模型权重大小不变时，工作区仍可能随输入或算法改变。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
常驻
让已启动的工作单元在内核内部反复处理多个任务，而非处理完一块便退出。具体任务领取方式由程序决定。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
投影
此处指注意力与前馈层内的稠密矩阵乘。它按实际输入 token 行数重复执行，同一份权重可被多行共享。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
擦除门
调节旧关联被减去多少的系数。与写入门分开后，覆盖旧值和写入新值可各自控制。
时间压缩
把多个相邻原始位置编码成较少的历史记录，减少记录条数，与减少每条记录宽度是两种改变。
显存峰值
某一时刻所有同时存活的显存分配之和达到的最大值。不同阶段各自的最大分配量不能简单相加。
暂存
在训练状态继续变化前，先复制一份可独立读取的快照供后台写盘。暂存结束和检查点可供恢复是两个不同的完成时刻。
未归一化
保留各项加权和，同时单独记录权重之和；除以对应分母后才是可直接输出的加权平均。
权重吸收
借助乘法结合律，把对每个历史位置的投影移到当前查询或汇总结果上。
查询头
以一组 Q 通道独立计算注意力分布的头。多个查询头即使共用 K、V，也保留各自的打分和概率。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
模型卡
模型发布者给出的配置、使用条件和评测说明。复核模型层数、头数或权重精度时应同时核对相应版本的配置文件。
步长
某个坐标轴上的下标增加 1 时，物理地址要前进的元素数。换算成字节还须乘元素大小。
残差流
跨子层传递的一条隐藏表示；多流模型先组合它们供子层计算，再按系数写回。
流水线
把搬运、计算等相互依赖的阶段错开执行。不同数据块可以重叠，但消费某个块之前仍要确认它已准备好。
消费者
读取共享槽位数据并据此计算的一方。可以开始读，与生产者可以覆盖同一槽，通常由不同完成事件决定。
激活
模型处理本次输入时产生的中间张量。它的形状和寿命依赖批量、序列长度以及接下来是否需要反向传播。
激活参数
MoE 在处理当前 token 时实际走到的参数。估算一次前向时要考虑专家选择，估算所有权重的常驻容量仍要计入未被本 token 选到的专家。
物化
把一个中间结果完整写到可供后续算子读取的存储中。融合可以让一些中间值只存在于片上。
状态快照
保存某个已知 token 边界的完整递归状态。拒绝草稿后可从该边界恢复，再重放仍须保留的位置。
稳定 softmax
在求指数前，从一行所有合法分数中减去同一个最大值。分子和分母同时缩放，概率不变，指数溢出的风险降低。
线性投影
用一组可学习的权重对输入分量加权求和。不同的权重矩阵可把同一输入分别映射为 Q、K 和 V。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
视图
共享底层存储但拥有自身形状、步长和偏移的张量表示。释放其中一个视图时，其他持有者仍可能让整块存储无法回收。
词表
记录 token 与整数编号对应关系的表。词嵌入矩阵使用同一套编号查行，每行才是模型参与运算的向量。
输出投影
拼接多个头的输出后再做一次线性变换，使同一位置可以混合来自不同头的特征。
递归状态
前一步计算留下的汇总量，读取后与当前输入一起形成下一步的状态。
通道缩放
对一个输入通道除以某个系数，同时对相应的权重通道乘该系数；实数线性层输出相同。
逻辑位置
某个 token 在这条请求中的序列下标。它决定所查的旋转角，搬动保存该 token 的物理页不会改变这个下标。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
重放窗口
从保存的边界重新执行一段已知 token 以恢复状态。边界缺少必要依赖时，这种恢复会引入近似。
量化
用有限个离散码近似表示原数值。尺度、零点和分组方式决定恢复后的数值及误差。
门控
用一条分支算出的输入相关系数，逐通道乘到另一条分支上。系数由输入决定，常规稠密实现仍会执行两个投影。
隐藏宽度
每个位置进入下一层时保留的特征通道数，通常记为 D。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
页表
把逻辑位置所在的页映射到实际存储块的结构。在 KV 分页中，连续的逻辑位置未必位于连续的物理页。
预取
在后续层开始计算前就发起参数传输。预取越早，计算等待参数的时间可能越短，但完整参数与当前层数据同时占用显存的时间也可能越长。
驻留
线程块已获得在 SM 上运行所需的寄存器、共享内存和调度名额。块被接纳后，其线程仍可能等待数据。
