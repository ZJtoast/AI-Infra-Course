1　集合通信、逐元素求和与结果分片

四张卡各算出一部分结果，下一步却要用四份结果的和。可以让四张卡共同执行一次通信，约好哪些卡参与、哪些位置相加，以及最后谁拿到结果。这样由一组成员共同参加的操作叫集合通信。推理时可以用它合并分在不同卡上的矩阵乘结果，训练时可以用它合并梯度。

通信组给每个参与者一个编号，叫 rank。在每个进程管理一张 GPU 的例子里，rank 0 和 rank 1 分别持有 [1,4] 和 [3,2]。按相同位置求和得到 [4,6]，再让两人各拿一份，这次操作就叫求和 AllReduce。若训练要对两个等大小批次求平均，两边还要各自把结果除以 2。

一个 rank 只看到了本地样本的梯度。若各自更新，模型副本下一步就会分叉。全员归约使每个副本拿到相同的合并梯度，再按约定的平均方式和同一优化器状态更新。

一组数据并行训练任务中，四个训练进程各自保存一份相同的模型，各自处理一份样本并产生本地梯度。若各份样本数相同、每个本地梯度已按本地样本求平均，四份梯度求和再除以 4，才得到这一步的全局平均梯度。AllReduce 的 SUM 只负责求和；除法由框架或指定归约操作承担。各 rank 有效 token 数不同时，还要按实际权重处理，简单平均各 rank 的局部均值会改变训练目标。

若两个 rank 的有效样本数是 1 和 3，本地平均梯度分别为 10 和 2，对两个均值直接平均得到 6。按四个样本等权的结果却是 10+3×24=4。AllReduce 的 SUM 只对交给它的元素求和；样本权重由调用方在归约前后安排。

rank 是 communicator 内的逻辑编号；communicator 定义参与者集合及对应通信资源。它与机器编号、GPU 物理编号、CUDA_VISIBLE_DEVICES 后的逻辑设备编号属于不同坐标系。常见训练配置是一进程一 GPU，communicator 标识共同参与通信的一组 rank。不同 DP、TP、EP 分组可以让同一张 GPU 在多个 communicator 中拥有不同 rank。

2　Ring AllReduce 的分片传输

四张卡各存有八个数。要把相同位置的四个数相加，再让每张卡都拿到八个和，可以把四张卡首尾相接，组成一个环。沿环传递时，把八个位置分成四片，每张卡负责算完其中一片。这样，四条边可以同时传不同位置的数据。这就是环形全归约（Ring AllReduce）。

3　消息大小与通信耗时

上一节的四张卡要走六轮才能收齐结果。即使每片缩到一个数，下一张卡也得等这个数到达，才能加上自己的数再往前传。每轮通信要花两笔时间。第一笔是每轮都要付的固定延迟，记作 α。第二笔随消息变大而增加，把每字节用时记作 β，发送 n 字节就需 α+nβ。下面用恒定的单向速率估算，假定链路没有拥塞，且本地加法所花时间很短。

P 个参与者将 N 字节分为 P 段。环的归约分散阶段走 P−1 轮，每轮每个 rank 发 N/P 字节，全收集再走同样多轮。用 α 记每轮固定时间，用 β 记每传一个字节的时间，两段的启动次数与传输字节数可分别相加。

Tring ≈ 2(P-1)α + 2P-1PNβ

教学条件取 P=8、α=3μs、有效单向带宽 25 GB/s，β=125×109sbyte。N=256MiB 时，每片 32 MiB，十四轮中每个 rank 发送 448 MiB，传输项约 18.790 ms，加 42 μs 启动项后为 18.832 ms。N=4KiB 时，每片 512 B，十四轮共发 7168 B。用 7168 B 除以每秒 250 亿字节，传输项只有约 0.287 μs，模型时间约 42.287 μs，主要由轮次决定。

还有一种减少等待轮次的办法。以八张卡为例，第一轮让四对卡分别相加，留下四份部分和。第二轮合成两份，第三轮再合成一份。把总和沿原路发回去，三轮就能交给全部八张卡。与环形算法相比，这个例子少等了八轮，但每一对卡都要发送整份数组。

设 P=2k，按两两配对的方式做树形归约，关键路径需经过 k=log2P 级，广播再走 k 级。若每一级都要完整传输 N 字节并等待完成，耗时约为 2log2(P)(α+Nβ)。八 rank、4 KiB 的同一假设给出约 18.983 μs，比 Ring 的启动项小；大消息下，这个朴素树模型却会重复经过更大的关键路径数据量。

Tsimple tree ≈ 2log2P(α + Nβ)

实际使用的 NCCL 会把大消息分块。上一块离开中间节点后，下一块就可以接着传。双树算法还让不同节点分担转发工作。因此读性能曲线时，小消息先看有多少轮必须前后等待，大消息再看链路能否持续传数据，以及哪张卡承担了最多转发工作。

ReduceScatter 和 AllGather 的 Ring 单阶段每 rank 发送量各为 (P−1)NP，这里的 N 指完整数组大小。两者 count 语义不同，却可用相同完整数组尺度计账。对于 AllToAll，若每对 rank 交换 m byte、把本地自拷贝单独处理，每 rank 外发 (P−1)m byte；所有目标同时注入流量时，交换网络的二分带宽和热点也会进入关键路径。

若一次消息的固定延迟为 5 µs，有效速率 10 GB/s，每微秒可传 10000 B。每条 10000 B 的消息传数据要 1 µs，两条串行发送需 2×(5+1)=12 µs。若能把两段合成同一条，需 5+2=7 µs。前提是两段都已就绪且下游不依赖第一段先到；若合包等待推迟关键消费者，节省的传输时间可能被等待合包的时间抵消。

跨节点 AllReduce 的分层归约

把四张 GPU 分装在两台服务器里，每台两张。来自不同服务器的数据要经过网卡，同一台服务器上的两张卡可以先用机内链路交换。利用这一点，各卡先把能在本机算的和算出来，再把部分和发到另一台服务器。这种按连接位置安排求和的做法叫分层归约。

以两个位置的梯度为例。服务器 A 的两张卡分别存着（1，10）和（2，20），服务器 B 的两张卡分别存着（4，40）和（8，80）。机内先做 ReduceScatter。每台的第一张卡负责第一个位置，A 算出 3，B 算出 12。第二张卡负责第二个位置，A 算出 30，B 算出 120。这样分工，每个位置在每台服务器上只留下一份待交换的部分和。

两台服务器的第一张卡相互发送 3 和 12，都得到 15。第二张卡相互发送 30 和 120，都得到 150。到这里四张卡各自只有一个位置的答案。两台服务器分别在机内做一次 AllGather，各自把 15 和 150 拼回原顺序，现在每张卡都得到（15，150）。

这次跨机传输，每台服务器向对端发了两个数。如果两张卡都把自己的原数组发过去，每台就要发四个数。省下跨机流量的代价是增加机内交换，实际耗时取决于两级链路的速度。NCCL 根据设备的连接关系安排集合通信。选用 RDMA（远程直接内存访问）传输时，网卡负责在两台机器已登记的缓冲区之间搬运数据。例中的 15 和 150 要经过归约才会产生。

反向传播中的梯度分桶与归约

训练时，同一份模型放在四张卡上，每张卡处理不同的样本。各卡算出的梯度通常不同。为了让四份模型同步更新，训练框架先把相同参数的梯度求和，再按训练所用的平均方式缩放。把几个参数的梯度排在一段连续的缓冲区里，一起交给 NCCL 传输，这段缓冲区就叫梯度桶。

设每张卡上最后一层的梯度在第 2 毫秒算完，前一层到第 5 毫秒才算完。把它们装进同一个桶，通信最早到第 5 毫秒才能开始。分开装，第一桶在第 2 毫秒就可以发起归约，接下来三毫秒的计算就有机会与通信重叠。拆桶也会多付一次启动开销，上一节用小消息测出的延迟在这里就用得上。

四张卡先加入同一个通信组（communicator），各自在组内有一个编号（rank）。框架约定每轮处理哪个桶，四个 rank 按同一顺序提交 AllReduce，指定相同的元素数、类型和求和操作。提交后，操作进入 GPU 的执行队列（CUDA stream）。若优化器在另一条队列上读取这个桶，就要先等归约完成，否则读取时桶里的数可能还在更新。

选 Ring 作教学例，先 ReduceScatter 聚合各块并确定所有者，再 AllGather 分发完成的块。若每份输入为 M 字节，四卡时每 rank 单向发 2×(34)M=1.5M。拓扑、消息量、协议和实现可能使 NCCL 选择不同算法与路径。若一张卡算梯度晚，其他卡的 NCCL kernel 区间可提前开始等待，先比较到达点，再核对每字节代价。

NCCL · communicator 以及 rank 与设备的对应

以只有两张卡的通信组为例。rank 0 的第二桶装的是权重 B 的一个梯度 2，rank 1 却把权重 C 的梯度 30 装在同一位置。通信库会把这两个数加成 32。两张卡的元素数和类型都对，问题出在各卡给“第几轮、第几个位置”安排了不同的参数。核对桶的参数顺序，才能查出这种错配。

5.1　GPU 与网卡的配对及端口带宽共享

两张网卡速度相同，GPU 到它们的路却可能一长一短。一条路只经过本地 PCIe 交换设备，另一条还要跨过两个处理器插槽之间的互连。给一张 GPU 选网卡时，先沿上一节的图找它们之间要经过哪些设备。

假设一台服务器有八张 GPU，两边各有一个 CPU 插槽和一张 400 Gb/s 网卡。GPU 0 至 3 靠近网卡 A，GPU 4 至 7 靠近网卡 B。把前四张卡全配到 B，要与后四张卡争同一个出口，还可能挤占处理器之间的互连。把前四张卡配回 A，可以缩短路径，并把发送流量分到两个端口。

如果每台服务器都这样分成两组，还可以把各台的网卡 A 接入一套交换网络，把各台的 B 接入另一套。这种按网卡位置分开的网络通路称为 rail。分层归约时，本机先把部分和拆给两组，再让两组分别沿所属通路跨机发送。要估每条通路的负载，看实际分给这组的字节数。

6　RDMA 的缓冲区登记、请求与完成通知

上一节沿网线追踪了字节，这里看程序怎样告诉网卡搬哪一段。假设一条消息占 64 字节。源端得指出这 64 字节放在哪里，目标端要留好可写的空间。两端各把相应的内存范围登记给网卡，得到一个已注册内存区（MR）。

程序通过 verbs 接口提交传输请求。请求里的一项本地缓冲描述称为 SGE，填写起始地址、长度和本地访问键（lkey）。例如一个 256 字节的登记区中，从偏移 32 开始发 64 字节，网卡实际读取偏移 32 至 95 的字节。保护域（PD）把内存区和可以使用它的队列等资源关联起来。若使用 RDMA WRITE，还要由对端提供目的地址与远程访问键（rkey），使网卡能核对目的范围和写入权限。

11　NVSHMEM 的对称内存与远端寻址

NVSHMEM 是让程序直接读写其他参与者内存的通信库。每个参与者称为一个处理单元（processing element，PE）。假设 PE 0 和 PE 1 各有一个同样布局的整数数组，PE 0 想把 7 写入 PE 1 的第五格。它给出自己数组中第五格的位置，再指定目标为 PE 1，库就能定位对方数组中的对应位置。这里“对称”指各方都有彼此对应的对象。

NVSHMEM 把各处理单元（PE）的对称内存组织成一个按 PE 分区的全局地址空间。每个 PE 对应自己的存储，远端访问通过“本 PE 得到的对称地址+目标 PE 编号”描述。nvshmem_malloc 是 collective 分配，参与者按相同分配顺序和大小建立对应对象。返回指针可用于本地访问；它的数值不需要在各进程中相同，也不能把另一 PE 返回的原始指针直接拿来本地解引用。

12　CFT 的跨卡传输与到达字节计数

15　计算通信重叠与资源争用

设一张 GPU 刚算好一桶梯度，还要继续算前一层。如果现在就启动这一桶的归约，下一层计算与本桶通信可以同时进行。直到优化器要用这两项结果时，较晚完成的那项才决定它何时能够开始。比较并发和串行，要量的就是从启动到这个汇合点的时间。

并行的机会来自数据依赖。前一层的反向计算可以用自己的输入继续算，因此能与已经就绪的梯度通信重叠。专家层则不同，某位专家要处理的词元还在路上时，它对这一批词元的矩阵乘法就得等。若另一个专家的数据已经送齐，可以先调度那个专家。

通信时间为 C，可与通信并行的计算时间为 I，工作 D 必须等待 C 与 I 都完成。在无资源争用的理想情况下，总时间由 C+I+D 降至 max(C,I)+D，暴露的通信尾部为 max(0,C−I)。这里的 I 必须在不读取未完成通信结果的前提下执行；把依赖 GEMM 放到另一条执行流 并不会使依赖消失。若 D 只依赖 C，且可继续与 I 并行，则该图的理想总时间应为 max(C+D,I)。判断 overlap 要先画出实际依赖，根据依赖图分别累加串行区间、合并重叠区间。

Tserial = C + I + D,    Tideal = max(C,I) + D

Cexposed = max(0,C-I)

教学例取 C=3ms、I=5ms、D=2ms，串行为 10 ms，理想重叠为 7 ms。若并发后通信占用 SM/HBM 使 I 变为 7 ms、通信本身变为 4 ms，总时间变为 9 ms；若 I 被拖到 8.5 ms，则为 10.5 ms，已经慢于串行。对照同一负载的 10 ms 串行基线，9 ms 的调度省了 1 ms，10.5 ms 的调度反而多用 0.5 ms。

三种教学调度按同一时间比例绘制。并发后的资源争用会改变每段耗时。

bucket 小，通信可更早开始，但每次固定开销和消息数更多；bucket 大，链路利用率可能提高，却必须等更多梯度准备好，可能在反向末尾留下更长尾巴。分块通信也有类似折中：细粒度结果更早就绪，但元数据、通知和同步次数增加。对于只支持整块完成的接口，不能擅自消费其中“看起来已到”的一部分。

通信内核在等信号时也可能占着 GPU 的计算单元（SM）。若发出信号的计算内核迟迟分不到资源，时间线上就会出现通信一直等、计算一直未启动的局面。调整通信线程块数、给计算预留执行资源之后，应再量两项工作都完成的时刻。

17　通信缓冲区的生存时间与显存峰值

把每一块显存画成时间线上的一段。左端是分配，右端是所有读写结束、空间可以复用的时刻。在同一时刻穿过几段，就把这几块各自占用的字节数相加。沿时间线找到的最大值，就是这些缓冲区共同造成的显存峰值。

以四卡保存一层参数为例。平时每张卡只保留四分之一，需要整层参数做计算时，再用 AllGather 把各片收齐。通信结束后，计算仍在读取整层参数，因此目的缓冲区要保留到计算读完为止。若这期间又启动梯度归约，梯度缓冲区也会占用显存。

每卡已经持有 1 GiB 参数分片，另分配 4 GiB AllGather 目的缓冲，并为梯度归约保留 2 GiB 独立桶。如果三者同时存活，本例峰值就是 7 GiB；若可在收集目的缓冲释放后才建梯度桶，两阶段峰值为 max(1+4,1+2)=5GiB。按 stream 完成依赖确定各自何时真的可释放，再比较是否值得用峰值换重叠。

在这个例子里，错开分配省下的是 2 GiB。代价取决于等这 2 GiB 时推迟了哪项计算或通信。把两种安排的缓冲区释放事件和下一步启动时刻放在一起，就能同时量出显存差和时间差。

LSA

MiB
二进制容量单位，1 MiB 等于 1,048,576 字节或 1,024 KiB。

NCCL
NVIDIA 的 GPU 通信库。它提供集合通信和点对点接口，并根据设备拓扑和可用链路组织传输。

rank

ReduceScatter

散布聚集表中的一个条目，描述一段数据的地址、长度与本地访问键，供网卡按列表读取或写入。

流式多处理器。NVIDIA GPU 在 SM 上驻留线程块并调度其中的 warp，寄存器和共享内存会限制可同时驻留的块数。

Blackwell 数据中心 GPU 使用的一种目标架构。SM100 对应的指令与布局要求不能直接移用于所有 Blackwell 型号。
stride
张量步长，指某一维下标增加一时，线性地址跨过的元素数或字节数。比较时须先确认单位。
tile
计算时一次处理的一小块数据。划分 tile 可以让线程重复利用已搬进片上的数据，同时限制临时存储量。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
Top-K
按分数挑出最高的 K 项。排序稳定性、并列项和掩码会影响返回的下标，正确性检查需说明约定。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
Transformer
用注意力混合不同位置的信息，再逐位置通过前馈网络。一个解码器通常把多层这样的计算依次连接起来。
WR
提交给 RDMA 队列的工作请求，包含操作类型、数据段和所需的远端信息。
互连
设备间传输数据的链路及交换结构。比较系统时要区分片内、单节点内与跨节点的范围。
信号
收发双方约定的完成标记。生产者更新标记前，要把标记与相应代的数据写入建立正确顺序。
元素数
张量各维长度的乘积。将它乘以每个元素的字节数，得到连续有效数据的大小，尚未计入对齐和分配器开销。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
内存注册
把一个内存区间及其访问权限登记到 RDMA 设备，使网卡能够校验并执行对该区间的 DMA 操作。
冗余专家
在其他 rank 放置同一专家的权重副本，让多个执行位置分担它收到的 token。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
到达偏斜
各 rank 进入同一集合通信操作的最早和最晚时刻之差，须在可对齐的时钟上计算。
参数分片
把一个逻辑参数拆到多个 rank 保存。若一次运算需要整个矩阵，就要显式恢复其布局或跨卡协作。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
固定延迟
即使载荷很小，一轮通信也要为发起、传播和协议处理付出的时间。多个依赖轮次的固定开销会累加。
固定提交
用 Git 提交哈希锁定本课所引用的源码版本，避免行号随主分支变化。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
地址空间
PTX 用来区分全局内存、共享内存等存储区域的寻址范围。相同位模式放到不同空间中未必指向同一个对象。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
完成事件
通信流记录的完成标记。其他 CUDA 流须建立对该事件的依赖后才能使用相应结果。
对称内存
各 PE 按约定共同分配的对应内存对象。远端操作通常以本地对称对象加目标 PE 标识指定目的地。
屏障
程序中规定的同步点或状态。哪些线程或设备必须到达，取决于屏障的参与范围和约定的完成条件。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
常驻
让已启动的工作单元在内核内部反复处理多个任务，而非处理完一块便退出。具体任务领取方式由程序决定。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
扇出
一个源 token 实际需要发送到几个不同的目标。计算节点间流量时，按不同远端节点计数。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
时间线
将不同线程、CUDA 流及设备活动按时间展开，可结合事件与请求编号追踪先后依赖。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
显存峰值
某一时刻所有同时存活的显存分配之和达到的最大值。不同阶段各自的最大分配量不能简单相加。
暂存
在训练状态继续变化前，先复制一份可独立读取的快照供后台写盘。暂存结束和检查点可供恢复是两个不同的完成时刻。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
消息大小
一次集合通信中每个进程交给接口的逻辑载荷字节数。实在线路上传输的总字节数还与算法、参与数有关。
消费者
读取共享槽位数据并据此计算的一方。可以开始读，与生产者可以覆盖同一槽，通常由不同完成事件决定。
目标 rank 去重
同一个 token 的多个专家位于同一个目标 rank 时，先只发送一份输入，再在目标端展开。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
线程块
一次内核启动中的一组协作线程。块内线程可以使用同一片共享内存，并在块级屏障处等待彼此。
线程组
为了搬运、发出矩阵指令或等待结果而协作的一组线程。组的大小和角色由内核及所用指令规定。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
缓冲复用
多次任务使用同一块内存。在先前读取完成之前覆盖它，可能使旧任务读到新内容。
融合
把原本分开的若干运算放到同一内核中执行，使中间值有机会直接从寄存器或共享内存传给下一步。
视图
共享底层存储但拥有自身形状、步长和偏移的张量表示。释放其中一个视图时，其他持有者仍可能让整块存储无法回收。
载荷
应用需要传送的数据。协议头、编码开销和重传都会占用链路，有效载荷只统计应用数据本身。
速度比
完成相同有效工作量时，原耗时与新耗时之比。若按输出速率计算，则用新速率除以原速率。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
队列对
RDMA 端点上的发送队列和接收队列组合，简称 QP。应用将工作请求提交到队列，由网卡处理。
零拷贝视图
借用现有缓冲区的一种张量表示。没有另行复制数据，使用者须在底层缓冲仍有效时读完它。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
预取
在后续层开始计算前就发起参数传输。预取越早，计算等待参数的时间可能越短，但完整参数与当前层数据同时占用显存的时间也可能越长。
饱和
超出可表示范围的数值被夹到最近端点，恢复时无法区分它原先超出了多少。
