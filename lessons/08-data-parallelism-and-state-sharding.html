1　从两份模型开始理解数据并行与 DDP

PyTorch 的 DistributedDataParallel（DDP）给模型副本加上梯度同步。每个进程读不同样本，独立做前向和反向；到了需要合并的位置，通信组把同一参数的各份梯度归约，然后各自按相同规则更新。先用一个权重走完这条链。

两张卡都从权重 10 开始，各用同样多的不同样本训练。若得到梯度 2 和 4，合起来的平均梯度是 3；用学习率 0.1 做一步普通梯度下降，两边都会更新为 10−0.1×3=9.7。数据并行把样本分给不同副本，再让各副本用同一个梯度继续训练。若两张卡各用自己的梯度直接更新，得到的会是 9.8 和 9.6，下一轮的起点就分开了。

梯度同步只能让副本接下来得到相同的增量。若起始参数已经不同，把同一增量加到两边并不会消除原差值。因此首次前向以前就要建立参数一致性，恢复训练还要核对优化器状态。

数据并行训练中，每个 rank 持有相同的一组参数，读取分给自己的样本，再计算这些样本对各参数的梯度。若起始参数、optimizer state 和超参数相同，所有 rank 又用相同的聚合梯度执行确定的更新，那么它们可以各自更新出相同参数。常规 DDP 每步主要同步梯度，无需每次把完整更新后权重重新广播一遍。初始化同步、buffer 同步和用户自定义通信需要另行区分。

2　梯度就绪与归约顺序

DDP 为梯度注册就绪钩子（hook），并把多个参数的梯度编入同一个通信桶（bucket），以便合并归约。一层梯度就绪时，只说明这一层的贡献完成；只有 bucket 内所有必要梯度都就绪，才能归约该 bucket。bucket 过小增加启动与消息开销，过大又推迟发起时间。bucket 内还要考虑 dtype、device、参数布局和真实反向次序。

DDP 重叠通信的最小单位通常是一桶梯度。假设同一桶的两个参数分别在 4 和 11 ms 产生梯度，即使第一项已经写完，整桶也要等到 11 ms 才具备本地就绪条件。若另一桶在所有 rank 都早就绪，集合操作仍要遵守各 rank 一致的启动顺序。缩小桶可能提前第一轮通信，也可能增加许多小消息的固定启动开销。对照时记录每桶最后一项梯度的就绪时刻、集合启动和结束，才能区分桶内等待、跨卡偏斜和链路耗时。

3　梯度累积与 no_sync

如果一次更新要累加四个微批次的梯度，那么先在本地求和、再在最后一次反向通信，可以少发前三轮归约。使用 no_sync 时要让相应前向和反向处于约定范围，最后一轮的梯度再与本地累积一起参与同步。

假设每个 rank 连续处理 K 个微批次，前 K−1 次只累计本地梯度，最后一次再把累积结果归约，可以减少重复通信。optimizer 仍在整个窗口结束后更新一次，loss 权重按第 13 课的有效 token 规则处理。no_sync 改变梯度归约时机，不能自动消除模型内部 TP collective、SyncBatchNorm 或用户显式通信。

6　用 PyTorch FSDP2 在计算一层时凑齐权重

完全分片数据并行（FSDP）让卡平时各存模型的一部分。假设两层各有四个权重，两张卡各保管每层两项。要跑第一层，两卡先交换第一层缺的两项；第二层仍保持分片。用完这一层可以释放完整副本，然后轮到下一层。FSDP2 把这套收集、计算、再分片的行为附到选定模块上。

FSDP2 的 fully_shard 在模块上附加分片行为。本组参数未参与当前计算时，通常以 DTensor 表示逻辑全局形状与本地 shard；执行模块计算时，AllGather 恢复该组需要的完整参数，供原来形状的算子使用。这里的参数分片主要改变存储时机；一个常规线性层仍在本 rank 计算完整输出，后续 TP 才进一步切分层内计算。

例如 W 的逻辑形状为 [8,4]，沿第 0 维分到四个 rank，各持 [2,4]。本 rank 要执行原来依赖整个 W 的矩阵乘时，需要取得另外三片。DTensor 的全局 shape、placement 与本地 storage 是不同层次，不能看到本地 [2,4] 就把模型层的逻辑权重形状改掉。

每次 fully_shard 调用定义一个通信组，包含模块中尚未被更早子模块调用管理的参数。因此通常从子 block 向根模块处理：block 各有自己的聚集/归约组，最后根模块接管 embedding、输出头等剩余参数。只给整个模型调用一次，可能在前向前聚集全部参数，把分片的峰值优势大幅削弱。

FSDP1 常用 FlatParameter 作为管理对象；FSDP2 保留逐参数 DTensor 与原有 FQN，便于冻结、混合精度与 state dict 映射。通信时仍会打包多个参数以降低启动成本。optimizer 应在应用分片之后建立，以管理正确的参数对象。

初始化本身也可能超容量。meta device 先描述 shape 和布局，再分配或加载本地 shard，可以避免先在每张卡构造一整份大模型。meta tensor 没有真实权重值；所有 rank 仍需得到相互一致的全局初始化或通过 checkpoint 恢复。

同一名称的参数在 state dict 可携带全局 shape=[8,4]，本 rank 实际持有的存储却可能只有 [2,4]。若用全局元素数乘 dtype 来估此 rank 的常驻字节，会多算四倍；若用本地 shape 推导下一次完整线性层的数学输出，又会低估工作。先标明查询的是逻辑元数据还是 local shard。

8　参数预取与显存峰值

提前收集下一层参数可以让通信藏在当前层计算期间。提得越早，两层完整参数同时驻留的时间就越长。若当前层的计算已足以覆盖通信，继续提前通常只会延长重叠占用。

把每组完整工作权重记为 Wi，常驻状态分片的总大小记为 S。在某一时刻，当前组的完整参数、下一组已经到达的参数、AllGather 打包区、当前梯度和 ReduceScatter 输入都可能共存。预算可以按实际独立 storage 逐项相加，再沿时间轴取最大值。

教学例假定 S=10GiB，当前组完整参数2 GiB，预取的下一组2 GiB，梯度归约缓冲3 GiB，激活4 GiB，其他工作区1 GiB，且这些 storage 互不别名，则当前为22 GiB。再预取一组相同权重使其变成24 GiB。预取减少暴露的等待，需要以增加驻留为代价；若当前计算短于通信，再多预取也受网络吞吐限制。

9　计算、归约与累积精度

开启 FSDP 的模块级混合精度后，优化器可用高精度的常驻参数分片完成更新；AllGather 和模块前向则可以使用低精度的工作参数。这里持久 FP32 shard 已承担高精度更新角色；无需机械再加一份“master shard”。输入输出张量在模块边界转换类型。模块内的算子采用哪种计算精度、梯度通信采用哪种归约精度，仍须分别检查。这与 autocast 按算子选择精度的方式不同。

10　FSDP 梯度累积的显存代价

PyTorch 的全分片数据并行（FSDP）让各卡分摊训练状态。平常某层做完反向，可以立即合并梯度，让每张卡只保留自己负责的分片。现在一轮更新要连续做几个微批的反向。把合并动作推迟到最后，可以少做通信，但中途完整的梯度就要多留一会儿。

set_requires_gradient_sync(False) 会推迟 FSDP 的梯度归约。暂缓梯度同步期间，各微批次的贡献先保存在完整梯度中。恢复同步后，ReduceScatter 才会将这些贡献归约，并把各分片交给对应的 rank。因此同样是“累积K次”，DDP 本来就有完整梯度，FSDP 却可能从分片梯度变回完整梯度，额外显存相当可观。

13　用 PyTorch DCP 在不同卡数下恢复权重

PyTorch Distributed Checkpoint（DCP）把一次并行训练的状态按张量名字和全局区间登记，再按当前任务需要的区间安排读写。例如旧分片保存 [0,4) 和 [4,8)，新任务需要 [2,6)，就从前一片读第 2、3 项，从后一片读第 4、5 项，依序放进目标缓冲。

八张卡存下的分片无法仅凭旧 rank 号交给四张新卡。同一个权重在两次运行中仍有稳定的全局坐标，读取方根据新目的区间与旧分片的交集读取数据，才能在并行度变化后恢复同一张量。

分布式检查点按逻辑张量名和全局形状识别参数。每个已保存的数据块还记录它在全局张量中的起始位置和长度，加载器据此定位文件内相应的字节。FQN 是模型中的完整参数路径，例如 layers.3.attention.wq.weight；它标明参数在模型中的位置。某个 rank 保存了该参数的哪一片，则是这次布局的属性。

FSDP 另有 reset_iter_state 处理一次 forward/backward 异常后的迭代内部状态，恢复流程需要丢弃失败迭代的梯度和未完成的累积状态。它不会凭空恢复丢失设备上的 optimizer 数据，也不保证一个已经失败的 NCCL communicator 自动可用。普通 checkpoint 重启、进程组修复和应用状态一致化应分别验收。

只重载权重而保留幸存 rank 旧 moments，或者新 rank 从不同 step 的 checkpoint 加入，都会破坏共同更新前提。故障恢复测试至少需要检查所有 rank 的 step 一致、状态片完整、下一批数据规则明确，并验证后续一次更新的结果；一次 barrier 成功返回，只能确认进程到达了同步点。

16　按显存耗尽或停顿发生的时刻追查训练

若在前向计算前收集完整参数时显存耗尽，检查组是否太大、是否重复保存全量初始化副本、预取是否过深；若 backward 尾部 OOM，检查完整累计梯度、ReduceScatter 输入和在途 AllReduce 缓冲；若首次 optimizer.step OOM，检查本地 master/moments 与临时更新空间；若保存时 OOM，检查 staging 副本、全量 state dict 聚集和多份在途快照。

比较 DDP、ZeRO 与 FSDP 时，应固定模型、训练目标、有效 token 数量、精度与 optimizer 数学行为。分别记录首次与稳态峰值、参数聚集时间、梯度归约尾部、整步时间、初始化和保存开销。配置差异若连 moments 精度或 loss 归一化都改变，就无法把结果全部归因于分片算法。

正确性先用可识别来源的小输入验证，再对参数更新、梯度和恢复后的状态建立允许误差。不同归约顺序与精度可能产生舍入差异；若要求位级一致，需额外限制算法、拓扑、样本顺序和随机源。本文提供源码与可复算模型，没有把估算数据写成多卡实测。

一个 rank 的 AllGather 条很长，可能因它比其他 rank 更早进入。先比较同一组、同一轮所有成员的进入点，以及最后一个成员到场后的共同尾段。上游计算迟到与本轮传输确实变慢对应两组不同的时间戳，不能只按最长条决定调哪一层。

17　状态分片与并行维度

同一组卡可以承担不同角色。数据并行轴上，各个模型副本读取不同样本。数有效全局批量时，要把这些副本处理的样本相加，用来分片参数的轴决定每卡常驻状态。若只按总卡数除显存、再按同一个总卡数乘 batch，协作处理同一样本的 rank 就会被重复计算。

在多维设备网格中，保存某段参数的 rank，不一定就是最终负责那段输出的 rank。为两者分别标注布局，即可确定中间需要哪种集合通信。

以 Y=XW 为例。把 W 按输出列交给两个 rank，若 X 在两边均可见，各自已经得到对应列的完整 Y 值，下一层可接受列分片就无需收齐。把 W 按输入行分给两边且 X 也按该轴切分时，两边得到同形的部分和，必须在需要完整输出时相加。这两种“权重各半”有相同静态容量，却要求不同的通信。

本课术语
Adam
同时估计梯度一阶矩与二阶矩的优化器，按分量调整步长；需要区分状态、梯度与权重各自的精度。
AllGather
把各进程持有的数据分片收集起来，让每个参与进程得到按约定顺序排列的完整张量。
AllReduce
在各个参与进程的对应元素上做求和等归约，然后让每个进程都得到完整结果。
API
供程序调用的接口。函数返回、设备执行结束和远端可见可能发生在不同时间，应按接口的约定判断。
BF16
16 位浮点格式，使用 8 位指数和 7 位显式尾数。指数范围接近 FP32，小数有效位更少。
DCP
在分布式检查点中，DCP 指 PyTorch Distributed Checkpoint；在推理解码并行中，这个缩写也可指 decode context parallel。含义由本节讨论的对象决定。
DDP
PyTorch 的分布式数据并行封装。各进程本地执行前向和反向，并在约定的时机归约梯度，使后续优化器更新可以保持一致。
DDP
PyTorch DistributedDataParallel。各进程持有模型副本，将本地梯度按桶组织并跨进程归约。
DP
数据并行。各进程处理不同训练样本，再同步梯度等状态，使更新对应于同一个全局批次。
DTensor
把一个逻辑全局张量与各设备的局部张量、设备网格和布局关联起来的分布式张量表示。
FP32
32 位浮点格式，具有 8 位指数和 23 位显式尾数。在低精度乘法中常用作累加器或保存统计量。
FQN
参数或缓冲区在模型中的完整限定名，例如由模块路径和参数名拼接而成。按名称定位逻辑张量，可在进程数变化时重新计算所需分片。
FSDP
完全分片数据并行。模型参数等训练状态在组内分片；模块计算前暂时收集所需权重，计算结束后按策略释放。
GiB
二进制容量单位，1 GiB 等于 1,073,741,824 字节；1 GB 按十进制等于十亿字节。
GPU
图形处理器，使用大量线程并行处理数据。需要许多独立运算或数据复用时，它常比逐项在 CPU 上执行更合适。
HSDP
混合分片数据并行。在一组设备内分片，再在不同组之间复制对应分片，分别沿两种通信组同步。
key
注意力中用来与查询匹配的向量。每个可见位置提供一个键，其分数决定同位置的值参与汇总的权重。
NCCL
NVIDIA 的多 GPU 通信库，负责组织集合通信和点对点传输。它会根据参与设备、消息与拓扑选择可用路径。
OOM
内存不足导致分配失败。本节需要进一步定位失败发生在哪一次收集、缓冲申请或优化器更新。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
ReduceScatter
先跨进程归约对应元素，再把归约后的结果按约定分片，每个参与者只留下自己负责的部分。
RNG
随机数生成器，其状态决定后续的随机序列。重算和训练恢复需要保留与本次操作对应的随机状态。
SGD
随机梯度下降，用小批次估计的梯度更新参数，可再配动量项。每次更新究竟用了哪些样本，取决于梯度累积和归约。
shape
张量形状，按顺序列出每一维的长度。即使元素总数相同，批次轴与通道轴的互换也会改变算子的含义。
stride
张量步长，指某一维下标增加一时，线性地址跨过的元素数或字节数。比较时须先确认单位。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
ZeRO
将普通数据并行中重复保存的优化器状态、梯度或参数分配到不同 rank 的分片方案。分片范围随阶段而变。
ZeRO
通过划分训练状态降低每个数据并行进程的显存占用。三个常见阶段依次把优化器状态、梯度和参数纳入分片。
主权重
优化器使用的高精度参数副本。小幅更新先累积到这份参数，前向另取低精度副本。是否单独保留取决于实现。
主权重
优化器用于累积更新的较高精度参数副本。本节的主权重对应本地分片，容量按本地持有的元素数计算。
二阶原始矩
对梯度平方作指数移动平均所得的状态。Adam 用它估计各参数梯度的量级，通常和一阶矩分开保存。
元素数
张量各维长度的乘积。将它乘以每个元素的字节数，得到连续有效数据的大小，尚未计入对齐和分配器开销。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
分桶
把若干实际批量映射到少量预先支持的形状。一条请求量为 3 的批次可选择容量为 4 的桶，空位需要正确屏蔽。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
参数分片
把一个逻辑参数拆到多个 rank 保存。若一次运算需要整个矩阵，就要显式恢复其布局或跨卡协作。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
固定提交
用 Git 提交哈希锁定本课所引用的源码版本，避免行号随主分支变化。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
完成事件
通信流记录的完成标记。其他 CUDA 流须建立对该事件的依赖后才能使用相应结果。
工作区
算子在执行过程中为暂存中间数据而申请的区域。模型权重大小不变时，工作区仍可能随输入或算法改变。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
常驻
让已启动的工作单元在内核内部反复处理多个任务，而非处理完一块便退出。具体任务领取方式由程序决定。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
归约精度
各 rank 合并梯度时实际采用的数据类型。它可以与前向矩阵乘使用的类型以及长期保存梯度的类型不同。
微批次
从一个训练批次中再划出的一小组样本。多个微批次可先后进入流水线，使不同阶段同时处理不同组输入。
恢复点
已完整提交且仍可读取的模型、优化器、数据游标等一致状态。从已完整提交的步骤中选择最近的一步。
恢复边界
开始接续计算的位置，必须具备该位置所需的全部全局与局部状态。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
故障恢复
从可信的一致状态重建执行，训练恢复点和已向客户端承诺的服务输出需分别核对。
显存
GPU 可直接访问的设备内存。讨论容量时要区分张量逻辑大小、分配器实际保留量与同时存活的峰值。
暂存
在训练状态继续变化前，先复制一份可独立读取的快照供后台写盘。暂存结束和检查点可供恢复是两个不同的完成时刻。
有效载荷
接收端实际要恢复的 K/V 字节，包头、填充及重复发送可另外增加链路流量。
梯度同步
把不同数据并行副本算出的对应梯度按约定归约。推迟同步会增加本地需要保留的梯度，具体大小取决于分片时机。
梯度累积
连续处理多个微批次，将其梯度贡献累加到缓冲区，再统一更新参数；样本数不同时还需处理归一化分母。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
消费者
读取共享槽位数据并据此计算的一方。可以开始读，与生产者可以覆盖同一槽，通常由不同完成事件决定。
激活
模型处理本次输入时产生的中间张量。它的形状和寿命依赖批量、序列长度以及接下来是否需要反向传播。
目标模型
推测解码中定义最终生成分布的模型。它一次验证多个候选位置，并在需要时提供纠正词元的分布。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
缓冲复用
多次任务使用同一块内存。在先前读取完成之前覆盖它，可能使旧任务读到新内容。
视图
共享底层存储但拥有自身形状、步长和偏移的张量表示。释放其中一个视图时，其他持有者仍可能让整块存储无法回收。
设备网格
把每个物理 rank 映射到各并行轴坐标的布置，轴的乘积须和实际设备覆盖关系吻合。
词表
记录 token 与整数编号对应关系的表。词嵌入矩阵使用同一套编号查行，每行才是模型参与运算的向量。
输入梯度
损失相对于共享输入各分量的偏导。多条分支都读同一输入时，各分支的梯度贡献要按元素相加。
通信桶
为了一次提交集合通信而编成一组的梯度。桶内各项均已就绪且满足操作顺序时，才能按协议发起归约。
通信组
共同参与一系列集合操作的一组 rank。组内进程必须按兼容的顺序参与，成员失效后通常要重新建立。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重新分片
在完成需要完整参数的计算后，释放临时收集的完整表示，仅保留该 rank 应持有的分片。
预取
在后续层开始计算前就发起参数传输。预取越早，计算等待参数的时间可能越短，但完整参数与当前层数据同时占用显存的时间也可能越长。
驻留
线程块已获得在 SM 上运行所需的寄存器、共享内存和调度名额。块被接纳后，其线程仍可能等待数据。
