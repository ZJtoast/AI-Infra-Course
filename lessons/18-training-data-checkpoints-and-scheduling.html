1　训练样本的标签移位与文档打包

训练模型回答问题时，可以把问题和参考答案接成一条词元序列。假设问题占两个位置，答案只有一个词，再在末尾补一个占位符。训练只对答案计损失时，这四个位置只提供一个预测目标。模型读完问题的第二个词就要猜下一个词，所以训练时取第二个位置给出的分数，与第三个位置的参考答案比较。数样本、数读入的 token、数参与损失的目标，这里会分别得到 1、4、1。

训练样本依次经过解码、分词和排序，再将若干样本装入一批，经主机队列送往设备。比较数据管线时分别报告入口读取率（原始字节/秒）和有效监督吞吐率。后者的分子是实际参与 loss 的 token 位置数，分母是同一观察窗口的实际经过的秒数。padding 和被 mask 的 prompt 不计入分子。即使读取率相同，文本组成与分词结果也会改变每秒获得的有效位置数。

代码 1　TorchTitan 对同一 token 序列分别切出输入与标签

62–64 行从同一串 token 构造监督对。例如原序列为 A、B、C，输入为 A、B，标签为 B、C，所以每个位置学习预测它的下一个词。

例如 [BOS, 甲, 乙, EOS] 中，BOS 和 EOS 分别标记文本的开始和结束。代码保留前三项作为输入，取后三项作为标签。因此模型在读到“乙”时学习预测 EOS。普通文本的三个标签都可计分，而只训练助手回答的对话样本还要按助手的位置筛选标签。

两段已经对齐的训练序列各长 5 和 3。逐条 pad 到 8 要占 16 个槽位，8 个有用。装进一行 8 个位置可把槽位利用率从 50% 提到 100%。若训练定义要求文档相互隔离，attention 还要携带 segment 边界。仅将第二段 position 重新从零开始，attention kernel 仍需要实际的分段 mask 或 cu_seqlens 才能隔开前一段。

分开 padding 时，第一条有 8−5=3 个空槽，第二条有 8−3=5 个空槽。两个缓冲共 16 槽，有效输入只有 8 槽。打包后第一段占下标 0–4、第二段占 5–7，累计边界是 [0,5,8]。分段边界还能告诉内核，第二段的位置 5 不该读第一段。

代码 2　每次切相同的 token 与 label 区间，移动剩余偏移

166–168 行使用同一切片取输入和标签。若文档被拆到下一训练行，只偏移输入而忘记同步移动标签，就会悄悄改变预测目标。

假设本行只剩两个槽，而当前文档还有四对已经对齐的输入和标签。num_segment_tokens 取两者中较小的 2，给输入和标签各取相同的两项。末行把 _remainder_offset 往后移 2，下次就从文档剩余的第三项开始填。

把两篇各含三个 token 的短文拼成一行，让每个位置预测下一个 token，会得到五对相邻的输入与目标，其中有一个跨文档。若训练定义要求文档独立，该项的监督 mask 应为零；每篇文档各有两个有效预测位置，平均损失的分母为 4。若训练目标允许跨文档预测，文档交界处的那一对也参与损失，此时分母为 5。外部统计训练 token/s 时，应同时写清是否数输入占位、实际非 padding 输入，还是参与损失的标签。

为了让 GPU 连续开工，数据加载器会在训练第一个批次时提前读第二个批次。如果这时重启，第二批虽被读过，还没有参与权重更新，仍要重新送入训练。恢复游标记录下一项应该参与训练的数据。

假设训练步 80 已用 800 条样本完成对应参数更新，预取线程已解码到 832。若把 832 存成恢复游标，而模型权重只包括前 800 条，重启会跳过 32 条。相反，若权重已经更新到 832 却恢复到 800，会再做一遍更新。可恢复边界应关联 optimizer step、样本顺序和已提交样本数。

输入流水线至少有三个位置：读取器已经取到哪条记录、packing 缓冲已经拼到哪一 token、模型最近一次提交的训练步消费了哪里。假设加载器取到文档 C，训练步只用完 A 并消费 B 的前 20 项。如果恢复时只保存“已读 C”，B 的剩余部分可能被跳过。可保存可重放的读取游标连同缓冲，或从已提交边界重建预取。检验恢复连续性时，比较文档 ID、token 的文内偏移、标签掩码和所属训练步；仅比较下一批的形状看不出重复与遗漏。

3　数据分片与 NVMe 缓存

节点可以把刚下载的一包样本暂存在本机的 NVMe 固态盘上。下一轮若还要用它，读本地副本就能省下一次网络下载。大数据集常把许多样本打包成数据分片（shard），以减轻对象存储的请求和元数据负担。全局逐样本随机读会同时触碰许多 shard。缓存装不下活跃集合时，节点会反复下载同一对象。按 shard 或块打乱可改善局部性，代价是相邻样本的来源可能更相关。应检查各训练窗口内的数据源和难度分布。

训练参数、主存快照与持久化检查点的可用时刻

再算定期保存会给存储系统增加多少流量。设模型、优化器及其他状态合计 4 TiB，集群实际共享写带宽为 64 GiB/s，每 300 秒发起一次保存。训练数据读取和后台写入共用网络时，保存期间的带宽需求会影响训练步的耗时。

4 TiB 是 4×1024=4096 GiB。一轮保存的载荷除以 64 GiB/s 得 4096/64=64 秒；摊到完整的 300 秒周期则是 4096/300≈13.65 GiB/s。前一个分母是瞬时写带宽，后一个是两次保存的时间间隔。

一份检查点需写 C 字节，设备每秒实际可写 W 字节；单次写入时长 Twrite 至少为 C/W。若每隔 I 秒写一次，Waverage 衡量长期平均需求。例如每 120 秒写 60 GiB，平均需 0.5 GiB/s；若要在 10 秒内写完同一份，保存期间需达到 6 GiB/s。

有空间容纳一个 staging 副本时，下一次保存若早于上一次上传结束，就要等缓冲释放、跳过本次或申请第二份。并发两份可改善短时阻塞，也会让主存峰值近乎加倍。增量保存仅在能识别稳定的未变内容时节约字节，还需要保存基线版本并验证整条恢复依赖。

若步 k 的异步写盘在 100 ms 才读完主机槽，而步 k+1 在 80 ms 就开始往同一槽暂存，恢复出来可能是一份混合内容。复制到主机这一刻只允许训练复用原 GPU 张量，主机缓冲槽须等写盘任务读完后才能复用。双缓冲同样需要逐槽代次和读完确认，若两个槽都在写盘，生产者仍需等待空槽。

6　多卡作业的整组调度与拓扑放置

一组通过集合通信同步的训练进程约好一起开工。若只启动其中一半，它们很快就会等另一半，又占着已分配的卡。整组调度（gang scheduling）先判断能否同时满足一组成员的资源和放置条件，再让作业进入可运行状态。

一个参与进程数固定的 MoE 训练作业要求 32 个节点，每个节点 8 卡。集群有 64 个节点各剩 4 卡，计数上共 256 卡，却无法满足每个节点完整 8 卡的约束。若先绑定一部分 Pod，让它们长期占卡等待同伴，会造成碎片并阻塞后续作业。队列配额、拓扑可行性、成组准入与进程实际就绪对应四个判断。

在 Kubernetes 中，Pod 是调度器放到节点上的工作单元。Volcano 为批处理作业提供调度能力，能把多个任务作为一组考虑。在这个例子中，若每个 Pod 负责一台八卡机器，那么启动整份训练需要的是 32 个这样的 Pod，里面共运行 256 个训练进程。

假设每个节点有一个由 8 张 GPU 组成的高速互连域、两张分别接入 第 0 条和第 1 条网络通路 的 NIC，每架 8 个节点。先为 dense 层设 TP8 节点内，DP32 跨节点，PP=1。在 MoE 层把相同 32 个数据 rank 按 4 个连续节点组成 EP4，剩余轴为专家数据并行 8。EP 在 dense DP 这条轴上重新分组，设备总数仍为 256。

8　机架故障后的检查点选择与设备重组

设某个机架在保存检查点期间掉电。步 1000 已提交到另一故障域，步 1020 的部分 rank 仍在写入。机架 A 故障后旧 world 中的同步 collective 会等待缺失成员。协调器选择完整的步 1000，确认所有旧 rank 退出，并以新作业代数重建进程组。如果备用机架少了一个完整节点，原先的 TP8×DP32 布局暂时无法重建。

两种可评审的选择是等待第 32 个节点，或在算法和 checkpoint reader 支持的情况下缩小 DP。后一条路径重新解释全局 batch、gradient accumulation、样本游标和学习率调度。专家所有权也要重新分配，TP 和 EP 的整除条件逐一核实。仅换一行 world_size 可能让数据重复或专家缺失。

进阶题 02节点减少后的通信组与全局批量

情境　作业原用 TP8×DP32，每个节点 8 卡，每个 TP 组必须完整落在一个节点。故障后可用节点数从 32 降至 31。原每个数据副本的微批为 2，梯度累积 4 次。暂不考虑专家，允许框架在新 DP 数重分片。

问题　分别算原卡数、余卡数和原配置每步处理的全局样本数。若保持每副本微批和梯度累积次数，DP31 的全局批量是多少？只调整整数次的梯度累积能否精确保持旧批量？除批量外还应核对哪些状态才能恢复？

答案

结论　卡数 256→248，全局批量 256→248。只改变梯度累积的整数步数无法在每副本微批 2 下得到原来的 256。

推导　每个 TP8 组共同处理一个数据副本。原批量 32×2×4，新布局 31×2×4。令 31×2×k=256，k=128/31，无法取整后仍保持原批量。
若业务允许变批量，须明确优化器步和学习率调度使用的单位；按全局参数范围重分配分片，恢复消费游标，并核对每个新副本所取样本不重不漏。

本课术语
DP
数据并行。各进程处理不同训练样本，再同步梯度等状态，使更新对应于同一个全局批次。
EOS
序列结束标记。生成器按协议接受它后会结束请求，推测解码的交付数也可能因它提前截断。
EP
专家并行。不同设备持有不同专家，路由器选完专家后，词元及其结果常常要跨设备传输。
GiB
二进制容量单位，1 GiB 等于 1,073,741,824 字节；1 GB 按十进制等于十亿字节。
GPU
图形处理器，使用大量线程并行处理数据。需要许多独立运算或数据复用时，它常比逐项在 CPU 上执行更合适。
lane
一个线程在 warp 中的编号。分析访存时，先列出同一条指令下各个 lane 的地址，再判断它们覆盖哪些内存区间。
MiB
二进制容量单位，1 MiB 等于 1,048,576 字节或 1,024 KiB。
MoE
混合专家模型。路由器给每个词元挑选少数几个专家，由选中的网络计算，再按路由权重合并结果。
NCCL
NVIDIA 的多 GPU 通信库，负责组织集合通信和点对点传输。它会根据参与设备、消息与拓扑选择可用路径。
NIC
网络接口卡，负责节点之间的网络收发。与 GPU 的 PCIe 拓扑会影响设备之间搬运数据的路径。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
RNG
随机数生成器，其状态决定后续的随机序列。重算和训练恢复需要保留与本次操作对应的随机状态。
shape
张量形状，按顺序列出每一维的长度。即使元素总数相同，批次轴与通道轴的互换也会改变算子的含义。
TiB
二进制容量单位，1 TiB 等于 1,024 GiB。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
TP8
使用八个参与者的张量并行组。每一份权重和缓存如何分布，还要结合被切分的轴判断。
互连
设备间传输数据的链路及交换结构。比较系统时要区分片内、单节点内与跨节点的范围。
全局 batch
一次参数更新实际汇入的全部样本。应按处理不同样本的数据并行副本数和累积的微批次数计。TP/CP 组内各卡协作处理的是同一批样本。
准入
调度器确认有可用资源并允许请求开始执行。准入前的等待属于排队时间。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
完整索引
将全局张量、优化器状态以及各分片的范围和位置对应起来的清单，可用于检查恢复所需数据是否齐全。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
归约
把一组数用求和、取最大值等操作合并成少量结果。算子内归约与跨卡归约面临不同的数据搬运和同步成本。
恢复点
已完整提交且仍可读取的模型、优化器、数据游标等一致状态。从已完整提交的步骤中选择最近的一步。
恢复边界
开始接续计算的位置，必须具备该位置所需的全部全局与局部状态。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
掩码
规定哪些查询和键可以相互关注。被屏蔽的位置应对该行的分母和输出都贡献零，整行被屏蔽时还需要约定返回行为。
故障域
一次故障可能同时影响的一组资源，例如同一机架的节点。副本和检查点的放置须考虑共享故障。
故障恢复
从可信的一致状态重建执行，训练恢复点和已向客户端承诺的服务输出需分别核对。
暂存
在训练状态继续变化前，先复制一份可独立读取的快照供后台写盘。暂存结束和检查点可供恢复是两个不同的完成时刻。
暂存完成
同一训练步的状态已复制到独立缓冲，原张量可以继续更新；远端持久化可能仍在进行。
梯度同步
把不同数据并行副本算出的对应梯度按约定归约。推迟同步会增加本地需要保留的梯度，具体大小取决于分片时机。
梯度累积
连续处理多个微批次，将其梯度贡献累加到缓冲区，再统一更新参数；样本数不同时还需处理归一化分母。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
流水线
把搬运、计算等相互依赖的阶段错开执行。不同数据块可以重叠，但消费某个块之前仍要确认它已准备好。
稳态
编译和一次性初始化已经完成、输入条件可重复时的执行状态；此时测得的单次节省可用于估算回本次数。
载荷
应用需要传送的数据。协议头、编码开销和重传都会占用链路，有效载荷只统计应用数据本身。
通信组
共同参与一系列集合操作的一组 rank。组内进程必须按兼容的顺序参与，成员失效后通常要重新建立。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
预取
在后续层开始计算前就发起参数传输。预取越早，计算等待参数的时间可能越短，但完整参数与当前层数据同时占用显存的时间也可能越长。
