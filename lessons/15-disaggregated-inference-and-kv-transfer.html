1　分离式推理的排队与交接

考虑一个32K 输入、持续生成数百 token 的请求。共置部署在同一组设备上执行 prefill 和 decode，KV 可以原地接续；长 prefill 也会占用正在服务其他 decode 请求的计算、带宽与调度机会。PD disaggregation 把 prefill 与 decode 交给不同资源池，允许分别配置并行度、batch 与容量，同时增加跨池交接及新的排队。

从 Requests 跟到 Controller，再沿左侧分支进入 prefill 池。这里的模型处理提示词，产生后续逐词生成所需的 KV。中间横向箭头把这些状态送往 decoding 实例，右侧模型继续生成。两个池各有并行运行时，能分别调整实例数或并行布局；两阶段之间的 KV 交接也因此成为一段可测的延迟。

prefill 通常有较多 query 行，decode 需要持续推进众多长驻请求，两类工作适合的资源配置可能不同。拆分可以减少直接干扰，但代价包括 KV 搬运、元数据协商、源页滞留、目标容量预留与故障恢复。短输入、低并发或网络繁忙时，这些新增成本可能超过收益。DistServe 讨论的目标是满足 TTFT 与 TPOT 约束后的 goodput，不能用无延迟约束的峰值吞吐替代。

Tserial = QP + CP + H + QD + CD

QP、QD 是两个资源池各自的排队时长，CP 是提示计算时长，H 是交接时长，CD 是后续生成时长；这个式子按各阶段依次执行估算总时间。实际系统可以把分层保存、传输、预取与计算重叠，端到端时间应按依赖图求关键路径。不能在计算已经包含传输等待时再加一次 H，也不能在尚未具备依赖条件时直接把所有阶段取最大。

计量首个 token 的时延前，先确定由哪一端发送结果。如果 P 完成采样后直接把首 token 发给客户端，KV 交接停顿可能主要反映在首 token 到第二 token 的间隔；如果 D 需要重放提示末尾来产生首 token，交接就进入 TTFT。报告PD服务指标时，应标明哪一端发出了首个 token，并固定客户端的计时边界。否则两次报告中的 TTFT 可能对应不同的事件。

一次跨池请求需要同时观察的队列

队列或资源积压意味着什么可能影响

2　KV 传输的有效字节数

普通 GQA 在 L 层、序列长度 S、G个 KV heads、每头维度 d、每元素 p 字节时，完整 K/V 容量为2LSGdp 字节。乘2对应 K 与 V；G由模型配置决定，不能替换成 query heads。这个式子给出一份完整逻辑状态的载荷，物理复制、页对齐与量化元数据还要另算。

CKV = 2LSGdp,    Twire ≥ CwireWeffective

取L=32、S=32768、G=8、d=128、BF16，完整 KV 为4 GiB。TP8且每 rank 恰好持有一个不同 KV head 时，每个 rank 为512 MiB，总量仍为4 GiB。若每个 rank 独立占用同一聚合出口，不能把单 rank 传输时间直接当成整个请求的交接时间；出口带宽会被八路分片共同分摊。

4 GiB 经过有效32 GiB/s 链路，仅传这份有效数据就至少需要 125 毫秒。标称400 Gb/s 是每秒4000亿 bit，理想50 GB/s，约46.57 GiB/s；相同4 GiB 对应约85.9毫秒，仍未扣协议、拥塞、PCIe 和内存路径损耗。有效带宽必须与计入的字节范围相同，不能混用 Gb、GB 和 GiB。

普通分页还可能传输未满尾页。例如page=16、有效长度33，逐整页发送48个位置比有效长度多45.45%的位置容量。实现可以裁剪、使用虚拟传输页或合并连续区域，但必须把有效 token 边界同时交给接收方。若量化 KV 包含 scale，遗漏 scale 的字节量看上去更小，恢复出的数值却没有正确含义。

MLA 潜变量、跨层共享、SWA 窗口、稀疏 index 记录和循环状态应使用第十二课的真实记录结构计量。源端多个层的逻辑引用可能指向同一物理存储；把所有层引用都序列化会重复发送。传输设计必须明确是按逻辑层导出、按物理 region 导出，还是按模型定义的可恢复状态导出。

设缓存页容纳 16 个 token，每个 token 的全部 K/V 共 8 KiB，提示长 33 个 token。逐有效元素打包需搬 264 KiB；按三个完整页发送则需 384 KiB。假设传输均耗时 1 ms，将 264 KiB 除以时间衡量业务有效吞吐，将实际发送的字节数除以时间衡量链路承担的负载。后者还可能包含分块头与重试字节，两者的计数位置应写清。

3　KV 交接协议

“第 8 页”只在分配它的进程和缓存池里有意义。接收端要把远端描述翻译成本地可写位置，还要确认页规格与注册代次相容。只传请求号和一串页号，无法确定从哪里读、读多少，以及旧页号是否仍有效。

一次交接至少要记录：这是哪个模型与请求的哪次尝试，已计算到哪个 token 边界，各层或 region 的数据在哪些源页，目标页由谁分配，使用哪种 dtype 和物理布局，以及谁在什么条件下允许释放。上层先核对模型、请求和历史边界，再把对应区间的地址和长度交给网络库。

代码 1　vLLM NIXL 握手描述包含地址、页长、步幅与布局

kv_caches_base_addr 提供 region 基址，block_lens 与 block_strides 描述每块载荷及相邻块距离；block_size 是 token 粒度。region_mem_types 还能区分所在内存介质。这些量不能互相替代，尤其不能默认 stride 等于有效载荷长度。

4　调度器中的外部命中与加载状态

vLLM 的 connector 把命中查询和资源分配留给调度器，把实际搬运交给工作进程。scheduler 先查询本地已计算前缀之外还能从外部恢复多少 token，再为这些 token 分配本地页。异步恢复期间，请求需要等待接收完成；worker 按照本轮绑定的 metadata 执行实际搬运，并把完成或失败报告回调度器。

代码 2　外部命中接口区分未知、零命中和异步加载

返回 None 表示查询尚未确定，需要以后再查；返回0表示没有可加载 token，此时异步标志必须为 False。非零匹配只能覆盖当前确实可获取的有效前缀，不能把已经驱逐或无法连接的数据算进可复用长度。

例如提示1024个 token，本地已算256，外部缓存可恢复到768，则新增外部命中为512，剩余256需要计算。接口报告的数量是超出本地进度的增量，这里按接口返回的增量更新本地进度。页对齐、最后位置 logits 需求和模型状态可能进一步限制有效命中边界。

代码 3　异步路径可以经历两次分配回调，加载由 num_external_tokens 决定

612–615 行给出了加载开关的判断依据。多连接器共享同一请求时，未被选中的连接器仍可能收到真实块地址，单看地址是否存在会重复发起加载。

第一次分配目标缓存页以供异步接收，完成后还可能为新计算分配额外页。源码特别说明 blocks 非空也可能没有选中该子 connector 的加载工作，因此不能用“存在页表”替代 num_external_tokens>0。

恢复失败时，已分配目标页里可能只有部分有效内容。调度器应根据失败结果重新确定可用前缀或转入重算，不能只把等待状态改成 RUNNING。对于多 rank 执行，完成条件还要覆盖所有必要分片；某个 rank 没有实际传输，也必须给出相应完成报告，否则聚合端会一直等待。

代码 4　合法的空分片仍需参加完成报告

DCP 下某 rank 负责的位置可能越过序列末尾，读路径只有通知而没有实际 transfer。预先建立空在途条目使该 rank 也能报告完成，避免“没有工作”变成“永远没完成”。

连接器在这里提供逐层等待缓存加载的接口；具体实现可能采用全请求接收完成后再运行，也可能逐层流水。在时间线上对齐每层的加载完成与计算开始，就能看出该后端实际重叠了哪些层。

6　NIXL 的内存注册与传输描述符

注册描述的是较长期有效的内存区域及访问能力；传输描述符列出本次操作访问的具体子区间。把一个大 KV 池注册一次，再为请求挑选其中的页，可以摊薄注册和元数据交换成本。请求的逻辑页由缓存管理器分配，传输前按 head 和页映射定位到已注册区域。

7　Mooncake 的批传输完成条件

Mooncake Transfer Engine 用段（segment）标识可访问的地址空间。打开 segment 取得句柄，注册本地内存并获得必要远端元数据后，调用者构造 TransferRequest 列表，再为这批请求分配 batch ID。实际路径由配置、可用 transport、内存位置与拓扑决定，项目名称本身无法保证某一次传输必走 GPUDirect RDMA。

9　TP8 到 TP4 的 KV 重排

先取普通 GQA，G=8，P 侧 TP8、D 侧 TP4。提示处理端的每个 rank 保存一个 KV 头；D 每个 rank 需要两个 head。D0从 P0和 P1取得 head0、1，D1从 P2、P3取得 head2、3，以此类推。完整逻辑 KV 仍为同一份，但每个目标页内 head 排列和来源段数改变。

TP8 的 KV 搬到 TP4 时，先定义一行的逻辑坐标（层、token、KV 头、头内通道），再写两侧各自的存储偏移。举例说有 16 个 KV 头，源 rank 各存连续 2 头，目的 rank 各存连续 4 头，则目的 rank 2 需要头 8 至 11，来源是源 rank 4 和 5。若源页有 16 个槽但最后一页只用了 3 个，应为每一层和每个有效 token 分别拼头；把两块物理页整段拼在一起，容易得到“先 16 个 token 的前两头，再 16 个 token 的后两头”，与按 token 存四头的目标布局不同。

代码 16　P 的 TP 度较大时，D 选择多个源 rank，并对重复 KV head 去重

11　逐层传输的 token 依赖

解码端计算第 1 层时，理论上只需要第 1 层的历史 KV。因此逐层交接有机会让前几层计算与后几层传输重叠。若某一层的 KV 来迟，当前 token 到达该层后仍会停下来等它。

考虑四层教学模型：P 每层2毫秒，网络传输一层的 K/V 需 1 毫秒，D 处理一个新 token 每层3毫秒。源 KV 在对应 P 层完成后即可发送，网络完成时刻依次为3、5、7、9毫秒。假设首个生成 token 在 P 第4层结束的8毫秒产生，忽略独立采样开销；D 要处理这个 token，最早从8毫秒开始。

即使 D 第1层 KV 在3毫秒到达，也无法在3毫秒就处理尚未产生的 token。如果实现支持按层消费，D 四层可在8—11、11—14、14—17、17—20毫秒执行，因为后续层 KV 都已经及时到达。若实现要求全部 KV 接收完成再运行，D 从9毫秒开始，完成于21毫秒。完全串行的 P 计算、四层搬运和 D 计算则为8+4+12=24毫秒。

si = max(ai,fi-1),    fi = si + ci

ai表示本层数据可用时间，fi−1表示上一层输出可用时间；第1层的f0必须取当前输入 token 可用时间，本例为8毫秒。这个递推同时体现网络与模型依赖。将f0错设为0会得到 15 毫秒，但这个结果假定第 1 层能在输入 token 生成前开始计算。

如果 decode 端重放已知的 prompt 尾部，或直接从远端缓存恢复，就不需要等同一轮 prefill 生成输入。测量这两种路径时应分别记录依赖。实现提供 wait_for_layer_load 接口后，还需核对 attention 后端、connector 和 CUDA Graph 实际等待的事件。

12　分层缓存的预留与发布

KV 分层存储把 GPU 服务中的状态扩展到主机内存、磁盘或远端介质。当前 LMCache 源码使用 L1 manager 与 L2 adapter 组织缓存；具体 L1介质由配置决定，定位数据时查相应层的存储配置。本节阅读其对象生命周期，与前面的 vLLM 页生命周期相互对照。

分层缓存的“目录可查”和“数据可用”必须分开。分配目的页后可以记录一条正在加载的占位项，避免第二个请求重复拉同一前缀。此时后来者只能等待，不能把未写完的页交给注意力。待所有必要的层与分片都完成写入且可见，目录再从 loading 改为 ready。加载失败要唤醒等待者并撤销占用，页只有在旧写者停止后才能回收。以请求标识、缓存键和页代次串起三个状态，才能查清偶发读旧值的来源。

代码 18　写入预留可以部分成功，临时对象有独立保留策略

返回的字典只列出成功预留了内存的对象，OOM 或写冲突可使部分 key 失败。is_temporary 对象在最后一个读锁释放后删除，并且不向 L2 offload；临时中转数据与长期复用缓存可以采用不同策略。

代码 19　写入完成后再将对象发布给读取方，重复副本可以丢弃

reserve_write 只是取得写入位置；finish_write 负责发布已写好的对象。如果 key 已存在，预留副本可以被丢弃。l1_owners 记录每个 key 在哪个 manager 里，不能在跨 manager 回调时猜测所属池。

假设对象 K 跨两段传输，第一段完成后第二段失败。若第一段到达就把 K 发布为命中，读取方可能拿到只写完一部分的数据；正确路径应保持写入未完成状态，再选择补齐、丢弃或重试。缓存命中统计也应依据可读对象。

实际 DMA 结束必须发生在 finish_write 允许发布之前；finish_write 作为管理接口无法替调用者等待所有外部异步写入。读取缓存的操作也须持有读锁，直到从该对象复制或消费的所有访问结束。释放 Python 层上下文与 GPU 复制完成可能发生在不同时间，需要在集成层建立相应事件顺序。

这与数据库中的“先准备再提交”有相似的可见性要求，但这里的数据页还受设备异步访问约束。多对象请求可能只命中部分 key，正常恢复需要按照模型的有效前缀或分组状态要求解释这些命中；普通因果 Transformer 的随意中间片段不能直接跳过缺失历史。

一次恢复需要同一模型版本的对象 A、B、C。系统给三者预留目标页后，目录仍应标记加载中。若 A、C 成功而 B 校验失败，能否消费 A 取决于 A 是否组成独立有效的连续前缀。要求三对象一起解释的记录要保持不可见。重试时须重新确认失败对象及其所有权，避免上一次尝试的晚到完成覆盖本轮状态。

13　预取完成与缓存读锁

LMCache 的 submit_prefetch_task 向 L1发起异步预取，允许的L1、L2介质与 key 分组由 PrefetchTaskSpec 表达。它返回 PrefetchHandle 以供查询，各对象的到达状态随后从结果中读取。底层对象可能在 L1已命中，也可能需要从 L2加载，最终结果需要逐对象或逐分组解释。

代码 20　结果完成后只返回一次；返回 None 的含义需要结合调用状态

正常进行中返回 None；同一 handle 的结果被消费后，后续查询也返回 None。因此调用者应保存首次取得的结果，结果已经取走后，再次读取会得到 None。

wait_prefetch_status 会一直等到有结果可查询，或达到超时时限，然后仍通过 query 取得具体结果。预取结束后可读取结果报告，再按请求 key 逐项查命中状态。当前代码记录 retained keys、L1 hits 与 L2 hits，指标需要保留这些分母和来源。

代码 21　消费完成后释放对应对象的读锁数量

525–526 行按键检查读锁释放结果。一次调用涉及多个对象时，需要按对象确认读取已经结束。

read_locks 可表示同一 lookup 持有的多个读引用，l1_owners 定位所属 manager。释放数量与原先预留不匹配，可能造成对象长期不可淘汰或过早复用。

假设普通因果缓存分成四个连续块，结果只命中第0、1、3块。第0、1块可以形成可恢复前缀，第3块无法让模型直接跳过缺失的第2块；即使第3块的字节存在，也要根据模型及缓存协议判断后续使用方式。SWA、跨层压缩和状态快照采用各自的有效范围规则，不能把任意 hit bitmap 都压成一个“总命中 token 数”。

预取也有容量与带宽成本。如果一次把大量可能用不到的对象搬进 L1，会挤掉热点缓存并占用源端读锁。合理的 ahead 距离取决于何时能消费、预取成功概率、目标容量和I/O队列；请求取消后仍要退还读锁及临时对象。

设预计 30 ms 后用到一个对象，预取需要 8 ms。立即预取会让它在可消费前占住约 22 ms 的目标空间；若在第 20 ms 发起，理想情况下只提前约 2 ms 到达。后者给排队波动预留的余量较小。无论怎样安排提前量，使用方仍须持有有效读引用到最后一次实际读结束，预取完成本身无法保护对象免于被驱逐。

14　远端 KV 恢复与本地重算

把远端恢复用时记为 Trestore。QR 是排队时间，α 是查找和调度等固定开销，C 是要搬的字节数，W 是有效带宽。Tconvert 和 Treplay 分别是格式转换与必要重放的时间。以下取这几段依次执行的情形。比较时，本地路径也要计入它自己的排队时间与重算用时。

Trestore = QR + α + C/W + Tconvert + Treplay

教学例子：2 GiB 远端 KV，有效20 GiB/s，查询与排队10毫秒，转换和重放15毫秒，恢复共125毫秒。无排队重算为300毫秒时，恢复节省175毫秒；重算为70毫秒时，恢复更慢。但若70毫秒重算前还要排队100毫秒，恢复又会优于170毫秒的重算路径。

以本节习题的时间为例，本地从等待到状态就绪用 q+70 毫秒，远端整条路径用 125 毫秒。两者相等时 q=125−70=55。若远端还要等 30 毫秒释放目标页，远端总时长变为 155 毫秒，临界等待相应变成 155−70=85 毫秒。

W>CTrecompute-QR-α-Tconvert-Treplay

该分界只在分母为正、固定项和带宽可近似独立时成立。按上例300毫秒重算与25毫秒其他恢复开销，2 GiB 需要超过约7.27 GiB/s 才值得恢复；若其他开销已超过重算总时间，再大的传输带宽也无法让此模型中的恢复获胜。

CPU staging 路径可能包含源 GPU 到 DRAM、网络、目标 DRAM 到 GPU 三个阶段。取2 GiB、两端复制各40 GiB/s、网络20 GiB/s，完全串行数据时间为50+100+50=200毫秒；分成四个0.5 GiB 块且三个阶段资源独立时，理想流水数据时间为12.5+4×25+12.5=125毫秒。共享 PCIe 或内存带宽会使这个理想值失效。

直接设备传输在同一20 GiB/s 有效网络假设下的数据下界为100毫秒，但能否走这条路径由平台、注册方式与 backend 支持决定。评估 zero-copy 时应标明省掉了哪次中转、是否仍有布局转换，以及把 CPU 开销转移到了何处。代入传输时间公式时，用相同路径和消息大小测得的有效带宽。

保留缓存本身也需要准入。设该缓存以后再次被访问的概率为 p。每次命中可省去 175 毫秒重算，本次写入耗时 20 毫秒，故期望净收益为 175p − 20 毫秒。p=0.2得到15毫秒期望收益，p=0.05得到−11.25毫秒；上述估算只计重算节省的时间和写入开销。若缓存很少复用，单是写入远端存储或 SSD 就可能得不偿失。缓存占用空间对其他请求的影响还需另算。

若本地重算预计 40 ms，恢复除数据传输外固定花 8 ms，有效带宽 4 GiB/s，则传输预算为 32 ms，对应 0.128 GiB，约 131 MiB。小于该值的对象在此简化条件下更适合恢复。若恢复队列新增 10 ms，临界点就降到约 90 MiB。比较时应使用相同前缀边界，并把格式转换、重放和等待计入相应候选路径。

情境　同一请求可从两条路径获得完全相同、可供下一步消费的状态。远端恢复的总时间为 125 ms，已含查找、传输、转换和获页；本地重算本身 70 ms，但须先排队 q ms。两条路径从同一决策时点计时，结束后的 decode 完全相同。

15　Dynamo 的缓存感知路由

缓存命中能省下的重算时间，要和排队时间放在同一条请求时间线上。一个几乎全命中的节点若已积压很多长提示词，仍可能晚于空闲节点完成。路由器给命中和负载分别计价，正是为了估计这次请求何时能开始解码。

缓存感知路由既要记录各工作进程已缓存哪些前缀，也要估计各进程当前的负载。只追求最长命中，可能把所有热门系统提示都挤到一个 worker；只追求最空闲，可能不断重算长历史。Dynamo 当前源码提供可组合 scorer 与 picker，本节选取 scheduler 中的 reference 评分实现做具体算例，实际启用策略还取决于部署配置。

代码 22　设备、主机、磁盘和共享缓存按不同权重形成信用

effective_overlap_score_credit 包含设备命中信用衰减；host 和 disk 使用各自权重，shared 只计指定本地前缀以外的匹配。各输入的区间含义来自上游 cache snapshot，不能把多个重叠来源的命中 token 未经处理直接相加。

代码 23　扣除缓存信用后的 prefill 负载，与 decode 及活跃请求成本相加

raw_prefill_tokens 同时包含现有 prefill 负载和本请求输入；在这段可用负载分支中，uncached 与 cached 最终合回完整输入，再通过 overlap_credit 扣减。这个 score 按块归一化，不能直接当作预测毫秒值。

J = λmax(R-K,0) + D + wN

在这条分支中，R 为原始 prefill 块负载，K 为加权缓存信用，λ是 prefill_load_scale，D 为预计 decode 块成本，wN 为活跃请求项。教学配置取block=16、输入1024个 token、λ=1、w=0。W1正在 prefill2048个 token，本请求全部64块在设备命中；W2无 prefill 积压，仅设备命中16块，decode 成本分别为20和10。

源码第 225–243 行还可以随相对积压衰减设备命中信用。令衰减系数1，最低 prefill 负载为0：W1相对积压128块，除以本请求64块得到2，信用系数为11+2=13，因此K=643。W1分数为192−643+20≈190.67；W2分数为64−16+10=58，较低成本指向 W2。全前缀命中仍可能输给较空闲的部分命中 worker。

换一个同负载算例，64块全在设备、主机或磁盘，教学权重分别取1、0.5、0.1，则信用为64、32、6.4块，反映不同恢复代价。这些是手算参数，未声称为默认配置。共享缓存读取还会受到网络和服务负载影响，固定权重需要结合实际预测误差校准。

reference.rs 第 222 行注明默认评分不为 worker 间 KV copy 单独给信用，特定 kvcr 策略才处理这类 copy offer。policy.rs 还允许多个 scorer 贡献相加，最终选择规则由 picker 决定；阅读生产行为应继续追到实际配置与组合。

教学 reference 评分：W1全命中但已有较多 prefill 负载，W2部分命中且空闲。评分单位为归一化成本，未转换为实际毫秒。

路由器可将各 worker 的候选完成时间写成排队时间、未命中部分的计算时间、必要恢复时间之和。A 命中更多，仍要等 30 ms，再算 3 ms；B 等 4 ms，再算 18 ms。忽略其他相同成本时，B 预计 22 ms 完成，比 A 的 33 ms 早 11 ms。这个推导用于解释取舍，实际路由公式应按所用 Dynamo 策略和配置读取。

16　缓存事件与 worker 确认

路由器通常维护缓存索引的副本，worker 通过创建、驱逐或重置事件更新它。事件传输存在延迟，worker 也可能在路由选定后驱逐对象。Dynamo inputs.rs 第 505–508 行明确指出 snapshot 在回调期间稳定，但可能落后于引擎状态；稳定快照只保证本次评分所见一致，无法保证远端对象永远存在。

代码 24　事件游标区分首次、连续、缺口与旧事件

37–40 行以最近已应用的序号为依据检查连续性。如果已经处理 40 却收到 42，记录预期的 41 能帮助上层决定从哪里补取缺失更新。

last=100时，101是连续，103暴露缺口，99或100属于旧事件。observe 只分类，不自动修复缓存索引；如何重放、重建或重置由事件处理层负责。

假设路由器收到“块K被创建”的事件100，却丢失“块K被驱逐”的101，随后收到102。若忽略序号缺口，路由器仍会把已驱逐的 K 当作命中。正确的事件协议需要明确重放或重建策略，worker 最终 lookup 与加载结果也要反馈真实命中。热缓存路由预测成功与实际恢复成功应分别计量。

事件序号通常只在对应 publisher 或 rank 的序列范围内有序；跨 worker 的编号不能任意比较。引擎重启需要新的身份或重置语义，否则新进程的低序号可能被误判为旧消息。注册 generation、缓存事件 epoch 和业务 request attempt 分别管理不同对象，设计日志时应保留它们的关联。

如果路由预测命中但 worker 发现缺失，仍可等待另一副本、从低层恢复或重算。策略应重新计入额外排队与容量，避免多个请求同时冲向一个已经失效的热点。对于长上下文服务，缓存事件积压本身也会转化为不必要的网络读取或重算，属于应观测的控制路径。

路由器在 t0 收到“前缀 P 位于 worker 3”，t1 选中该 worker，t2 才发出读取。若 worker 在 t1 到 t2 之间驱逐 P，即便事件严格按序投递，这次预测仍可能失效。worker 应再次对前缀及版本做匹配，并取得读取期间的保护。观测索引可用于排序候选，成功持有的本地引用才决定这个请求可以读取哪些页。

普通 Transformer 可以依赖完整有效 KV 接续计算；混合模型还可能需要循环状态、滑动窗口边界、跨层共享映射或推测回退快照。只复制一个名为 KV 的 tensor 列表，未必包含恢复下一 token 所需的全部状态。交接协议应按第十二课介绍的模型结构，逐项列出续算所需的状态及其有效范围。

恢复正确性可从一段 token 身份和版本都已核实的前缀出发：比较恢复后每个 region 的含义与有效边界，再核对接续计算输出。格式转换可能允许数值误差，但丢页、head 映射错误和旧写覆盖属于状态错误，不能混在“低精度有误差”里。本文仅给出验证设计，没有运行跨机或 GPU 实验。

恢复期间有两道独立检查。第一道在控制面核对请求代次，防止旧完成回调把新请求标为 ready；第二道在数据面等待旧操作不再写入拟复用的地址，防止新页被覆盖。只做代次检查仍可能见到无声的数据损坏。若要立刻重试，可以把新传输写入另一组隔离页，待验证成功后发布，再单独清理旧句柄和页。

情景面试题 01取消传输后旧写覆盖新页

情境　取消操作已使本次 HTTP 请求结束。调度器立即把目的物理页 P 再分给新尝试，GPU 上偶尔出现旧数据。旧完成回调带 generation 标记，会被软件拒绝；传输可能由多条独立 DMA 组成。

问题　请给出一种即使所有旧回调都被拒绝仍会污染 P 的时序。怎样用两个对照区分“旧设备写未排空”和“新映射选错页”？设计取消后的中间状态，并逐项说明将 P 重新分配和将本次结果发布给计算流各自需要满足什么条件。

答案

结论　迟到的设备写会直接覆盖物理字节，它不需要通过软件回调才能发生。应先将旧页放进待回收队列，与可分配页隔离，旧的读写操作全部结束后再将页放回空闲池。

推导　先给新尝试独立物理页，在已知映射写入本代标记，并人为延迟旧传输；只有提前共享 P 时才出现旧标记，支持在途写。另固定所有旧写已确认排空，再交换页表或记录实际地址，若错误仍随逻辑映射变化则查寻址。
取消后撤销 ready 状态、保留每个旧句柄与代次，由后端确认全部子传输已停止。新尝试的数据还需自身写完并可见，旧回调不能为它置 ready。

每条请求4 GiB、有效出口32 GiB/s，网络理想上界为8请求/秒；即使 prefill 能处理20请求/秒、decode 能接纳15请求/秒，完整服务仍受这条路径约束。到达率10请求/秒时每秒产生40 GiB 载荷，网络队列持续增长。增加 prefill 实例而不增加有效网络或降低 KV 字节，可能让源页滞留更严重。

若6请求/秒、每条请求4 GiB，交接期间平均持有0.25秒，则源端合计平均额外滞留6 GiB。规划峰值时还要回放各请求实际持有页的时间。拥塞、重试和长尾请求会放大保留时间，页回收慢又限制新 prefill，形成反压。目标提前预分配过多未到达 KV，同样会挤占 decode 容量。

八个4 GiB 请求同时共享32 GiB/s 出口，总载荷32 GiB，理想清空时间为1秒。公平并行时每条请求约在1秒完成；串行时可以让第一个约125毫秒完成，最后一个仍约1秒。调度改变完成顺序与尾延迟分布，这些请求仍然共享同一出口的总带宽。

本课术语
API
供程序调用的接口。函数返回、设备执行结束和远端可见可能发生在不同时间，应按接口的约定判断。
BF16
16 位浮点格式，使用 8 位指数和 7 位显式尾数。指数范围接近 FP32，小数有效位更少。
CUDA Graph
预先记录并实例化一组 GPU 操作及其依赖，再重放整个执行图，可减少主机逐次提交许多小操作的开销。
DCP
在分布式检查点中，DCP 指 PyTorch Distributed Checkpoint；在推理解码并行中，这个缩写也可指 decode context parallel。含义由本节讨论的对象决定。
decode
推理时利用已有状态生成后续词元的阶段。普通自回归生成中，每条序列每轮通常新增一个位置。
DMA
直接内存访问。复制引擎或网卡可在已授权的缓冲区之间搬运字节，提交操作之后需要检查它的完成条件。
DRAM
动态随机存储器。性能报告里的 DRAM 流量通常指设备与外部显存之间的实际传输量。
FP32
32 位浮点格式，具有 8 位指数和 23 位显式尾数。在低精度乘法中常用作累加器或保存统计量。
fragment
协作完成一次矩阵运算时，分布在各线程寄存器中的矩阵片段。单个线程持有其中一部分，具体元素映射由指令规定。
GiB
二进制容量单位，1 GiB 等于 1,073,741,824 字节；1 GB 按十进制等于十亿字节。
GPU
图形处理器，使用大量线程并行处理数据。需要许多独立运算或数据复用时，它常比逐项在 CPU 上执行更合适。
GPUDirect RDMA
让受支持的网卡等外设直接访问 GPU 显存的机制，可减少经主机内存中转的数据拷贝。
GQA
分组查询注意力。多组查询头各自共享一组键和值，可以减少解码时需保存和读取的 KV 数据。
HBM
GPU 常用的高带宽显存，用于保存权重、激活和中间结果等数据。芯片与显存之间可持续传输的字节数会限制某些算子。
ITL
Inter-Token Latency，同一请求相邻两个输出词元抵达的时间间隔，可用来观察生成是否间歇性停顿。
key
注意力中用来与查询匹配的向量。每个可见位置提供一个键，其分数决定同位置的值参与汇总的权重。
KiB
二进制容量单位，1 KiB 等于 1,024 字节。
KV
键和值的合称。一个历史位置通常既提供参与匹配的键，也提供按注意力权重汇总的值。
KV 头
共享一套键和值的注意力头。使用 GQA 时应按 KV 头数估算缓存容量。
L2
GPU 上多个 SM 共享的二级缓存。L2 命中可免去一次更远的显存访问，因此 L2 流量和 HBM 流量通常不同。
logits
模型为词表中各个候选 token 输出的未归一化分数；经过 softmax 可得到概率。不同词表的同一数字编号不必指向同一 token。
MiB
二进制容量单位，1 MiB 等于 1,048,576 字节或 1,024 KiB。
MLA
多头潜在注意力。模型把历史内容压到低维潜向量，后续计算按模型规定从该向量获得各头所需的信息。
NIC
网络接口卡，负责节点之间的网络收发。与 GPU 的 PCIe 拓扑会影响设备之间搬运数据的路径。
OOM
内存不足导致分配失败。本节需要进一步定位失败发生在哪一次收集、缓冲申请或优化器更新。
PCIe
主机与 GPU、网卡等设备之间的互连标准。设备位于哪个根端口或交换机下，会影响传输所经的链路。
prefill
推理时处理已有提示词的阶段。模型可以同时计算多个输入位置，并留下后续生成要读的缓存。
query
注意力中发起查询的位置或它的向量。它与各个可见位置的键相乘，得到对应的一行分数。
rank
一个进程在指定通信组中的编号。张量与缓冲区由哪个 rank 持有，要结合该通信组的成员列表判断。
stride
张量步长，指某一维下标增加一时，线性地址跨过的元素数或字节数。比较时须先确认单位。
SWA
滑动窗口注意力。一个查询只访问附近的历史位置，窗口外的依赖能否丢弃取决于模型其他层和状态。
token
分词器分配编号的基本单位，可能是一个字、词的一部分或标点。模型按编号查词嵌入表，生成时也按这些单位计数。
TP
张量并行。多张卡各算同一个算子的一部分，例如各持有一组输出通道，再按下一层的要求收集或归约结果。
TP4
使用四个参与者的张量并行组。某个头或通道由哪张卡负责，取决于具体布局。
TP8
使用八个参与者的张量并行组。每一份权重和缓存如何分布，还要结合被切分的轴判断。
TPOT
Time Per Output Token，常用于表示首个输出之后平均每个词元的耗时。应注明是否排除首词以及使用了多少个生成间隔。
Transformer
用注意力混合不同位置的信息，再逐位置通过前馈网络。一个解码器通常把多层这样的计算依次连接起来。
TTFT
Time To First Token，从请求的约定起点到看到第一个输出词元的时长。比较数据时应写明起点在客户端还是服务端。
传输句柄
代表一次或一批已提交传输的对象，可用来查询完成状态。消费目标页前，先查询对应传输的完成状态。
共置
训练与生成在同一组设备上分时或按资源划分运行，切换时可能需要搬移参数及重建状态。
关键路径
在已有依赖下决定结束时间的最长路径。若其他并发分支已在关键路径之前结束，单独缩短这些分支不会使任务提前完成。
内存注册
把一个内存区间及其访问权限登记到 RDMA 设备，使网卡能够校验并执行对该区间的 DMA 操作。
准入
调度器确认有可用资源并允许请求开始执行。准入前的等待属于排队时间。
分块
把大矩阵按行列范围切成可由线程块协作处理的小矩阵，乘法沿归约维度逐块累加。
分片
把同一逻辑张量的不同元素交给不同 rank 持有。分片可降低本地常驻量，执行时仍可能临时收集完整参数。
前缀命中
复用已经计算好的前缀 K/V。新增查询仍要读取掩码允许的前缀位置。
发布
让缓存条目进入其他使用者可以查询和读取的状态，须先确认内容完整、可见。
在途
数据已开始传输，但相关读取、写入或完成通知尚未全部结束。缓冲区即使暂时没有计算在用，也不能随意覆盖。
地址空间
PTX 用来区分全局内存、共享内存等存储区域的寻址范围。相同位模式放到不同空间中未必指向同一个对象。
复用
输入元素被加载到片上后，多次参加不同输出元素的乘加。估算节省量时应说明是哪一级存储少读了数据。
复用长度
可以复用已有计算结果的连续前缀长度。估算本轮开销时，应分别记录序列已推进的位置数和本轮还需计算的查询行数。
外部命中
本地连续前缀以外、能从其他缓存来源恢复的部分，真正可用还取决于数据是否到达。
头分片
按 KV 头编号分到各 rank 的局部切片。两端并行度不同时，须按头编号重新组合。
完成事件
通信流记录的完成标记。其他 CUDA 流须建立对该事件的依赖后才能使用相应结果。
布局
张量的逻辑坐标与物理存储地址之间的对应关系。相同形状的张量可能因步长不同而产生不同访存模式。
张量
按若干个轴排列的一组数。形状给出每个轴的长度，步长给出沿该轴移动一格时存储地址的变化。
拓扑
设备以及设备间连接关系的图。同机 GPU 之间所经过的链路和交换层级可能不同。
排空
等待或确认已经提交的设备访问全部结束，使原缓冲能安全复用。
故障恢复
从可信的一致状态重建执行，训练恢复点和已向客户端承诺的服务输出需分别核对。
时间线
将不同线程、CUDA 流及设备活动按时间展开，可结合事件与请求编号追踪先后依赖。
有效吞吐
单位时间向请求提交的有效输出 token 数，草稿生成和作废位置不计入分子。
有效载荷
接收端实际要恢复的 K/V 字节，包头、填充及重复发送可另外增加链路流量。
校准
预测概率与同类样本中的实际通过频率是否相符，判断时须控制位置及样本是否曾被验证。
槽位
流水线中一块反复使用的缓冲区。同一地址先后保存多代数据，生产者要等上一个消费者用完才能覆盖。
步长
某个坐标轴上的下标增加 1 时，物理地址要前进的元素数。换算成字节还须乘元素大小。
注册代次
区分同一实例前后两次注册的编号，旧地址和访问凭据只能用于它们所属的代次。
消费者
读取共享槽位数据并据此计算的一方。可以开始读，与生产者可以覆盖同一槽，通常由不同完成事件决定。
状态快照
保存某个已知 token 边界的完整递归状态。拒绝草稿后可从该边界恢复，再重放仍须保留的位置。
组合
把一个布局给出的坐标交给下一个布局继续映射。判断最终元素归属时，要按照两个映射实际作用的顺序计算。
缓存感知路由
结合前缀命中与当前负载选择工作进程。多命中的候选也可能因排队更慢。
计时边界
明确一个耗时由哪两个事件的时间戳相减得到，跨主机相减前还须核对时钟关系。
读锁
持有期间保护缓存对象，防止它在读取方用完之前被驱逐或覆盖。
载荷
应用需要传送的数据。协议头、编码开销和重传都会占用链路，有效载荷只统计应用数据本身。
逻辑坐标
由张量的轴和下标标记的位置。坐标本身不能唯一决定物理地址，还须结合布局与起始指针。
重叠
两项任务的执行区间在时间上有交集。它们若争用计算、访存或链路资源，即使时间线重叠也未必缩短整步。
重放
再次执行已经实例化的 CUDA Graph。它重复提交图内记录的操作与依赖，输入数值可以更新，但须遵守地址和接口约束。
量化
用有限个离散码近似表示原数值。尺度、零点和分组方式决定恢复后的数值及误差。
页
缓存分配器一次分配或回收的固定大小存储块。请求用页表把逻辑 token 的区间映射到这些块。
页滞留
请求在逻辑上已经退出，但在途读写或其他持有者使物理页暂时不能回收。
页表
把逻辑位置所在的页映射到实际存储块的结构。在 KV 分页中，连续的逻辑位置未必位于连续的物理页。
预取
在后续层开始计算前就发起参数传输。预取越早，计算等待参数的时间可能越短，但完整参数与当前层数据同时占用显存的时间也可能越长。
